# agent_life9_decomp_alpha

Тринадцатый пакет поверх ASSEMBLE, первый БЕЗ evolve/HGT/Evolution
вообще. LIFE-8 закрыла "добить B3 на S0 (6 моделей, 4 фиксированных
шага)" — `B3_STACK`. LIFE-9 спрашивает другое: оживает ли что-то из
UNION-мёртвых (`U_dead`) при другой цепочке/разрезе задачи (α>0)? Если
да — фиксирует минимальный D-продукт и его `r`; если нет — закрывает S0
формально. Phase A (residual anatomy) → Phase B (α̂ по уже существующей
`whole_grid.json`) → Phase C (живой decomposition-пайплайн, только если
не C-skip) → Phase D (продолжение в том же `run_all.py`) → отчёт.

```
python scripts/verify_seams.py   # md5 + UNION ±1 + reparse/regex/planner-JSON фикстуры
python scripts/run_all.py        # A -> B -> [C-skip | smoke -> C] -> D -> REPORT_LIFE9.md
```

Итог — `reports/REPORT_LIFE9.md`: **α̂_B2 = 0.721 (STRONG)** уже на
Phase B (CPU, без единого нового вызова — из уже существующей
`whole_grid.json`, с раскрытой локальной поправкой парсинга, см.
BLOCKERS.md). Phase C (100 живых задач, 355 вызовов, 0 инфраструктурных
сбоев) дала неожиданный контраст: **decomp-пайплайн (planner изобретает
разбивку + executor'ы) почти не сработал** (`r_D_test=0.010`,
`α̂_decomp=0.000`) — но **тот же planner-модель, спрошенная ЦЕЛИКОМ, без
декомпозиции, решает 70/100** — устойчиво выше B3 (0.510), UNION (0.570)
и организма LIFE-8 (0.456). Механическая корзина **`D_ONLY_ALPHA`**
(вычислена буквально по имени `r_D_test`, как предрегистрировано) — но
реально выбранный D1-кандидат-продукт (whole B2, не decomp) устойчиво
бьёт B3 (`paired_delta_r` CI95=[0.05,0.33], p=0.014) — раскрыто как
интерпретация рядом с вердиктом в REPORT_LIFE9.md §4.1/BLOCKERS.md, не
вместо него. Практический вывод: не декомпозиция даёт α, а сам факт
недекомпозированного запроса достаточно сильной моделью.
