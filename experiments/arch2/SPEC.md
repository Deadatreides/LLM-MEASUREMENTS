## 0. Зачем слой существует

Молекулы (6 моделей, промпт-варианты, температуры, 3 механических шва, K0/K1/K2
context-builder'ы, R0/R1/R2 представления, классификаторы коллизий и новизны) измерены
13 экспериментами **по одной**. Итог отрицательный: ни одно одиночное действие после
коллизии не бьёт слепой повтор по tokens-per-resolved (эксп. 11 §13, эксп. 12 §5),
структурный контекст не окупается (ΔK2 = +0.6 п.п., p = 0.845), смена модели без
контекста значимо вредит (−8.8 п.п., p = 0.0042). Единственный устойчивый плюс —
переформулировка промпта на syntax-коллизиях (93.0% против 73.9%, n = 115, p = 5.9e-5).

Все 13 экспериментов сравнивали **одно действие, применённое ко всем состояниям
одинаково**. Ни один не измерял **распределение фиксированного бюджета между
молекулами**. Пересчёт по уже лежащему сырью (`experiment12/runs12/phase0_full_exp12-v1.json`,
1320 записей = 6 моделей × 55 задач × 4 seed) при **строго равном токенном бюджете**
(660.9 токенов на ячейку, 4 вызова):

| размещение 4 вызовов | oracle@4 | N_eff | ток/resolved |
|---|---|---|---|
| 1 модель × 4 seed (то, что мерили все эксперименты) | 0.5758 | 1.60 | 1147.9 |
| 2 модели × 2 seed | 0.6204 | 1.81 | 1065.3 |
| 4 разные модели × 1 seed | 0.6745 | 2.10 | 979.8 |
| лучшая четвёрка моделей | **0.7455** | — | 911.3 |
| худшая четвёрка | 0.5455 | — | — |
| лучшая одиночная модель (hindsight) | 0.6910 | — | 1070.6 |

Парный bootstrap по задачам: **+9.88 п.п., CI [+5.79, +14.18], 19 задач лучше / 0 хуже /
36 ничьих** (n = 55). Разброс между четвёрками — **20 пунктов** при одном и том же
бюджете и одном и том же наборе молекул.

Отсюда цель слоя: **сделать сочетание молекул первоклассным объектом** — сериализуемым,
запускаемым, оцениваемым и **смертным**. Проверяемые источники ценности, недоступные
отдельной молекуле: (а) гетерогенное размещение бюджета, (б) остановка на глубоких
барьерах, (в) маршрутизация по механически наблюдаемому типу коллизии.

# ЧАСТЬ I. МАТЕМАТИКА

## 1. Комплекс как объект

### 1.1 Генотип

Генотип — **данные**, не императивный код. Дерево над ссылками на молекулы.

```
G ::= (complex_id, spec_version, gen, parent_ids, origin, root)

Node ::= CALL(molecule, params)         -- вызов генеративной молекулы
       | CHECK(seam)                    -- механический шов
       | SEQ[N₁..N_k]                   -- последовательно, состояние течёт вперёд
       | PAR[N₁..N_k]                   -- независимые ветви от ОДНОГО входного состояния
       | SWITCH(obs, {v → N}, default)  -- диспетчер по наблюдаемой величине
       | BUDGET(limit_tokens, N)        -- жёсткий потолок
       | STOP(reason)                   -- терминал
       | ASSEMBLE[N₁..N_k]              -- пятый цикл, §30-34: слот i = шаг i задачи
```

`params` — точка **конечной объявленной сетки** (§ `registry.py`): temperature ∈
{0.0, 0.5, 1.0}, seed_slot ∈ {0..3}, max_tokens ∈ {150, 320, 400, 500}, prompt ∈
{K0, K1, K2, promptB, R1, R2}. Пространство генотипов счётно и перечислимо.

**Почему ровно 7 комбинаторов.** Каждый выводится из измеренного:

| комбинатор | обоснование |
|---|---|
| CALL | базовая единица; молекула не знает о комплексах |
| CHECK | I-9 / I-15: суждение только от доверенного механического шва |
| SEQ | retry-цепочка — то, что мерили эксперименты 10–13 |
| PAR | best-of-N — единственный baseline, который никто не побил (F46, эксп. 11 §13). Комплекс обязан **уметь выразить эталон**, иначе отбор подтасован. И именно PAR несёт измеренный +9.9 п.п. |
| SWITCH | все воспроизводимые эффекты типозависимы (F24, эксп. 11 §14, эксп. 12 §7, F20) |
| BUDGET | I-11: у каждого действия есть стоимость; без потолка смерть не наступает механически |
| STOP | I-21 + F20/F21: самое сильно подтверждённое действие всей программы (5–15× экономии) |

Таблица выше — точный исторический протокол Частей I–IV: язык был из семи узлов,
и §10/§20/§29 explicitly называли восьмой узел вне области. **Пятый цикл (§30-34)
пересмотрел это** по измеренному основанию (эксп. 14, G1 = +0.3800 п.п.,
CI [+0.27,+0.49]): язык из семи узлов не мог выразить «шаг i от модели X, шаг j
от модели Y» — маршрут подбирался перечислением, не отбором. Восьмой комбинатор,
ASSEMBLE, добавлен там же, с тем же требованием (обоснование от измеренного), не
здесь — таблица выше НЕ переписана, чтобы остаться честным протоколом того, что
было верно до пятого цикла.

**Чего в языке НЕТ и почему:** нет `budget-split` (это `PAR[BUDGET(b₁,·), BUDGET(b₂,·)]`);
нет `early-stop` (это семантика PAR + `SWITCH → STOP`); нет циклов и рекурсии (иначе
верхняя оценка стоимости не вычислима статически и гарантия BUDGET рушится); нет узла
«спросить модель, что делать» (I-9); нет узла записи в общее состояние (I-17).

### 1.2 Пространство состояний исполнения

σ = (a, e, h, c, τ):

| поле | смысл |
|---|---|
| `a` | текущий артефакт — **сырой** вывод модели до парсинга (I-16) |
| `e` | evidence: список `SeamResult` (status ∈ {PASS, FAIL, INAPPLICABLE, ERROR, UNKNOWN}, details, **trusted**) |
| `h` | история: список (node_path, molecule, status, tokens) — только прошлое |
| `c` | потрачено токенов |
| `τ` | задача (id, family, шов-оракул). Read-only. |

Семантика (детерминированная; стохастика только внутри CALL):

```
⟦CALL(m,p)⟧σ   = σ[a ← m(σ.a, σ.e, p), c += tokens, h += …]
⟦CHECK(s)⟧σ    = σ[e += s(σ.a, τ), h += …]                     -- 0 токенов
⟦SEQ[N…]⟧σ     = foldl ⟦Nᵢ⟧ σ
⟦PAR[N…]⟧σ     = первая по порядку ветвь Nᵢ, дающая PASS от ДОВЕРЕННОГО шва;
                 исполняется лениво — остальные ветви не запускаются;
                 если PASS нет — σ с объединённым e и суммой c по всем ветвям;
                 каждая ветвь стартует от КОПИИ входного σ (нет потока информации между ветвями)
⟦SWITCH⟧σ      = ⟦cases[obs(σ)] или default⟧σ                  -- 0 токенов
⟦BUDGET(n,N)⟧σ = ⟦N⟧σ, но CALL отклоняется, если c + est(CALL) > c_вход + n;
                 при отклонении узел возвращает σ с пометкой EXHAUSTED
⟦STOP(r)⟧σ     = σ, помеченное терминальным; r записан в трассу
⟦ASSEMBLE[N…]⟧σ = слот i исполняется от КОПИИ σ с τ, заужённым на шаг i (§31);
                 RESOLVED ⟺ подтверждены ВСЕ слоты; STOP в слоте — как в PAR
```

Два решения по семантике, зафиксированные при реализации:

- **STOP завершает весь прогон**, а не только свою ветвь PAR. Иначе «мы решили не
  тратить дальше» в одной ветви противоречило бы продолжению соседних. Валидатор
  дополнительно запрещает узлы после STOP внутри SEQ (недостижимый код).
- **σ несёт непрозрачный карман `meta`**, который Runner только ПЕРЕНОСИТ и никогда не
  читает. Он нужен backend'у (offline-режиму — чтобы помнить, из какой сохранённой
  записи получен артефакт). Гарантия «Runner не пишет ничего, кроме трассы» не
  нарушена: пишет backend.

**Наблюдаемые `Obs` — закрытый список.** Все механические, все считаются только из σ:

| obs | значения | источник |
|---|---|---|
| `last_status` | PASS / FAIL / INAPPLICABLE / ERROR / NONE | σ.e |
| `collision_subtype` | syntax / contract_interface / dependency / semantic / value / other | `experiment12/seams.py::collision_subtype` |
| `same_failure` | SAME / DIFFERENT / NA | `experiment12/outcome_classification.py::classify_outcome` |
| `attempts_used` | 0 / 1 / 2 / 3+ | σ.h |
| `tokens_bucket` | 0 / low / mid / high | σ.c |
| `task_family` | arithmetic / code | τ |
| `dominant_share_bucket` | low / high / NA (при ≥2 попытках) | σ.h, признак эксп. 6 §2 |
| `n_unique_signatures` | 1 / 2 / 3+ / NA | σ.h |

**Запрет утечки (I-обязательство слоя).** `Obs` не содержит ничего, чего нет в σ.
Оракульная информация попадает в σ **только** через `CHECK` доверенного шва — тем самым
каналом, который в этом стенде и есть проверка. **Ограничение фиксируется явно:** в
домене без механического оракула (OQ-4) `PASS` как условие выхода PAR недоступен, и
слой туда **не переносится без переизмерения**.

### 1.3 Стоимость и исход

```
C(G, τ, ω) = Σ (input_tokens + output_tokens) по ФАКТИЧЕСКИ исполненным CALL
O(G, τ, ω) ∈ {RESOLVED, UNRESOLVED, INAPPLICABLE, EXHAUSTED, ERROR}
```

`ω` — seed-вектор. `RESOLVED` ⟺ CHECK **доверенного** шва на финальном артефакте дал
`PASS`. Токены — фактические (`usage` из llama.cpp), как во всех экспериментах проекта.
Latency пишется в трассу, но в фитнес не входит (эксп. 11 §10, эксп. 12 §6 — не узкое
место на этом железе).

## 2. Фитнес

**Скалярного фитнеса нет.** I-19 плюс прямое измерение старого Мицелия: скалярная
агрегация была **анти**коррелирована с истиной (ρ = −0.429) против +0.771 у разделённой
по ролям. Фитнес — вектор, отбор — Парето.

Пусть T — оценочный пул, |T| = n.

**Эталонов четыре, а не один.** Сравнивать всё только с самым дешёвым было бы
подтасовкой: комплекс из четырёх вызовов почти всегда обгонит по решаемости комплекс из
одного, ничего не открыв. Все четыре прогоняются каждое поколение, ни один не умирает,
ни один не участвует в отборе и не занимает мест в элите:

| эталон | что это | роль |
|---|---|---|
| **B0** | один слепой повтор без контекста | линейка стоимости: ΔR и E считаются к ней |
| **B1** | 4 слепых повтора одной моделью | равный бюджет, гомогенное размещение |
| **B2** | 4 повтора **сильнейшей одиночной моделью**, выбранной задним числом | снимает конфаунд «угадали сильную модель» |
| **B3** | 4 повтора **лучшей моделью под каждое семейство задач**, тоже задним числом | снимает конфаунд «угадали сильную модель ДЛЯ ЭТОГО ТИПА задач» |

**Планка выбирается по факту, а не назначается.** Каждое поколение ею становится
эталон с максимальным `r` на текущем срезе. Причина конкретна: B3, будучи
привилегированнее B2 по конструкции, на пуле состояний коллизии оказался СЛАБЕЕ него
(r = 0.600 против 0.633) — выбор «лучшей модели под семейство» делался на полном пуле
задач и на эту подпопуляцию не перенёсся. Фиксированная планка в такой ситуации молча
занижает требование.

Проверка вымирания (§3.3) идёт против этой планки, а не против B0.

**Отдельно от отбора** конфаунд «сильная модель» снимается конструкцией с равным
средним p1: гетерогенное размещение (по одному вызову каждой моделью из S) против
гомогенного (4 вызова одной моделью, усреднённые по m ∈ S). У обоих ожидаемая
вероятность успеха одной попытки одинакова **по построению**, поэтому разница не может
объясняться силой моделей. Измерено: надбавка +0.0988, CI [+0.0591, +0.1415], на
**15 наборах из 15**; доза-эффект (2 модели +0.0446 → 4 модели +0.0988).

Короткий горизонт:
```
r(G) = (1/n) Σ_t 1[O(G,t) = RESOLVED]                    -- resolve rate
c(G) = Σ_t C(G,t) / Σ_t 1[O(G,t) = RESOLVED]             -- tokens per resolved (∞, если 0)
```
Оба — с парным bootstrap 95% CI по задачам (10 000 ресэмплов; метод уже реализован в
`experiment13/harness.py::bootstrap_rate_diff`).

Производные (гейты, не отдельные оси):
```
ΔR(G) = r(G) − r(B₀)      парно по задачам
E(G)  = c(B₀) / c(G)      efficiency gain
```

Длинный горизонт:
```
U(G) = { t ∈ T : O(G,t) = RESOLVED ∧ ∀ G' ∈ peers: O(G',t) ≠ RESOLVED }
u(G) = |U(G)| / n
```
`peers` = элита, а пока элиты нет (поколение 0) — остальная живая популяция: иначе в
первом поколении защита прекурсора не работала бы вовсе. Сравнение всегда идёт по
**пересечению** оценённых задач: уникальность, полученная за задачу, которую конкурент
просто не видел, — это дефект измерения, а не новизна.

**f(G) = (r, −c, u)**; отбор по Парето-фронту в этих трёх координатах. Ни одна ось не
сворачивается в другую и не взвешивается. Никаких субъективных метрик, никакого
LLM-судьи, никакой оценки «качества текста».

**Почему u, а не структурная новизна.** Эксперимент 13 (пилот, 14 состояний × 3 режима)
даёт механическое мерило структурной новизны (`representation.py::classify_novelty`), и
оно срабатывает часто (NOVEL_STRUCTURE в 7/14 у R1 и R2), но **не конвертируется**:
pass 0.214 у R1/R2 против 0.286 у R0 при 2.0–2.7× токенах. Структурная новизна
**пишется в трассу как наблюдение и в фитнес не входит**. Новизна засчитывается только
по исходу.

## 3. Смерть

### 3.1 Счёт жизни

Экономическое довольствие поколения: `L_econ(G) = B_gen · w(G)`, где `w` — доля по слою
Парето (равномерно внутри слоя, геометрически убывая по слоям). Субсидия `S(G)` —
только для комплексов, попавших в элиту по оси `u` (трек новизны).

### 3.2 Три способа умереть

**D1 — скрининговая смерть (дешёвая, ранняя).** После оценки на скрининговом пуле T_s
комплекс умирает, если **оба** условия:
```
upper95(ΔR(G)) < 0        доверительно не лучше эталона
u(G) = 0                  и не решил ничего, чего не решает элита
```
Второе условие — **защита прекурсора**: комплекс хотя бы с одним уникальным решением не
может умереть по экономике на этом шаге, каким бы дорогим он ни был.

**D2 — смерть от исчерпания субсидии.** `L_econ(G)` — доля бюджета поколения по слою
Парето. Комплекс **на фронте свою трату заработал** — с него не списывается ничего.
Остальные платят перерасход `max(0, spend − L_econ)` из субсидии, а субсидия выдаётся
**только линии новизны** (у комплекса был или есть `u > 0`) и убывает геометрически:
`S₀` в поколении рождения, `λ·S₀` в следующем. Полный расход по линии ограничен
`Σ ≤ S₀/(1−λ)` — **конечная сумма аналитически**. Комплекс без новизны, вне фронта и с
перерасходом умирает сразу.

Три защиты прекурсора внутри D2: (а) новорождённый живёт минимум одно полное поколение;
(б) на Парето-фронте не умирает никто, а `u` там ось — значит комплекс с уникальными
решениями недоминируем по построению; (в) линия новизны обязана конвертироваться в
экономику за `G_MAX` поколений, иначе смерть (это и есть граница субсидирования).

**D3 — смерть от неподтверждения (запрет бессмертия).** Членство в элите
**переподтверждается каждое поколение на свежем срезе контрольного пула T_c** (ротация
без возврата). Если `upper95(ΔR)` на свежем срезе падает ниже 0 — комплекс выбывает из
элиты и теряет `L_econ`, оставаясь живым один цикл на субсидии.

D3 — прямая кодификация собственной истории проекта: эффект «CHANGE_MODEL в 2.7 раза
дешевле» (эксп. 10) не воспроизвёлся на независимом стенде (эксп. 11, p = 0.72).
**Ни один комплекс не бессмертен: элита переизбирается на данных, которых не видела.**

### 3.3 Вымирание популяции

Популяция объявляется вымершей (эксперимент дал отрицательный ответ), если за `G_stall`
поколений подряд **ни один** комплекс не имеет `lower95(ΔR) > 0` **или** `lower95(E) > 1`
на контрольном пуле.

Это **предрегистрированный допустимый исход**, а не отказ харнесса. С учётом того, что
вся программа экспериментов 10–13 дала отрицательные ответы, такой исход вероятен, и
архитектура обязана уметь его произнести.

### 3.4 Архив

Генотипы мёртвых комплексов **не удаляются** (append-only, как Storage в arch1). Они
доступны как доноры поддеревьев для горизонтального переноса (§9.2). Воскрешение целиком
возможно, но **без субсидии**: воскрешённый начинает с `S = 0`.

## 4. Барьер ΔV и расстояние до бифуркации

### 4.1 Что вообще идентифицируемо

Для конфигурации θ = (модель, промпт, T, состояние):
```
q(θ) = P(следующая попытка PASS | текущая FAIL)
```
По Крамерсу скорость выхода `k ∝ exp(−ΔV/D)`; при малом q имеем `q ≈ k·Δt`, откуда
```
B(θ) := ΔV/D = −ln q(θ)
```
**Идентифицируема только безразмерная величина B = ΔV/D.** Интенсивность шума D
(температура сэмплирования и всё, что с ней смешано) отдельно не наблюдаема; любое
утверждение о ΔV самом по себе требует допущения о D, которого данные не дают. Далее
«барьер» = B, в натах.

### 4.2 Оценка по наблюдаемым

```
q̂(θ) = #{попытка PASS, следующая за FAIL} / #{FAIL, за которыми была попытка}
B̂ = −ln q̂,  bootstrap CI по состояниям
```

Измерено на `phase0_full_exp12-v1` (330 полных ячеек, все 24 перестановки seed;
воспроизводится `barriers.py --phase e4`):

| условие | q̂ | B̂ (нат) | ток/попытку | предельная цена, ток/resolved |
|---|---|---|---|---|
| 1-я попытка (безусловно) | 0.4144 | 0.881 | 165.2 | 398.7 |
| 2-я после 1 провала | 0.1496 | 1.900 | 188.6 | 1260.6 |
| 3-я после 2 провалов | 0.0903 | 2.405 | 196.3 | 2175.2 |
| 4-я после 3 провалов | 0.0635 | 2.756 | 199.8 | 3144.5 |

Цена считается на **условной** популяции (только те ячейки, что реально дошли до
k-й попытки) — их ответы систематически длиннее (165 → 200 токенов), и усреднение
по всем ячейкам занижало бы предельную цену.

**Барьер растёт с каждым провалом**: обусловливание на провал отбирает высокобарьерную
подпопуляцию. Это количественная форма F1 (P(persist) ≈ 0.748) и прямая причина
существования BUDGET и STOP.

По типам коллизий (слепой повтор, тот же датасет): syntax B̂ = 0.52 · semantic 1.18 ·
dependency 2.06 · value 2.30 · other 2.54. Спред предельной цены — **13×**
(190.0 против 2454.5 ток/resolved).

### 4.3 Расстояние до бифуркации — и что данные ЗАПРЕЩАЮТ

Для управляющего параметра u (T, семейство модели) и порядкового параметра
`m(θ) = dominant_cluster_share`:
```
χ_u(θ) = |m(θ) − m(θ+δu)| / |δu|          восприимчивость (для дискретного свопа — |Δm|)
Γ(θ→θ') = B(θ) − B(θ') = ln(q(θ')/q(θ))   выигрыш барьера от смены конфигурации
```
Наблюдённая бифуркация (эксп. 5): llama/CODE_04 при T = 0 — Pass@1 = 0, Oracle@16 = 0,
dominant 93.75%, H_sem = 0.337 (systematic trap); при T = 0.5/1.0 — Pass@1 = 0.31,
Oracle@16 = 1.0, H_sem = 1.8–2.0. Ловушка исчезает при смене управляющего параметра.

**Жёсткое ограничение.** F18/F19 измерены прямо: H_sem сильно предсказывает *суммарный*
разрыв (r = 0.89 с G_8) и **не предсказывает предельный прирост следующего вычисления**
(r = 0.002 с ΔG(8→16)); при близкой энтропии нужны разные действия.

> **Архитектура не имеет права предсказывать χ или Γ по одной конфигурации.**
> Разрешено ровно два способа: (а) **измерить одним зондом** — исполнить альтернативу и
> посчитать Γ по факту; (б) использовать **асимметричный надёжный сигнал** «конфликта
> нет ⇒ не тратить» (F15: P(correct|no_conflict) ≈ 0.995; F20: dominant ≥ 0.75 и
> доминант CORRECT ⇒ STOP, 28/36).

В языке генотипа это реализовано буквально: нет узла «оцени перспективность», есть
`SWITCH` по уже наблюдённому и `PAR`, который платит за зонд.

### 4.4 Критерий ценности слабого сигнала

Слабый сигнал (evidence в промпте, structured context K1/K2, переформулировка) снижает
барьер на ε (`q → q·e^ε`) ценой удлинения промпта (`c → c·e^δ`, `δ = ln(c₁/c₀)`).
Положительная ожидаемая ценность ⟺ падает цена решения:
```
c₁/q₁ < c₀/q₀   ⟺   ε > δ   ⟺   Γ = ln(q₁/q₀) > ln(c₁/c₀)
```

Это **тождество, а не открытие**; ценность его в том, что оно задаёт шкалу: сколько
барьера обязан снять контекст, чтобы окупить свои токены. Проверка по всем 7 плечам
эксп. 12 v2 (`phase1_full_exp12-v2.json`, 2226 записей):

| плечо | q | ток/попытку | ε = ln(q/q₀) | δ = ln(c/c₀) | ε−δ | окупается |
|---|---|---|---|---|---|---|
| K0O0 (эталон) | 0.3208 | 240.8 | — | — | — | — |
| **K0O0_promptB** | 0.3931 | 266.2 | +0.2033 | +0.1003 | **+0.1031** | **да** |
| K1O0 | 0.3553 | 317.8 | +0.1024 | +0.2774 | −0.1749 | нет |
| K2O0 | 0.3616 | 319.0 | +0.1200 | +0.2814 | −0.1614 | нет |
| K1O1 | 0.3302 | 321.5 | +0.0290 | +0.2891 | −0.2602 | нет |
| K2O1 | 0.3365 | 323.8 | +0.0479 | +0.2962 | −0.2483 | нет |
| K0O1 | 0.2327 | 239.5 | −0.3209 | −0.0053 | −0.3156 | нет |

Те же расчёты по эксперименту 11 (контроль `REGENERATE_SAME`: q = 0.1942, c = 150.0,
B = 1.639 нат): `CHANGE_PROMPT` ε = +0.0720 против δ = +0.1078 (net −0.036),
`CHANGE_MODEL` ε = −0.0616 (net −0.055), `CHANGE_TEMPERATURE` ε = −0.0616 (net −0.065) —
ни одно плечо не окупается, что дословно совпадает с вердиктом §12/§18 отчёта эксп. 11.
`SEEK_EVIDENCE` и `STOP` ничего не генерируют, критерий к ним **неприменим** (а не
«не окупается»).

Итого критерий проверен на 9 генерирующих плечах двух независимых кампаний и во всех
девяти воспроизводит знак измеренного вердикта. Числа публикуются с 4 знаками, и
самопроверка `barriers.py` сверяется именно с этой точностью: первая версия файла
содержала выдуманные 6-значные «ожидания», и самопроверка это поймала.

Инженерное правило,
которое из него следует: **structured context удлиняет промпт на 32% и обязан поднять
решаемость более чем на 32% относительных; измеренный подъём — 11%.** Поэтому K1/K2 в
алфавите доступны, но приоритета не получают: это покажет отбор, а не запрет.

Связь с бифуркацией: большой Γ при малом изменении параметра = большая χ = близость к
бифуркационной поверхности. Далеко от неё (value/other: q ≈ 0.08, B ≈ 2.5, Γ от любого
известного действия ≤ 0.4) слабый сигнал бесполезен **арифметически**, а не идеологически.

## 5. Критерий «открыт новый режим» (novelty)

Комплекс G открыл новый режим относительно элиты E на пуле T ⟺ выполнены **все три**:

1. **Уникальность.** `|U(G)| ≥ u_min`.
2. **Воспроизводимость.** При перепрогоне со свежим seed-вектором ω' сохраняется ≥ 50%
   множества U(G).
3. **Не объяснимо бюджетом.** Лучшему члену элиты выдаётся **тот же суммарный бюджет**,
   что потратил G (дополнительными ветвями PAR), и он всё равно не решает U(G):
```
∀ t ∈ U(G):  P(RESOLVED | G, t) − max_{G'∈E} P(RESOLVED | G'@C(G), t) > 0,
             нижняя граница bootstrap CI > 0
```

Пункт 3 — математическое различение «новый режим» и «просто лучше ROI / больше
вычислений». Он прямо следует из F46: артефактный pipeline «выигрывал» только при счёте
по вызовам, а не по токенам. Без бюджетного матчинга novelty была бы такой же иллюзией.

**Дешёвый скрининговый признак (не критерий):** доля U(G), приходящаяся на состояния с
высоким B̂ (верхний квартиль барьера по элите) — комплекс выходит из ловушек, а не
подбирает лёгкое.

# ЧАСТЬ II. АРХИТЕКТУРА

## 7. Слои и направление зависимостей

```
уровень 2   SELECTION / EVOLUTION   популяция, фитнес, мутации, смерть, архив, регистрация
уровень 1   COMPLEX                 генотип, валидатор, Runner, трасса
уровень 0   MOLECULAR               реестр молекул: генераторы, швы, наблюдаемые
```

Строго вниз, как в `arch1/CLAUDE.md`. Уровень 0 не знает про комплексы; уровень 1 не
знает про популяцию и фитнес; `fitness.py` не импортирует `runner.py` — читает трассы
с диска.

### 7.1 Molecular Layer (считается данным)

```python
Molecule = {
  "id": str,
  "kind": "generator" | "seam" | "observable",
  "iface_in": "state", "iface_out": "state" | "evidence" | "value",
  "params_grid": {...},        # конечная объявленная сетка
  "cost_profile": {...},       # ЭМПИРИЧЕСКОЕ распределение токенов, не оценка
  "impl": callable,            # (state, params, rng) -> (state', trace_fragment)
}
```

Наполнение — то, что уже есть; **переиспользуется, не переписывается**:

| kind | id | источник |
|---|---|---|
| generator | `gen.<model_id>` × 6 | `experiment11/configs/model_registry.py::generate` |
| generator | `gen.same_operator`, `gen.other_operator` | роли, а не модели — см. ниже |
| seam | `seam.multistep_arith`, `seam.enriched_code`, `seam.final_answer` | `experiment12/seams.py`, `experiment13/seams.py` |
| observable | `collision_subtype` | `experiment12/seams.py::collision_subtype` |
| observable | `same_failure` | `experiment12/outcome_classification.py::classify_outcome` |

**Промпт — это ПАРАМЕТР вызова, а не отдельная молекула** (`prompt ∈ {primary, K0, K1,
K2, promptB}`). Так генотип остаётся плоским, а выбор контекста виден прямо в узле CALL.

**Роли `same_operator` / `other_operator`** существуют потому, что эксп. 12 измерял
именно ось O0/O1: альтернативная модель выбиралась случайно на состояние и записана в
`config.model_id`. Роль честно отражает измеренную ось; запрос конкретной третьей
модели в offline-режиме недоступен.

**Гейт доверия (I-15).** Молекула-шов без пройденного `self_test` не может дать
`trusted = True`; её результат не может быть ни условием выхода PAR, ни входом `Obs`, ни
признаком RESOLVED. **Контрольные случаи обязательны и для извлечения входов шва**, а не
только для `check()` — прямое исполнение вывода этапа 8 arch1 (`SEAM_MODEL §5` — дыра в
самой спеке).

### 7.2 Complex Layer

Формат генотипа — JSON, версионированный, хешируемый:

```json
{
  "complex_id": "cx-000af3",
  "spec_version": 1,
  "gen": 3,
  "parent_ids": ["cx-0009b1"],
  "origin": "mutate:M1",
  "root": {
    "op": "SWITCH", "obs": "collision_subtype",
    "cases": {
      "syntax": {"op": "SEQ", "children": [
        {"op": "CALL", "molecule": "gen.qwen2.5-coder-1.5b-instruct-q4_0",
         "params": {"prompt": "promptB", "temperature": 0.5, "seed_slot": 1, "max_tokens": 320}},
        {"op": "CHECK", "seam": "seam.enriched_code"}]},
      "value": {"op": "STOP", "reason": "barrier_too_high"},
      "other": {"op": "STOP", "reason": "barrier_too_high"}
    },
    "default": {"op": "BUDGET", "limit_tokens": 700, "child": {"op": "PAR", "children": [...]}}
  }
}
```

`complex_id` = `cx-` + первые 6 hex sha256 канонизированного JSON **без** полей
происхождения (`gen`, `parent_ids`, `origin`, `complex_id`) ⇒ структурно одинаковые
комплексы имеют один id, дубликаты схлопываются бесплатно, до GPU.

**Валидатор** (статический, до любого исполнения):
1. типы: `CALL → state`, `CHECK → evidence`, `obs` из закрытого списка;
2. покрытие: у `SWITCH` обязателен `default`;
3. конечность: нет циклов (дерево), глубина ≤ `MAX_DEPTH`, узлов ≤ `MAX_NODES`;
4. верхняя оценка стоимости `Ĉ_max(G) = Σ max_tokens` по всем достижимым CALL;
5. доступность молекул и значений params в реестре и в сетке.

Невалидные мутанты отбрасываются **бесплатно** — главный фильтр, потому что дефицитный
ресурс здесь GPU.

**Runner:**
```python
def run(genotype, task, seed_vector, budget_tokens, registry, backend) -> RunResult
```
Гарантии (каждая покрыта контрольным случаем, иначе не считается выполненной):
1. `C(result) ≤ budget_tokens` — проверка **перед** каждым CALL и факт-проверка после;
   превышение невозможно, а не маловероятно. Оценку «до» даёт backend, если умеет
   (offline-replay знает записанные usage-токены ТОЧНО, и тогда BUDGET-рамки считаются
   по факту); иначе берётся консервативная верхняя граница из реестра. Инвариант в обоих
   случаях один: `оценка ≥ факт`;
2. трасса полна: на каждый исполненный узел — `node_path`, `molecule`, `params`,
   `raw_output` (до парсинга), `seam_result` (со `trusted`), `input_tokens`,
   `output_tokens`, `latency`, `timestamp`;
3. детерминизм по структуре: при одинаковых (генотип, задача, seed_vector) и одинаковых
   выходах молекул последовательность узлов та же;
4. Runner ничего не пишет, кроме трассы (аналог I-17);
5. `RESOLVED` не выставляется от недоверенного шва — структурно, а не по соглашению.

**Хранилище трасс** — append-only JSONL, `runs/<experiment_id>/<complex_id>.jsonl`,
атомарная запись (`.tmp` + `replace`), резюмируемость — та же схема, что в
`run_experiment12.py` / `run_experiment13.py`.

### 7.3 Selection / Evolution Layer

Цикл поколения:
```
1. evaluate(population, T_s)               -> трассы на диск
2. fitness = recompute_from_traces(T_s)    -- ОТДЕЛЬНАЯ ПРОГРАММА
3. D1: скрининговая смерть
4. evaluate(survivors, T_c_slice)          -- свежий срез контроля
5. Парето (r, −c, u) + fitness sharing + квота семейств -> elite
6. D3 переподтверждение элиты; D2 списание субсидий, смерть по исчерпании
7. воспроизводство: мутации + горизонтальный перенос + доля свежих
8. регистрация (§10), если кто-то прошёл гейт
9. проверка §3.3 (вымирание)
```

## 8. Как явно представлены три требуемые вещи

**Ранняя смерть линии** — два независимых уровня: внутри прогона `BUDGET → EXHAUSTED` и
`SWITCH → STOP(barrier_too_high)`; между поколениями — D1 на скрининговом пуле.

**Перераспределение бюджета** — `L_econ(G) = B_gen · w(G)` по слою Парето; внутри
прогона — `BUDGET` вокруг ветвей PAR (это и есть budget-split). Обосновано измеренной
кривой предельной отдачи (§4.2): 4-я слепая попытка стоит 3144.5 ток/resolved против
398.7 у первой (7.9×) ⇒ бюджет обязан быть перемещаемым между состояниями, а не
размазанным.

**Оценка ΔV / близости к бифуркации** — не предсказывается, а входит в `SWITCH` через
уже наблюдённое: `collision_subtype` — фактически бакет по B̂ (syntax 0.52 … other 2.54
нат), `attempts_used` — счётчик роста барьера (0.88 → 2.76 нат за 4 попытки). Комплекс,
«умеющий пользоваться барьером», — это комплекс с ветвью `STOP` на высоких бакетах.
Отдельного «модуля оценки ΔV» нет намеренно: F18/F19 запрещают предсказание, а
бакетирование по наблюдённому разрешено.

## 9. Мутации и горизонтальный перенос

### 9.1 Мутации (операции над данными, все проходят валидатор)

| M4 | расщепить ветвь SWITCH по наблюдаемой / слить две ветви | F24, эксп. 11 §14: эффекты типозависимы |
| M5 | горизонтальный перенос поддерева (§9.2) | — |
| M6 | компрессия поддерева в ссылку на зарегистрированную молекулу (§10) | автокатализ |

Вероятности операторов фиксируются до прогона и по ходу не подстраиваются.

### 9.2 Горизонтальный перенос

Донор — любой комплекс из **живых или архива**. Переносится поддерево, совместимое по
типу в точке вставки (`state → state`). Реципиент получает `parent_ids = [свой, донор]`.
Перенос из архива — единственный способ, которым мёртвая линия влияет на будущее, и он
не даёт мёртвому комплексу ни субсидии, ни места в популяции. Это и есть «РНК-подобный
прекурсор»: генотип сохраняется навсегда, но живёт только то, что платит.

## 10. Комплекс → молекула (автокатализ)

Регистрация ⟺ **все** условия:
1. оценён на ≥ `n_min` состояниях суммарно;
2. на **held-out** срезе лежит на Парето-фронте (r, −c) и `lower95(ΔR) > 0` **или**
   `lower95(E) > 1`;
3. интерфейс корректен (`state → state`), валидатор проходит;
4. трасса воспроизводима: независимый пересчёт фитнеса совпадает с прогонным.

**Как именно вызывается зарегистрированный комплекс — без восьмого узла в языке.**
Композит объявляется в реестре молекулой вида `generator` с `role="composite"` и пустой
сеткой параметров; в генотипе он вызывается обычным `CALL(molecule="cx.<id>", params={})`.
Runner, увидев роль `composite`, исполняет корень замороженного генотипа **в том же
контексте**: общий бюджет, общая трасса. Автокатализ **по-прежнему** не требует
отдельного узла (композит — молекула, вызывается обычным CALL) — это НЕ пересмотрено
пятым циклом. Восьмой узел (ASSEMBLE, §30-34) добавлен по ДРУГОЙ причине: не для
вызова композита, а для выражения многошаговой декомпозиции внутри одного генотипа.
Чёрных ящиков по-прежнему нет — внутренние CALL/CHECK композита видны в трассе как
обычно.

При регистрации генотип **замораживается** (id + хеш + `spec_version`), `cost_profile` =
измеренное эмпирическое распределение токенов (не оценка), `registered_from = complex_id`.
Мутация зарегистрированной молекулы невозможна: «разворачивание» (M6 в обратную
сторону) даёт новый комплекс-потомок с той же семантикой, который дальше мутируется как
обычный. Так уровень N+1 получает уровень N в качестве алфавита.

## 13. Зачем этот раздел

1. **Родство.** Хранится только `parent_ids` внутри генотипа; какой оператор сработал и

3. **Автокатализ не замкнут.** Регистрация композита существует (§10), но новые
   генотипы его не вставляли: `registry.generator_ids()` возвращает композиты, а
   `library.attempt()`/M1 строили для них `CALL` **с параметрами**, тогда как у
   композита `params_grid = {}` — валидатор такие мутанты отбрасывал молча.

Раздел добавляет ровно четыре механизма, закрывающие эти три пробела. Ни один из них не
меняет ни семь комбинаторов, ни планку отбора, ни D1/D2/D3.

## 14. Типизированные рёбра наследственности

Помимо `parent_ids` ведётся **append-only журнал рёбер** между `complex_id`:

| ребро | смысл | кто эмитит |
|---|---|---|
| `mutated_from` | точечная/структурная мутация | `reproduce` после любого M1–M4, M6 |
| `crossed_from` | горизонтальный перенос подграфа | `reproduce`, дополнительно к `mutated_from`, если сработал M5 |
| `reinforces` | похожий фенотип из **другой** линии | конец поколения, §15 |
| `echo` | тот же режим в другой эпохе **своей** линии | конец поколения, §15 |
| `compressed_into` | комплекс зарегистрирован как молекула | §17 |
| `instantiated_from` | новый комплекс содержит `CALL` на эту молекулу | рождение комплекса |

### 14.1 Инвариант NO_MERGE

> Два `complex_id` никогда не сливаются в один. Максимум, что связывает похожие
> комплексы, — ребро `reinforces`/`echo`. Схлопывание допускается **только** через
> явную регистрацию молекулы (§17), и оно ничего не удаляет: исходный комплекс остаётся
> в архиве и в рёбрах.

Структурно одинаковый потомок — это тот же `complex_id` по построению (канонический
хеш, §7.2), и он просто не добавляется повторно; это не слияние двух сущностей.
Архив монотонно не убывает; `merge_events` обязан быть 0 и выносится в отчёт.

Обоснование: это ровно тот «semantic coagulation», от которого защищается источник
идеи (`ptg/PTG+MCP1.3/ptg_core.py`, ПАТЧ 9), и одновременно защита прекурсора, уже
принятая в §6: линия с потенциалом не должна исчезать из-за похожести на соседа.

## 15. Placement-score — диагностика, а не приговор

```
place = W_SEM*sem + W_TEMP*temp + W_DENS*density + W_SKEL*skel
```

| ось | определение |
|---|---|
| `sem` | Жаккар масок решённых задач **на пересечении оценённых** обоими комплексами |
| `temp` | `0.5 ** (dgen / TEMP_HALF_LIFE_GENS)` |
| `density` | `1 − доля элиты, у которой sem к этому комплексу ≥ SEM_HIGH` |
| `skel` | `0.5*Жаккар(мультимножество op) + 0.3*(1 − ddepth/MAX_DEPTH) + 0.2*[совпало множество obs у SWITCH]` |

`sem` считается **только по пересечению** оценённых задач. Это прямой перенос урока E3:
там уникальность сначала считалась по объединению, и комплекс получал очки за задачи,
которых конкурент не видел.

**Решение принимается явными CASE-условиями, а не argmax скаляра:**

```
sem >= SEM_HIGH  и  одна линия   и  dgen >= ECHO_MIN_GEN  ->  echo
sem >= SEM_HIGH  и  разные линии                          ->  reinforces
иначе                                                     ->  независимая линия, ребра нет
```

Источник идеи предупреждает об этом дословно: «один скаляр — источник багов»
(`ptg_core.py`, ПАТЧ 10). Поэтому `place` целиком используется только там, где нужен
**ранжирующий** выбор, и никогда — как условие смерти:

* выбор донора для M5: `donor_score = 0.5*skel + 0.5*(1 − sem)` — структурно совместимый,
  но фенотипически **дополняющий** донор;
* выбор родителя для мутации: взвешивание по `w(t)` (§16);
* выбор кандидата на регистрацию при равенстве прочего: наименьшая избыточность
  относительно уже зарегистрированных.

## 16. Decay, uses, shadow

```
w(t) = W0 * exp(−dgen_idle / LAMBDA) * (1 + RHO * uses)
```

`uses` растёт, когда комплекс **или его потомок** (транзитивно по
`mutated_from`/`crossed_from`) попадает в элиту либо бьёт планку среза.
`dgen_idle` — поколений с последнего такого события (или с рождения).

* `w < W_FLOOR` → **shadow**: комплекс выходит из популяции (не оценивается, не
  размножается, не занимает места в `POP_SIZE`), но остаётся в архиве, в рёбрах и
  доступен как донор для M5;
* **revival**: shadow-комплекс, у которого `uses` вырос (успех потомка) и `w` вернулся
  выше `W_FLOOR`, возвращается в популяцию **с нулевой субсидией** — тем же правилом,
  что уже действует для воскрешения из архива (§3.4).

**Ортогональность смерти.** Decay **не убивает**. Смерть — по-прежнему только D1/D2/D3.
Shadow — это третье состояние между «жив» и «мёртв», и оно обратимо; смерть необратима
(генотип остаётся в архиве, но линия не воскресает с субсидией).

## 17. Замкнутый цикл: комплекс → молекула → снова в генотипах

Регистрации самой по себе недостаточно — без вставки в новые генотипы это библиотека, а
не автокатализ. Цикл считается замкнутым, когда работают все четыре звена:

**(1) Критерии регистрации** — все обязательны, проверяются в конце поколения после
отбора элиты:

1. `n_evaluated >= N_MIN_REGISTER`;
2. **не доминируется планкой** на контроле: НЕ (`gate.r >= c.r` И `gate.c <= c.c`), то
   есть комплекс лежит на Парето (r, −c) относительно планки;
3. генотип валиден (`genotype.validate` пуст) и замораживается; хеш = `complex_id`;
4. `cost_profile` **измерен** по трассам (медиана токенов, медиана числа вызовов), а не
   оценён.

Не более `MAX_REGISTER_PER_GEN` за поколение.

**(2) Регистрация** — запись в реестр с `role="composite"`, ребро `compressed_into`.

**(3) Вставка в новые генотипы** — три независимых пути: `M6` (компрессия поддерева в
ссылку), `M1` (замена молекулы на композит) и `random_genotype` (лист-композит с
вероятностью `P_COMPOSITE_LEAF`). Во всех трёх `params = {}`, потому что у композита
пустая сетка параметров.

**(4) Исполнение** — Runner, увидев `role="composite"`, исполняет замороженный корень
**в том же контексте**: общий бюджет, общая трасса, внутренние `CALL`/`CHECK` видны.
Мёртвая ссылка (узел есть, исполнения нет) — это провал, а не деталь.

# ЧАСТЬ IV. УСИЛЕНИЕ ОТБОРА

## 21. Зачем этот раздел

`REPORT_HEREDITY.md` §6 честно зафиксировал три слабых места: (1) «потомки с
композитом лучше» не воспроизводится между H0 и H0b — знак разницы плавает;
(2) фенотипически разные каркасы не защищены явно, только связаны рёбрами
`reinforces`, но состав элиты от этого не меняется; (3) D3 убивает по одному
провальному срезу контроля, что при трёх срезах по 60 задач может быть шумом
ротации, а не устойчивым провалом.

Три механизма (§23–25) закрывают эти пробелы точечно, поверх `evolve.select_elite`,
`evolve._d3_elite_dropouts`, `evolve._try_register_molecule`. Семь комбинаторов,
Runner, D1/D2, рёбра наследственности (§14) — не меняются.

## 22. Общий control на поколение — уже выполнено, здесь фиксируется явно

Проверка `evolve.run_generation` показала: `control_ids` — один срез на поколение
(`control_slices[gen % len(control_slices)]`), и элита, планка (`gate`) и все
`scored` считаются на нём одном; ротация — только МЕЖДУ поколениями. Это уже
удовлетворяет требованию «единый пул на поколение для всех комплексов и всех
эталонов». Изменение здесь — только протокольное: в отчёт поколения добавляются
`control_set_id` (`f"gen{g}_slice{g % n_slices}"`) и явное указание, какая ось
(r или E) у планки сработала для каждого претендента (уже вычисляется в
`win_details`, просто становится видимым полем).

## 23. Ниши по каркасу

`niche_key(g)` — стабильный хеш от `heredity.skeleton(g)` (уже существующей
подписи: мультимножество операторов, глубина, множество `obs` у SWITCH, `has_stop`,
ширины PAR). Без `cost_bin`: при `ELITE_SIZE=8` и наблюдённых 6–8 различных каркасах
в финальной элите (`REPORT_HEREDITY.md` §4) квартили `c` фрагментировали бы ниши до
одного представителя без всякого отбора внутри неё.

**Резервирование — не третья ось Pareto**, а процедура ПОСЛЕ стандартного отбора
(Парето-слои + квота семейств, уже реализованные в `select_elite`):

```
для каждой ниши N, представленной в живой популяции, но НЕ представленной в элите:
    best_N = участник ниши N с максимальным r на текущем control
    если best_N бьёт планку по r ИЛИ по E (переиспользуется предикат beats_gate
                                            из win_details, не пересчитывается)
        и в элите есть ниша с >= 2 представителями:
            заменить в элите худшего (по r) представителя ИЗБЫТОЧНОЙ ниши на best_N
```

Не меняет `ELITE_SIZE`. Не трогает Парето-фронт: свопу подлежат только избыточные
представители вне фронта (комплекс на фронте по определению не удаляется — тот же
инвариант, что уже защищает D2, §3.2).

## 24. Парсимония

**Tie-break внутри Парето-слоя.** Текущая сортировка `-shared_score` (плотность
покрытия задач, F.shared_scores) дополняется вторичным ключом

```
complexity_key(g) = (n_nodes, n_raw_calls, composite_nesting_depth)
```

где `n_raw_calls` — число `CALL` на НЕкомпозитную молекулу, `composite_nesting_depth`
— глубина цепочки композит-в-композите (0, если композитов нет). Вторичный ключ
применяется, только когда `shared_score` совпадает с точностью до 4 знаков —
иначе плотность покрытия по-прежнему первична. Это тождественно правилу задания
«prefer fewer nodes; prefer fewer raw-model CALL; prefer shallower composite
nesting», применённому в указанном порядке как компоненты одного кортежа.

**Запрет регистрации доминируемой более сложной обёртки.** Пятый пункт
`registration_gate` (дополняет четыре из §17, не заменяет их): кандидат
отклоняется, если существует уже зарегистрированная молекула M (по её `(r, c,
n_nodes)`, зафиксированным В МОМЕНТ РЕГИСТРАЦИИ) такая, что M доминирует
кандидата по (r, −c) **и** кандидат сложнее M по числу узлов. Дешёвая, но более
слабая молекула кандидатом НЕ отклоняется — это ровно дешёвый край Парето,
который §17 обязан пропускать (см. `test_accepts_cheaper_even_if_slightly_worse`).

## 25. Устойчивость на двух срезах

Задание допускает два варианта дословно и требует выбрать один. Выбран
**вариант (a)**: кандидат не входит в элиту заново после провала, а действующий
член элиты изгоняется только после **двух подряд** провальных срезов, а не
одного. Провал среза — `fail_gate(delta_r) := delta_r.ci_95[1] < 0`, тот же
предикат, что уже использует скрининг D1 (не новое понятие).

Механизм: `Account.gate_fail_streak` — инкремент при провале текущего среза,
сброс в 0 при успехе (`ci_95[1] >= 0`). D3 изгоняет из элиты при `streak >= 2`.
Вариант (b) («среднее по двум срезам бьёт среднюю планку») не реализуется —
он вводит дополнительную статистическую машинерию (агрегация по двум
независимым bootstrap) без ясного выигрыша в интерпретируемости.

Отдельно, информационно (не блокирует вход в элиту): для каждого НОВОГО члена
элиты в отчёте поколения фиксируется, оценивался ли он вообще на control
предыдущего поколения и, если да, бил ли он тогдашнюю планку — таблица
«вошёл по одному срезу / данные есть за два» в `REPORT_SELECTION.md`.

## 26. Критерий регрессии V1 (точная формула)

```
E_A = bootstrap-эффективность (лучший_по_r комплекс кампании A) относительно
      его планки на общем финальном пуле задач
E_B = то же для кампании B (H0 — эталон сравнения)
ratio = E_A / E_B, парный bootstrap по общим задачам (общий rng на каждый
        ресэмпл, чтобы ratio считался на ОДНОЙ и той же выборке задач для A и B)

провал V1  <=>  point(ratio) < 1  И  ci_95[1](ratio) < 1
```

Реализация: `fitness.paired_ratio_ci`. Это формализация ручного расчёта, уже
сделанного при подготовке `REPORT_HEREDITY.md` §3 (там же был проверен тот же
принцип «сравнение на пересечении общих задач финального поколения»).

# ЧАСТЬ V. ВОСЬМОЙ УЗЕЛ: ASSEMBLE

## 30. Зачем этот раздел

Эксперимент 14 (`experiment14/REPORT_EXPERIMENT14.md`) измерил тезис пользователя
напрямую: пул из 6 моделей с маршрутизацией по роду шага решает 43% задач против 5%
у лучшей одиночной модели (G1 = +0.3800, CI [+0.27,+0.49], p<0.0001) — при РАВНОМ
числе вызовов. Но там же зафиксирован честный предел: маршрут подбирался
**перечислением** 6⁴ = 1296 вариантов, а не отбором `arch2/`, потому что язык
генотипа (семь узлов Частей I–IV) не мог выразить «шаг i от модели X, шаг j от
модели Y». Три места в тексте прямо называли это вне области:

- §1.1 (Часть I): таблица «почему ровно 7 комбинаторов» — восьмого не было;
- §10 (Часть II): «Язык остаётся из семи узлов» — про автокатализ, ДРУГОЙ вопрос,
  и там утверждение остаётся верным (композит по-прежнему не требует узла);
- §20 (Часть III): «восьмой узел языка» — явно в списке того, что раздел не добавляет.

Этот раздел пересматривает ИМЕННО ЭТО, по правилу, сформулированному в самом §1.1:
комбинатор существует, только если выведен из измеренного. Измеренное здесь — G1
эксперимента 14. **Ни один из семи существующих узлов, Runner, D1/D2/D3, ниши,
парсимония, наследственность (§14) не меняются** — единственное изменение
семантики исполнения добавляется, не заменяет.

## 31. ASSEMBLE — грамматика и семантика

```
ASSEMBLE[N₁..N_k]  -- слот i производит значение шага i задачи
```

Форма поля **намеренно идентична SEQ/PAR** — список под ключом `children`
(`genotype.py::ASSEMBLE`). Это не экономия по лени: `mutate.addresses`,
`children_of`, `walk`, `cost_upper_bound` и валидатор трактуют ASSEMBLE как
SEQ/PAR всюду, где расходится только семантика ИСПОЛНЕНИЯ, а не форма дерева — и
поэтому все шесть операторов мутации (M1–M6) видят поддеревья слотов БЕЗ единой
правки самих операторов, кроме одной строки в `addresses()`. Отдельного седьмого
оператора мутации не понадобилось: откат внутри слота — это `PAR` с ≥2 ветвями,
уже существующий узел, и M3 (`wrap_par`/`add_par_branch`/`drop_par_branch`)
уже умеет его строить и настраивать. Проверено прогоном (`REPORT_ASSEMBLE.md` §4):
`wrap_par` затем `add_par_branch`, применённые напрямую через `addresses`/`set_at`,
корректно оборачивают и расширяют слот ASSEMBLE, не касаясь остальных трёх.

**Денотационная семантика** (§1.2): `⟦ASSEMBLE[N…]⟧σ` — слот `i` исполняется от
КОПИИ входного σ с `τ`, заужённым на шаг `i` (`{**task, "step_index": i, "step":
steps[i]}` — без нового поля состояния: шаг виден через уже существующее `task`,
решение зафиксировано здесь и не пересматривается без правки этого раздела).
Артефакт и evidence слота стартуют ПУСТЫМИ (шаг — независимый вопрос, не
продолжение чужого артефакта; в отличие от PAR, где ветви — альтернативные попытки
ОДНОЙ цели и потому делят входной артефакт). Слот подтверждён ⟺ его ветвь дала PASS
от ДОВЕРЕННОГО шва — тот же критерий, что `_trusted_pass` уже применяет в PAR. Исход
RESOLVED ⟺ подтверждены ВСЕ слоты.

**Найденный и исправленный дефект (до публикации любого результата кампании).**
Первая редакция дописывала evidence каждого слота в общее состояние СРАЗУ внутри
цикла. Если слот `i>0` обрывал прогон через STOP, PASS более раннего слота
оставался ПОСЛЕДНЕЙ записью evidence, и `_last_seam`/`runner.run` объявляли
RESOLVED всему ASSEMBLE, хотя вычисление даже не дошло до решения. Найдено не
проверкой, а АНОМАЛЬНЫМ ЧИСЛОМ на живой кампании: r=1.000 при cost=170 токенов —
ниже стоимости ЛЮБОГО валидного маршрута и выше теоретического потолка объединения
(0.700). Диагностировано, исправлено (`runner._exec_assemble`: per-слотовое evidence
копится в ЛОКАЛЬНОМ списке и коммитится в общее состояние ТОЛЬКО при нормальном
завершении цикла, вместе с агрегатом; путь STOP не коммитит НИЧЕГО), покрыто
регрессионным контрольным случаем
(`tests/test_assemble.py::StopAndBudgetTests::
test_earlier_slot_pass_does_not_leak_through_a_later_stop`), кампания перезапущена
с нуля. Норма проекта: правка видна, а не спрятана — здесь и в `STATUS.md`.

Итог ASSEMBLE попадает в evidence ОДНОЙ синтетической записью, дописанной
ПОСЛЕДНЕЙ (`{"status": PASS|FAIL, "trusted": True, "details": {"kind": "assemble",
...}}`), — так `_last_seam` видит агрегат по ВСЕМ слотам, а не статус случайно
оказавшегося последним слота. ГАРАНТИЯ 5 не нарушена: `trusted=True` на агрегате
верен ПОТОМУ ЧТО он строится только из уже доверенных PASS каждого слота, а не
потому что ASSEMBLE сам оценивает доверие. Стоимость — сумма по слотам (как у
SEQ/PAR: у ASSEMBLE это не только худший случай, а типичный — слоты исполняются
ВСЕ, ленивого выхода нет). STOP в любом слоте завершает весь прогон, решение §1.2
для PAR наследуется без изменений.

**Что сознательно НЕ введено.** `heredity.skeleton()` не получил отдельного
`assemble_widths` (по образцу `par_widths`) — счётчик `ops` подхватывает
`"ASSEMBLE"` сам, а отдельное поле изменило бы `niche_key` у ВСЕХ существующих
генотипов и сломало бы воспроизводимость S0/S1 задним числом. Седьмого оператора
мутации нет (см. выше). Новых полей `State` нет.
