# REPORT_HEREDITY — наследственность и автокатализ в Complex Layer

Спека: `SPEC.md` часть III (§13–20), константы зафиксированы **до** прогона.
Кампании: `metrics/h0_evolution.json`, `metrics/h0b_evolution.json`, рёбра —
`runs/h0/heredity.jsonl`. Критерии: `metrics/h0_autocatalysis.json`,
`metrics/h0b_autocatalysis.json`. Контрольные случаи: `python run_checks.py` — **88/88**
(55 прежних + 33 новых), гейт швов OK.

Обе кампании — **replay, 0 GPU, 0 токенов**. Живой прогон в этой работе не выполнялся.

---

## 1. Что добавлено и зачем

Первый цикл оставил три пробела, каждый из которых виден был прямо в коде:

1. **родство терялось** — хранился только `parent_ids`, оператор и донор не
   восстановимы;
2. **фенотипические близнецы конкурировали вслепую** — в E0 два структурно РАЗНЫХ
   комплекса с побайтово одинаковыми (r, c) = (0.600, 290.2) делили места в элите, и
   один умирал по D2;
3. **автокатализ не был замкнут** — и мешал латентный дефект: `registry.generator_ids()`
   уже возвращал композиты, а `library.attempt()`/M1 строили для них `CALL` **с
   параметрами** при пустой сетке, поэтому валидатор молча отбрасывал таких мутантов.
   **Ни один композит не мог попасть в новый генотип.** Это регресс-тест
   `CompositeInsertionTests`, а не гипотеза.

Добавлены четыре механизма (SPEC §14–17): типизированные рёбра, placement-score как
диагностика с решением по явным CASE-условиям, decay/uses/shadow и замкнутый цикл
регистрации. Семь комбинаторов, планка отбора и D1/D2/D3 не менялись.

### 2.2 Самый содержательный результат — молекула поколения 3

Медиана 0 токенов при r = 0.500 выглядела как дефект и была проверена отдельно.
Дефекта нет: распределение бимодально, а сам комплекс — **второго порядка**:

```
SWITCH task_family
  arithmetic -> STOP(barrier_too_high)          115 задач, 0 токенов
  code       -> SEQ[ CALL cx.cx-e7a657, CHECK enriched_code ]   105 задач
  default    -> STOP(unknown_family)
```

Отбор собрал комплекс, который (а) **полностью отказывается от арифметики**, опираясь
на измеренную высоту барьера (E4.3: value 2.30 нат, other 2.54 против syntax 0.52), и
(б) **делегирует код молекуле, зарегистрированной тремя поколениями раньше**. Ни одного
`RESOLVED` при нулевой стоимости в его трассах нет (проверено): нули — это ветвь STOP.

Это и есть замкнутый цикл в его прямой форме: комплекс стал молекулой и оказался
строительным блоком структурно другого, более дешёвого комплекса.

По итогам этой проверки в `cost_profile` добавлены среднее и доля нулевых стоимостей —
одна медиана на бимодальном распределении читалась бы как «молекула бесплатна». Поля
добавлены **после** этих кампаний и в сохранённых профилях H0/H0b отсутствуют; на
решения они не влияют (профиль не участвует в гейте регистрации).

## 4. Разнообразие элиты

| | элита | корневых семейств | различных каркасов |
|---|---|---|---|
| E0 | 8 | 4 | 6 |
| H0 | 8 | 4 | **8** |

Каркас (skeleton) — независимая от семейства моделей ось: мультимножество операторов,
глубина, множество наблюдаемых у SWITCH. В H0 все восемь членов элиты имеют **разные**
каркасы против шести из восьми в E0. То есть наследственность увеличила структурное
разнообразие, не тронув разнообразие по семействам моделей.

## 6. Что НЕ подтвердилось и что осталось непроверенным

### 6.1 «Потомки с композитом лучше» — не воспроизводится

| кампания | с композитом | без композита |
|---|---|---|
| H0 | r = 0.512, c = 392.0 (n = 14) | r = 0.334, c = 555.2 (n = 4) |
| **H0b** | r = **0.302**, c = 472.3 (n = 9) | r = **0.320**, c = 449.5 (n = 8) |

В H0 разрыв большой и в пользу композитов, **в H0b знак противоположный**. Сравнение
к тому же не парное и на крошечных подвыборках (n = 4 «без композита» в H0). Поэтому:
**использование композита само по себе преимуществом не является** — подтверждён
только факт замкнутости цикла (A1–A5), а не польза композита как таковая. Ровно для
этого второй прогон на свежем seed'е и делался.

### 6.2 Shadow и revival ни разу не сработали

`shadow = 0`, `revivals = 0` в **обеих** кампаниях. Механизм реализован и покрыт
контрольными случаями, но на реальных данных **не проверен**, и по норме проекта
непройденная ветка не считается проверенной.

Причина видна из констант и измеренной динамики: `w = exp(−idle/3)·(1 + 0.5·uses)`
опускается ниже `W_FLOOR = 0.25` только при простое в 5 поколений без единого успеха
потомка, а D1/D2 убивают такой комплекс за одно-два поколения. **Decay доминируется
более жёсткими фильтрами смерти.** Это не ошибка: decay задумывался как ортогональный и
более мягкий канал. Но утверждать, что он что-то сохранил, нельзя — он ничего не
сохранил, потому что ни разу не сработал. Проверить его можно только отдельным
прогоном с ослабленными D1/D2 либо с другим `LAMBDA`, и подкручивать константы **после**
прогона запрещено.

### 6.3 Чего эта работа не заявляет

Ограничения `REPORT_ARCH2.md` §8 остаются в силе и не пересматриваются:

- **не доказано** превосходство над hindsight-best (офлайн +0.0545 CI [−0.0182, +0.1273];
  живьём против B3 ΔR = +0.050 CI [−0.100, +0.200], E = 1.02 CI [0.70, 1.48]);
- **novelty-критерий не пройден** — эта работа его не пересматривала и не перепроверяла;
- **абсолютные live-числа не переносятся** — переносится ранжирование; H0/H0b живьём не
  прогонялись вовсе, все их числа офлайновые;
- прирост A3 означает «потомок с композитом дошёл до элиты/побил планку **своего
  среза**», а не «композиты улучшают систему» — см. §6.1.
