# ЭТАП 0. Фильтр. Результат отрицательный и однозначный

```
R = 0.0000            250 испытаний: 50 иголок × 5 позиций, 49 блоков в стоге
случайный отбор       0.3333 по построению
```

Порог задания — `R ≤ 0.40` означает «отбор случаен, этап 2 не запускать». Получено 0.

**Но результат хуже, чем просто случайный.** Отбор систематически отталкивает нужный блок:

| величина | значение | что означало бы случайное |
|---|---|---|
| средняя доля ранга блока с иголкой | **0.768** | 0.5 |
| лучший достигнутый ранг за 250 испытаний | **22 из 49** | ожидались бы единицы |
| медианный ранг | 35 из 49 | 25 |
| доля попаданий в нижнюю треть | **72.4 %** | 33 % |
| точечно-бисериальная `r(J, содержит иголку)` | **−0.113** | 0 |

`R` равно нулю по всем пяти позициям одинаково: `{5: 0.0, 30: 0.0, 50: 0.0, 70: 0.0, 95: 0.0}`.
Позиция иголки в стоге на результат не влияет.

## Проверки, сделанные до того, как выводу поверить

**Индексация.** Блок, объявленный содержащим иголку, действительно её содержит и
единственный: 0 расхождений на 100 испытаниях. `R = 0` — не ошибка адресации.

**Лексическая утечка.** Требование §0 выполнено программно: `keywords(иголка) ∩
keywords(вопрос) = ∅` для всех 50 иголок. Достигнуто так: `_keywords` — это
`\b[a-zA-Z_]\w{2,}\b` без стоп-листа и стемминга, то есть требует буквы в начале токена.
Поэтому общий референт сделан **числовым** — номер виден модели, но невидим лексическому
отбору, а все содержательные слова разведены синонимами.

```
иголка : Strongroom 100 opens on the combination 7K3DEG.
вопрос : Which sequence unlocks vault 100?
keywords(иголка)  = {combination, opens, strongroom, the}
keywords(вопрос)  = {sequence, unlocks, vault, which}
```

Код ответа тоже начинается с цифры, поэтому и он в keywords не попадает.

## Механизм: почему знак отрицательный

```
corr(J, число общих слов с вопросом)   = +0.416
corr(J, число рёбер графа блока)       = −0.417
вставка иголки: ΔJ = −0.0069, отрицательна в 100 % случаев (+1 узел, +2.72 ребра)
```

Обе половины работают против иголки:

1. **`J` в значительной мере является детектором лексического пересечения с вопросом.**
   Именно этот канал требование §0 и перекрывает — намеренно и правильно. Без него у `J`
   не остаётся сигнала о том, где ответ.
2. **Оставшийся вклад в `J` даёт связность графа, и он направлен не туда.** Вставка
   постороннего предложения добавляет узел и ~2.7 ребра, распределение `π` становится
   ровнее, энтропия растёт, `J` падает. Это происходит в 100 % случаев.

То есть негэнтропийный отбор без лексической подсказки не просто не находит нужный блок —
он его **штрафует за то, что в блоке появилось нечто постороннее**, а именно посторонним
и является искомый факт.

Это, по-моему, и есть содержательный ответ, а не просто отрицательный: механизм измеряет
внутреннюю связность блока, а искомость факта с внутренней связностью не связана.

## Φ отсекает всё

```
Φ > 0 не выполняется НИ ДЛЯ ОДНОГО блока, при обоих прочтениях d_iS
доля блоков с Φ > 0:  0.0 %   (сумма по узлам)   0.0 %   (среднее по узлам)
corr(Φ, содержит иголку) = +0.076
```

Формулировка §0 неоднозначна: `L_r` названо числом рёбер блока, то есть скаляром, а `π_r`
повекторно, поэтому способ свёртки по узлам не задан, и **знак `Φ` от него зависит**.
Посчитаны оба прочтения:

```
d_eS   = −ρ·ΔH·q_env,  ΔH = H(π) − ln n,  ρ = 1, q_env = 0.5  ⇒  |d_eS| = 0.5·ln n·J
d_iS   = L_рёбер · Σ_r (π_r − π̄)²        (прочтение 1, сумма)
d_iS   = L_рёбер · Σ_r (π_r − π̄)² / n    (прочтение 2, среднее)
```

При обоих `d_iS > |d_eS|` всегда. Фильтр `Φ > 0` отбраковал бы контекст целиком. Это не
«катастрофа» в смысле §0 — иголка не отсекается выборочно, отсекается всё, — но означает,
что при этих значениях `ρ` и `q_env` фильтр нерабочий и калибровка констант не проверялась.

# ЭТАП 3.1. Ранг-1 зонд слеп, и контроль важнее числа

```
Q(4) = 0.343 ± 0.197      порог годности из §3.1 — 0.70
```

| k | Q, реальные кластеры | Q, **случайные** кластеры | 1/\|C\| |
|---|---|---|---|
| 2 | 0.399 ± 0.181 | **0.596** | 0.500 |
| 4 | **0.343** ± 0.197 | **0.346** | 0.250 |
| 8 | 0.275 ± 0.194 | 0.198 | 0.125 |
| 16 | 0.208 ± 0.182 | 0.112 | 0.062 |
| 32 | 0.138 ± 0.151 | 0.063 | 0.031 |

Замерено на 7 слоях (0, 4, 8, …, 24), по всем кластерам каждого слоя.

**Главное здесь — не то, что `Q(4) = 0.343 < 0.70`, а то, что случайные кластеры дают
ровно столько же: 0.346.** Соактивационная кластеризация не даёт ранг-1 зонду ничего. При
`k = 2` она даже заметно хуже случайной (0.399 против 0.596).

Смысл: `Q` измеряет согласованность **направлений весов** внутри группы, а кластеры
строились по **совместной активации**. Это разные вещи, и они, судя по `k = 2`, скорее
антикоррелируют. Группировка, сохраняющая разрежённость (задание 2, `S(4) = 0.627`), — не
та группировка, которая позволяет заменить `|C|` скалярных произведений одним.

Замечание к самому порогу: ориентир §3.1 «`Q ≈ 1/|C|` ⇒ зонд слеп» занижен. Строки
`gate_proj` не изотропны, поэтому даже случайная четвёрка даёт 0.346, а не 0.25. Правильная
точка отсчёта — случайные кластеры, и по ней зонд не слеп, а **ровно бесполезен**.

## Что вызывает сомнение

- **Стог синтетический и шаблонный.** Абзацы собраны из банка предложений по 12 темам и
  6 шаблонам. Разнообразие ниже, чем у настоящего текста, и это могло сузить разброс `J`
  (наблюдаемый: 0.0137…0.1082, std 0.0214). На реальном тексте разброс был бы шире, но
  знак корреляции с «содержит иголку» от этого едва ли изменится: механизм отрицательного
  результата — рост связности от вставки — от источника текста не зависит.
- **`R = 0` получено при одном размере блока** (абзац из 6 предложений). Более крупные
  блоки дали бы больше узлов и, возможно, иной баланс. Не проверялось.
- **`Q` посчитано по `gate_proj`.** Зонд, вообще говоря, может строиться и по
  `gate_proj·up_proj` совместно; §3.1 этого не уточняет.
- Кластеры строятся MiniBatchKMeans, а не полным k-means — как и в отчёте 2. `Q` и `S`
  поэтому нижние оценки.

## Вывод по этапу 0

Негэнтропийный отбор блоков в том виде, как он задан, **не находит нужный блок и
отталкивает его**. Причина установлена и не зависит от модели, размера стога и позиции:
без лексического пересечения с вопросом `J` не несёт сигнала о релевантности, а вставка
искомого факта повышает связность блока и тем самым `J` понижает.

Прежде чем запускать какой-либо инференс по этой линии, нужен другой критерий отбора.
Проверка этого стоила менее двух минут вместо четырёх часов.
