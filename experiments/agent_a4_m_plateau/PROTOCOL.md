## 1. Цель пакета — три ответа сразу

A3 (`agent_a3_mstar/reports/REPORT_A3.md`) нашёл `m*=0.60` как ЛУЧШИЙ из
протестированной сетки `{0.05,0.15,0.30,0.45,0.60}`, но не плато: `J` и
`p_A∧B` ускоренно росли к правому краю (0.30→0.45: +0.019, 0.45→0.60:
+0.074). A3 также показал, что snapshot-вердикты систематически завышают
успех относительно archive-вердиктов (на m*=0.60: `V1_snap=1.00` против
`V1_archive=0.00` на всех 10 прогонах без исключения).

A4 закрывает вопрос m в одном заходе:
1. Находит плато или верхнюю рабочую точку `p_cross` на РАСШИРЕННОЙ сетке
   `{0.50,0.65,0.80,0.90}`.
2. Все claim'ы — ТОЛЬКО archive на полной 100-задачной сетке (исключая
   эталоны). Snapshot считается опционально, для таблицы «для истории», НЕ
   для вердикта.
3. Вердикт — ровно ОДНА из трёх корзин:
   - `M_PLATEAU_V3_FAIL` — `p_A∧B` вышел на плато, `best_r_archive < 0.70`
   - `M_STILL_RISING` — на правом краю сетки `p_A∧B`/`J` ещё растут
   - `V3_ARCHIVE_HIT` — `∃ g ∈ archive \ references: r_full(g) ≥ 0.70 И
     c_full(g) < 917.4`, подтверждено у ≥2 из 3 seed на одном уровне

**Ограничения**: алфавит молекул не расширяется; `testgrid`/live GPU не
запускаются; число поколений НЕ подбирается по сетке — фиксируется одним
достаточно большим значением (32), чтобы `G_STALL=16` не душил high-`p_cross`
раньше времени. `arch2/`, `agent_a2_assemble_budget/`, `agent_a3_mstar/` не
редактируются. При провале `verify_baselines.py` (|Δr| > 1e-4) — СТОП.

## 4. Сетка `p_cross` (расширенная вверх относительно A3)

```
p_cross ∈ {0.50, 0.65, 0.80, 0.90}
```

4 уровня × 3 seed = 12 прогонов.

Оператор — тот же `swap_assemble_slot`, что A3 (перенос целого поддерева
слота, уклон `P(LOOKUP)=P(COMPUTE)=2×P(READ)=2×P(FORMAT)`, откат на
`arch2.mutate.mutate` при неудаче за 10 попыток). Сам оператор в A4 НЕ
меняется — меняется частота его применения.

**`min_frac_local` (новое в A4, обоснование).** `swap_assemble_slot`
ПЕРЕСТАВЛЯЕТ уже существующие в популяции атомы между генотипами — он не
может произвести атом, которого ещё ни у кого нет (это делает только
обычная точечная мутация, M1-M4/M6 из `arch2.mutate`). При `p_cross=0.90`
(90% актов — перестановка) риск: популяция быстро гомогенизируется вокруг
уже открытых атомов, но перестаёт ИССЛЕДОВАТЬ новые. Поэтому: **фактически
применяемая вероятность `effective_p_cross = min(p_cross, 1 −
min_frac_local) = min(p_cross, 0.75)`** — при `p_cross ∈ {0.50, 0.65}` без
изменений (уже ≤ 0.75), при `p_cross ∈ {0.80, 0.90}` реально применяется
0.75. Номинальный и фактический `p_cross` оба публикуются в отчёте — правка
видна, не спрятана.

**Запрет**: НИ ОДИН эталон (`REF_B1_route`, `REF_B2_greedy2`,
`REF_B3_greedy_cover`) не вставляется ни в старт, ни как донор для
`swap_assemble_slot`/`arch2.mutate.mutate` (тот же принцип, что A2/A3).

**Поправка, внесённая ДО кампании (найдено смоук-тестом на p_cross=0.90,
seed=20261101, до полных 12 прогонов)**: A3's `PROTOCOL.md` §4 УЖЕ
декларировал этот запрет («ни как донора не производится ни при каком
уровне»), но код A3 (`custom_reproduce`) его фактически не применял —
`ctx["donors"]` строился из ВСЕГО `ev.archive`, эталоны включительно.
На A3's протестированной сетке (`p_cross ≤ 0.60`) это не проявилось видимо
(максимум `best_r_archive` = 0.680, эталона не достигал), но на A4's
`effective_p_cross=0.75` (клэмп при `p_cross=0.90`) обнаружилось напрямую:
первый смоук-тест дал `best_r_archive=0.7000, best_c_archive=917.37` —
ТОЧНОЕ повторение `REF_B3_greedy_cover`, а не открытие поиска: при высокой
интенсивности рекомбинации `swap_assemble_slot` может ПОСЛЕДОВАТЕЛЬНО
скопировать все 4 слота эталона через несколько раундов, и потомок-клон с
другим `complex_id` окажется в архиве идентичным B3 по (r,c). Исправлено в
`custom_reproduce` (`src/orchestrator.py`) ДО реальной кампании: эталоны
исключены из `ctx["donors"]` тем же способом, что и из архивных метрик.
Повторный смоук-тест на тех же параметрах дал `best_r_archive=0.53` —
не эталонное число. Расхождение между предрегистрацией и реализацией в A3
(не исправляется здесь — `agent_a3_mstar/` не редактируется, изоляция) не
меняет качественный вывод A3 (V3_archive=False на всех 10 прогонах): если
что, наличие незамеченной лазейки и всё равно нулевой результат делают
A3's негативный вывод более, а не менее устойчивым.

## 5. Метрики (решают ТОЛЬКО эти, все — по archive \ references, full 100 tasks)

Правило archive-вердиктов идентично A3 (`agent_a3_mstar/PROTOCOL.md` §5.1):
переоценка каждого архивного генотипа (исключая посеянные эталоны) на ВСЕХ
100 train-задачах, сравнение с ФИКСИРОВАННЫМИ каноническими числами §2
(не с шумным control-срезом).

- `p_A`, `p_B`, `p_A∧B` — доля генотипов архива с расширенным COMPUTE/
  LOOKUP/обоими (`len(models_on_slot) ≥ 2`, формула из A2/A3 без изменений)
- `best_r_archive`, `best_c_archive`, `best_nodes` — argmax по `(r_full,
  −c_full)` среди генотипов архива (без эталонов)
- `V1_archive`: `∃ g: r_full(g) > 0.4600 И c_full(g) ≤ 667.4`
- `V2_archive`: `∃ g`: ASSEMBLE, слот COMPUTE (индекс 3) — PAR ≥2 ветви, И
  `r_full(g) ≥ 0.5800`
- `V3_archive`: `∃ g: r_full(g) ≥ 0.7000 И c_full(g) < 917.4`
- `J = mean(p_A∧B) − 0.05 × mean(nodes) / 30` (та же формула, что A3)

**Snapshot** (последнее поколение, control-срез, как A2/A3) считается и
публикуется в отдельной таблице «для истории» — НЕ используется ни в одном
предрегистрированном правиле §6.

## 6. Предрегистрированные правила (не меняются после прогонов)

1. **`m* = argmax mean(J)`** по 3 seed на каждом уровне `p_cross`. Тай-брейк
   при `Δmean(J) < 0.005` между уровнями — меньший `p_cross`.
2. **Плато**: на ДВУХ соседних ВЕРХНИХ уровнях сетки одновременно
   `Δmean(p_A∧B) < 0.015` И `ΔJ < 0.01` → `PLATEAU = yes`.
3. **`V3_HIT`** (строже A3): `V3_archive` истинен у **≥2 из 3** seed на ОДНОМ
   уровне `p_cross` → успех пакета по V3 (не «хотя бы 1»).
4. **Корзина вердикта** — ровно одна из трёх (§1), выбирается по факту
   итоговой таблицы, в этом порядке приоритета: если `V3_HIT` истинен на
   каком-либо уровне → `V3_ARCHIVE_HIT`; иначе если `PLATEAU = yes` И
   `best_r_archive` на плато-уровнях `< 0.70` → `M_PLATEAU_V3_FAIL`; иначе
   → `M_STILL_RISING`.

## 7. Non-goals (явный запрет заявления)

- Не заявляется `r_full ≥ 0.70` без подтверждённого `V3_archive` (правило 3).
- Не заявляется перенос на held-out/testgrid.
- Не заявляется расширение алфавита молекул.
- Не производится правка `arch2/`, `agent_a2_assemble_budget/` или
  `agent_a3_mstar/`.
- Snapshot-числа не используются как основание ни для одного вердикта —
  только archive.
