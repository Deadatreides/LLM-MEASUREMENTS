## Дефект, найденный и исправленный ДО кампании (смоук-тест одной ячейки)

Обнаружено на `p_cross=0.90, seed=20261101`: `ctx["donors"]` в
`custom_reproduce` строился из ВСЕГО `ev.archive`, включая посеянные
эталоны. При высокой интенсивности рекомбинации (`effective_p_cross=0.75`)
`swap_assemble_slot` может ПОСЛЕДОВАТЕЛЬНО скопировать все 4 слота
`REF_B3_greedy_cover` через несколько раундов — первый смоук-тест дал
`best_r_archive=0.7000, best_c_archive=917.37`, ТОЧНОЕ повторение эталона,
не открытие поиска. **Это расхождение уже существовало в A3**: A3's
`PROTOCOL.md` §4 декларировал запрет на эталон-как-донора, но код A3
(`custom_reproduce`) его не применял — на A3's сетке (`p_cross≤0.60`) это
не проявилось видимо (максимум `best_r_archive`=0.680), но на A4's более
высокой интенсивности обнаружилось напрямую. Исправлено в A4 ДО кампании:
эталоны исключены из `ctx["donors"]` (`src/orchestrator.py::
custom_reproduce`). `agent_a3_mstar/` не редактировался (изоляция) —
расхождение зафиксировано здесь как найденное, не исправлено там.

## ВАЖНАЯ находка после кампании: `p_cross=0.80` и `p_cross=0.90` — не независимые прогоны

`effective_p_cross = min(p_cross, 0.75)` (PROTOCOL.md §4, `min_frac_local`)
означает, что `p_cross=0.80` и `p_cross=0.90` ОБА дают
`effective_p_cross=0.75` РОВНО. Поскольку `p_cross` больше нигде в
`custom_reproduce` не используется (только через `effective_p_cross`), а
RNG-поток эволюции зависит только от `seed` (одинакового для пары
0.80/0.90 при совпадающем seed), результаты для 0.80 и 0.90 оказались
**побитово идентичными по всем полям** на каждом из 3 seed (проверено
программно: `runs[(0.8,seed)] == runs[(0.9,seed)]` для всех полей кроме
`p_cross_nominal`, для всех трёх seed — да, идентичны).

**Следствие**: сетка `{0.50, 0.65, 0.80, 0.90}` фактически протестировала
только **3 РАЗЛИЧНЫХ конфигурации** (`effective_p_cross ∈ {0.50, 0.65,
0.75}`), не 4. Механическое правило плато (PROTOCOL.md §6.2, сравнение ДВУХ
ВЕРХНИХ НОМИНАЛЬНЫХ уровней) сравнило `0.80` с `0.90` — то есть сравнило
конфигурацию САМУ С СОБОЙ, дав `Δp_A∧B=0.0000, ΔJ=0.000000` тривиально, не
потому что кривая действительно вышла на плато. Настоящая кривая по ТРЁМ
различным точкам (`eff=0.50→0.65→0.75`) — **НЕ монотонна**:
`p_A∧B`: 0.0394 → 0.0122 (падение) → 0.0348 (восстановление, но ниже 0.50).
`J`: 0.0066 → −0.0183 → 0.0043. Это шум/немонотонность, а не чистое плато.

Формальный вердикт-корзина (`M_PLATEAU_V3_FAIL`), вычисленный механически по
предрегистрированному правилу, **сохраняется как есть** (правило само по
себе не переопределяется задним числом — норма проекта), но интерпретация в
`reports/REPORT_A4.md` §3/§5 явно отмечает: подтверждающее плато-условие —
артефакт конструкции клэмпа, а не независимое эмпирическое наблюдение.
Честная альтернативная формулировка: за пределами `effective_p_cross=0.75`
эта конкретная конструкция (`min_frac_local=0.25` фиксирован) СТРУКТУРНО НЕ
МОЖЕТ различить более высокие номинальные `p_cross` — вопрос "растёт ли J
дальше" при этом `min_frac_local` не может быть задан, а не отвечен
отрицательно.
