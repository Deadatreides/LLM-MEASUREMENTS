# ARCH-0 — архитектурная спецификация Мицелия

**Что это.** Формальная архитектура вычислительной среды, в которой объект управления — состояние графа артефактов и claims, а не ответ LLM.

**Чего здесь нет.** Кода, роутера, bandit, production-API, PTG-интеграции, MVP. Спецификация остановлена на границе между экспериментом и реализацией.

**Статус:** `READY_FOR_IMPLEMENTATION` (см. ARCHITECTURE_AUDIT.md §5).

## Три вещи, которые нужно понять прежде всего

**1. Три отношения нельзя смешивать.**
```
STRUCTURAL DEPENDENCY  ≠  VALIDITY STATE  ≠  REPAIR NECESSITY
```
«C2 зависит от C1» не означает «C2 сломан» и не означает «C2 надо перегенерировать».

**2. Граф даёт верхнюю границу, а не план ремонта.**
```
AFFECTED_REGION  ⊋  MINIMAL_REPAIR_SET
```
Между ними обязателен шаг сужения через проверку. Граф безопасен (ничего не пропускает), но систематически избыточен.

**3. LLM — оператор, а не судья.**
Суждение модели о корректности не может быть жёстким доказательством ни при каком количестве повторов. Это самый задокументированный факт всего проекта.

## Главный риск (читать перед реализацией)

Вся ценность архитектуры — локализация и экономия ремонта. Но:

- декомпозиция **не улучшает** качество ответа и стоит дороже (подтверждено);
- значит, она оправдана **только** экономией ремонта;
- а сама эта экономия спроектирована по данным, но **живьём не измерялась**;
- и все подтверждения точности локализации получены на графах, **заданных заранее человеком**.

Поэтому первый этап реализации (ARCH-1, см. ARCHITECTURE_AUDIT.md §5.4) — не полная система, а вертикальный срез, единственная цель которого — измерить эти два допущения. При их провале расширять систему нельзя.

Подробно — ARCHITECTURE_AUDIT.md, Часть 4.
