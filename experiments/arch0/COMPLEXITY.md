# COMPLEXITY.md — асимптотика

Обозначения:

```
N — артефактов в задаче
M — claims
E — рёбер зависимости
S — швов
K — evidence
R — итераций ремонта
D — глубина DAG
B — коэффициент ветвления
```

Наблюдённые в экспериментах масштабы: N ≈ 3–6, M ≈ 4–8, E ≈ 0–6, D ≈ 2–4. **Всё, что ниже — расчёт, а не измерение**, кроме отдельно отмеченного (F41).

---

## 1. Построение графа

| Операция | Сложность | Комментарий |
|---|---|---|
| Извлечение claims из артефакта | O(размер артефакта) | парсинг секций, детерминированный |
| Вывод зависимостей по фиксированной схеме | O(M) | схема задаёт рёбра напрямую |
| Вывод зависимостей эвристикой (§3.2 DEPENDENCY_MODEL) | **O(M²)** | попарное сравнение claims — **первое место квадратичного роста** |
| Детекция цикла при вставке ребра | O(V + E) на ребро; O(E·(M+E)) на построение | можно снизить инкрементальным поддержанием топологического порядка |
| Генерация швов по схеме | O(S) | |

### 1.1 Квадратичный рост №1: попарный вывод зависимостей

Эвристика «совпадающее значение + пересечение контекста» (F40) по построению попарная: O(M²).

**Смягчение:** индексирование по значениям — сравнивать только claims, разделяющие хотя бы одно нетривиальное значение. Ожидаемо близко к O(M · среднее число claims на значение), в худшем случае остаётся O(M²).

**Практический предел:** при M порядка сотен попарный вывод перестаёт быть бесплатным относительно генерации. Экспериментальных данных нет (OQ-DEC-3).

## 2. Обход зависимостей

| Операция | Сложность |
|---|---|
| `downstream_closure(origin)` | **O(M + E)** при предвычисленном обратном индексе |
| `upstream_closure(claim)` | O(M + E) |
| `root_origins(defective)` | O(\|defective\| · (M + E)) наивно; **O(M + E)** при одном проходе в топологическом порядке |
| `topological_order` | O(M + E) |
| Схлопывание SCC (Tarjan) | O(M + E) |

**Оптимизация `root_origins`:** наивная реализация вызывает `upstream_closure` для каждого дефектного claim. Правильная — один проход в топологическом порядке с пометкой «достижим из дефектного предка». Это важно, потому что `root_origins` вызывается на каждой итерации ремонта.

---

## 3. Распространение состояния

| Операция | Сложность |
|---|---|
| `propagate_stale(changed)` | **O(M + E)** — один обход вниз |
| Проверка инвариантов состояния | O(M + K) |
| `apply_evidence` для одного subject | O(K_subject) — evidence по этому subject |

Распространение STALE линейно. Это принципиально: оно происходит при **каждом** изменении версии узла, то есть чаще всего остального.

---

## 4. Вычисление области влияния

| Операция | Сложность |
|---|---|
| `candidate_affected_set` | O(M + E) |
| `narrow()` — шаг сужения | **O(\|candidate\| · cost(seam))** |
| Итого на коллизию | O(M + E + Σ cost(seam)) |

**Доминирующий член — не граф, а швы.** Обход дёшев (F41: доли миллисекунды на графе из 6 узлов), а исполнение проверок может быть произвольно дорогим — вплоть до вызова модели для SOFT-швов.

Отсюда правило в REPAIR_MODEL.md §3: если `cost(seam) > cost(REGENERATE)`, узел уходит в `unknown_set` вместо проверки.

## 5. Планирование ремонта

| Операция | Сложность |
|---|---|
| Назначение necessity | O(\|candidate\|) |
| Оценка стоимости стратегий | O(число стратегий · \|candidate\|) = O(\|candidate\|) |
| Хеш плана (детекция осцилляции) | O(\|candidate\|) |
| **Точный MRS перебором** | **O(2^M · cost(проверка))** ← экспоненциальный рост |

### 5.1 Экспоненциальный рост: точный MRS

Это **измеренный**, а не предполагаемый факт (F41): полный перебор подмножеств для 6 узлов = 64 проверки, укладывался в доли миллисекунды. При M = 20 это уже ~10⁶ проверок, при M = 30 — ~10⁹.

**Архитектурное решение:** точный MRS перебором **не используется в общем пути**. Используется приближение сверху через шаг сужения (REPAIR_MODEL.md §5.3), стоимость которого линейна по `|candidate|`.

Перебор допускается только:
- в диагностическом режиме,
- при `|candidate_set| ≤ MRS_BRUTE_FORCE_LIMIT` (конфигурируемый жёсткий предел),
- для калибровки правил сужения на малых графах.

## 6. Итерации ремонта

Полная стоимость обработки коллизии:

```
O( R · [ (M + E)                       # обходы графа
       + |candidate| · cost(seam)      # сужение
       + |repair_set| · cost(action) ] # исполнение
  )
```

`R` ограничен сверху жёстко:
- `MAX_ITERATIONS` на коллизию;
- детекция повтора состояния по хешу (граф + план) — O(1) на итерацию при хранении множества хешей;
- детекция осцилляции — O(1).

**Без этих ограничителей `R` неограничен**, и именно это делает их обязательными, а не желательными.

## 7. Хранилище

| Величина | Рост |
|---|---|
| Число версий артефактов | **линейно по числу действий** — append-only, ничего не удаляется |
| Evidence | линейно по числу проверок |
| STATE_RECORD | линейно по числу переходов |
| RUN + сырьё | линейно по числу вызовов, **но с большим коэффициентом** (полный промпт + полный вывод) |

**Осознанный размен:** append-only хранение сырья стоит дискового места и растёт линейно без верхней границы в пределах задачи. Это принято сознательно — F45: без сырья невозможно отличить дефект проверяющей инфраструктуры от свойства модели, а такие дефекты в этом проекте возникали регулярно.

Смягчение (не влияет на семантику): сжатие холодных записей, вынос сырья в отдельное хранилище с ссылкой. **Удаление — нет.**

## 8. Параллельность

```
Два claim можно вычислять параллельно ⟺
    ни один не достижим из другого по графу зависимостей
```

| Понятие | Определение |
|---|---|
| `parallelizable` | множество claims без взаимной достижимости |
| `serial` | claims на одном пути зависимостей |
| `barrier` | merge-узел: не может стартовать, пока не завершены все его прямые предки |

**Максимальный параллелизм** ограничен шириной графа (максимальное антицепное множество). Для наблюдавшихся графов (B = 2) это 2 — то есть выигрыш от параллелизма скромный и структурно ограничен.

Отдельно: параллельные ветви **делят общий бюджет**, поэтому BUDGET MANAGER использует reserve/commit (BUDGET_MODEL.md §1), иначе параллельные ветви перерасходуют.

Практическое ограничение, не архитектурное: в проведённых экспериментах вычисления шли на одном GPU, где параллельный запуск нескольких моделей невозможен физически. Семантическая модель параллелизма определена, но её выигрыш на реальном железе не измерялся.

## 9. Сводка мест роста

| Место | Рост | Статус | Смягчение |
|---|---|---|---|
| Попарный вывод зависимостей | O(M²) | расчётный | индекс по значениям |
| Точный MRS перебором | **O(2^M)** | **измерен** (F41) | не используется в общем пути; жёсткий лимит |
| Наивный `root_origins` | O(\|D\|·(M+E)) | расчётный | один топологический проход |
| Хранение сырья | линейно, без границы | принято сознательно | сжатие, вынос; не удаление |
| Итерации ремонта | потенциально неограничен | — | обязательные STOP-условия |
| Обходы графа | O(M + E) | измерен как пренебрежимый (F41) | — |

## 10. Открытый вопрос

**OQ-COMPLEX.** Все измерения асимптотики получены на графах из 4–8 claims. Поведение при M порядка сотен неизвестно: в частности, неясно, начнёт ли O(M²)-вывод зависимостей доминировать над стоимостью генерации, и останется ли доля времени графового анализа пренебрежимой. Ни одного эксперимента на больших графах не проводилось.
