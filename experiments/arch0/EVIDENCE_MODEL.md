# EVIDENCE_MODEL.md — модель свидетельств

## 1. Роль evidence

Evidence — **единственный** способ изменить представление системы о валидности. Состояние claim не меняется «потому что так решил планировщик» или «потому что модель уверена» — только по evidence с достаточной силой.

```
SEAM / ACTION / EXTERNAL SOURCE  ──►  EVIDENCE  ──►  STATE ENGINE  ──►  STATE
```

---

## 2. Типы evidence

| Тип | Источник | Воспроизводимость | Базовая сила |
|---|---|---|---|
| `MECHANICAL` | детерминированная процедура (сравнение, разбор схемы, арифметика) | `DETERMINISTIC` | **HARD** |
| `EXECUTION` | фактическое исполнение кода/вычисления | `DETERMINISTIC` (при фиксированном окружении) | **HARD** |
| `EXACT_MATCH` | точное совпадение с известным эталоном | `DETERMINISTIC` | **HARD** |
| `STATIC_ANALYSIS` | разбор структуры без исполнения (AST и т.п.) | `DETERMINISTIC` | **HARD** (для структурных утверждений) |
| `EXTERNAL_DATA` | внешний независимый источник данных | зависит от источника | **HARD** или `MODERATE` |
| `HUMAN` | человеческое суждение | `ONE_SHOT` | **HARD** (по определению доверия) |
| `MULTI_SOURCE_AGREEMENT` | согласие нескольких генераций | `STOCHASTIC` | **зависит от оси независимости**, см. §4 — максимум `MODERATE` |
| `MODEL_JUDGEMENT` | суждение модели о **чужом** артефакте | `STOCHASTIC` | **WEAK** |
| `SELF_JUDGEMENT` | суждение модели о **собственном** артефакте | `STOCHASTIC` | **WEAK** (и особо помечено) |
| `UNKNOWN` | процедура не дала результата / сломалась | — | `NONE` |

## 3. Иерархия доверия

### 3.1 Порог `HARD_ENOUGH`

```
HARD_ENOUGH := strength ∈ {HARD}
```

То есть: **перевести claim в `CORRECT` или `INCORRECT` может только evidence силы `HARD`.**

`MODERATE` и `WEAK` evidence могут:
- переводить в `CONFLICTED` или `UNKNOWN`;
- менять `confidence`;
- порождать коллизию;
- служить основанием для запроса более сильного evidence;

но **не могут** сами закрыть вопрос о валидности.

### 3.2 Правило разрешения конфликтующих evidence

```
FUNCTION resolve(evidence_set, claim):
    hard_support ← {e ∈ set : strength=HARD ∧ assertion=SUPPORTS}
    hard_refute  ← {e ∈ set : strength=HARD ∧ assertion=REFUTES}

    IF hard_refute ≠ ∅ AND hard_support ≠ ∅:
        RETURN CONFLICTED          # два жёстких источника не согласны — это
                                   # содержательная проблема, а не арифметика
    IF hard_refute ≠ ∅:  RETURN INCORRECT
    IF hard_support ≠ ∅: RETURN CORRECT
    IF set == ∅:         RETURN GENERATED / UNVERIFIED (по применимости seam)
    RETURN UNKNOWN                 # есть только MODERATE/WEAK
```

**Слабое evidence не «набирается» до сильного.** Ни при каком количестве `WEAK` evidence claim не становится `CORRECT`.

Обоснование — F9/F10/F14 совместно: множественные согласные суждения модели в этих данных систематически ошибались вместе (сгенерированные тесты отвергали правильный эталон в большинстве случаев, при этом внутренне выглядели строгими). Механизм накопления слабых свидетельств воспроизвёл бы именно эту ошибку.

### 3.3 Явный запрет (инвариант `LLM_JUDGEMENT_IS_NOT_HARD_ORACLE`)

```
∀ claim: state == CORRECT ⇒ ∃ evidence e:
    e.assertion == SUPPORTS ∧
    e.strength == HARD ∧
    e.evidence_type ∉ {MODEL_JUDGEMENT, SELF_JUDGEMENT}
```

Это проверяемый assert, а не рекомендация.

## 4. Независимость источников — обязательное поле

### 4.1 Проблема

Наивно: «три генерации согласились → уверенность высока».
Экспериментально: **ошибка одной модели на конкретной задаче повторяется в независимом повторе примерно в 3 случаях из 4** при базовой частоте ошибки около 1 из 10 (F1). То есть повтор той же конфигурации — это не независимая проверка, а почти детерминированное воспроизведение того же результата, включая ошибочный.

### 4.2 Ось независимости

`MULTI_SOURCE_AGREEMENT` **обязан** нести поле `independence_axis`:

| Ось | Что различается | Наблюдаемая сила независимости | Максимальная присваиваемая strength |
|---|---|---|---|
| `NONE` | ничего (буквальный повтор) | нет | `NONE` |
| `SEED` | только seed | минимальная (F1) | `WEAK` |
| `TEMPERATURE` | температура/сэмплинг | низкая (F5: растёт поверхностное, не смысловое разнообразие) | `WEAK` |
| `PROMPT` | формулировка промпта | низкая; **в этих данных не лучше смены seed** (F7) | `WEAK` |
| `MODEL` | другая модель | наивысшая из проверенных внутримодельных (F6, F8) | `MODERATE` |
| `FAMILY` | другое семейство/происхождение модели | наивысшая | `MODERATE` |
| `EXTERNAL` | независимый неязыковой источник | максимальная | `HARD` (переходит в `EXTERNAL_DATA`) |

**Важно:** даже согласие разных моделей даёт максимум `MODERATE`, никогда `HARD`. Основание — F14 и F17: доля совместной необнаруживаемой ошибки не равна нулю ни на одной оси, а на конкретных «слепых» claim согласие может быть полным при полной неправоте (наблюдался случай 0 верных из 8 при полном согласии).

### 4.3 Уточнение к F7

F7 (смена промпта не дала независимости) имеет силу NEGATIVE на одном наборе моделей класса ≤1.7B. Архитектура закладывает **порядок** осей, а не абсолютные значения, и допускает пересмотр таблицы §4.2 при появлении данных на других классах моделей. Таблица — конфигурация, а не константа кода.

## 5. Структура записи

```
EVIDENCE {
  evidence_id, subject, assertion ∈ {SUPPORTS, REFUTES, INCONCLUSIVE}
  evidence_type, strength, reproducibility
  independence_axis        # обязательно для MULTI_SOURCE_AGREEMENT
  source { kind, identifier, version }
  method                   # как именно получено, воспроизводимо описано
  raw_ref                  # ссылка на сырые данные (RUN.raw_output и т.п.)
  timestamp, provenance
}
```

**`raw_ref` обязателен.** Основание — F45: за проект не менее шести дефектов проверяющих правил были обнаружены пересчётом по сохранённым сырым данным. Evidence без ссылки на сырьё невозможно перепроверить, а значит невозможно отличить ошибку модели от ошибки проверки.

## 6. Режим без механического oracle

Отдельный обязательный раздел (требование §22 задания). Экспериментально это **самый большой пробел** (OQ-4): все подтверждённые факты получены там, где oracle существовал.

### 6.1 Что система имеет право утверждать

При `task.oracle_availability = NONE` система работает в режиме **graph consistency only**:

**Может:**
- фиксировать структурную несовместимость между claims (два claim в графе утверждают взаимоисключающее);
- фиксировать нарушение объявленного контракта формата (`SEAM_FORMAT` остаётся HARD);
- фиксировать расхождение независимых источников (`SEAM_CONFLICT` — факт расхождения объективен);
- локализовать, **где** возникло противоречие, и какие claims от него зависят;
- определить, какие ветви точно не затронуты (F35 — структурное свойство, не зависит от наличия oracle);
- отделить проверяемое от непроверяемого.

**Не может:**
- утверждать, что claim `CORRECT`;
- утверждать, что claim `INCORRECT` — только `CONFLICTED` или `UNKNOWN`;
- разрешить конфликт «по большинству»;
- считать согласие моделей подтверждением.

### 6.2 Распространение неопределённости

```
IF claim.state == UNKNOWN:
    все downstream по CONFIRMED и HYPOTHESIS рёбрам получают
    "unverifiable_ancestor" маркер и НЕ могут перейти в CORRECT,
    пока предок остаётся UNKNOWN
```

То есть неопределённость **не исчезает** при движении вниз по графу — claim, построенный на непроверяемой предпосылке, не может быть «более доказан», чем его предпосылка.

### 6.3 Что считается полезным результатом без oracle

Требование §21 задания: локализация конфликта, определение затронутых артефактов, определение зависимостей и сохранение честного `UNKNOWN` **считаются успехом** даже без установления истины. Архитектура фиксирует это как легитимный терминальный результат (`COLLISION.status = ACCEPTED`, `claim.state = UNKNOWN`), а не как отказ.

## 7. Политика для UNKNOWN

Требование §21 задания: решение зависит от риска и бюджета задачи, а не зашито.

```
FUNCTION unknown_policy(claim, task, budget):
    IF существует более сильный доступный источник evidence
       AND budget позволяет:
        RETURN VERIFY                    # запросить более сильное evidence

    IF task.risk_level == HIGH:
        RETURN STOP_AND_REPORT           # не выдавать как результат молча

    IF task.risk_level ∈ {LOW, MEDIUM}:
        RETURN ACCEPT_WITH_UNCERTAINTY   # отдать с явным маркером UNKNOWN

    RETURN STOP_AND_REPORT               # безопасный дефолт
```

Во всех трёх исходах `UNKNOWN` **остаётся в выдаче как явный статус**. Инвариант `UNKNOWN_IS_NOT_ERROR` запрещает как молчаливое превращение в ошибку, так и молчаливое превращение в успех.

## 8. Чего модель evidence сознательно не содержит

| Отсутствует | Почему |
|---|---|
| Числовой «общий уровень доверия» claim | нет экспериментального основания; F18/F19 показали, что скалярные метрики не предсказывают то, ради чего их вводят |
| Байесовское накопление слабых свидетельств | предполагает независимость, которой в данных нет (F1); воспроизвело бы систематическую ошибку как «уверенность» |
| Автоматическое повышение силы при повторе | F1 напрямую запрещает |
| Голосование | F14, F16, F17 |
