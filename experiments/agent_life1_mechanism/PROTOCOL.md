# PROTOCOL.md — agent_life1_mechanism

Написан и зафиксирован **2026-08-20, до вычисления любых чисел audit**
(N_A/N_AB/P(B|A)/L/overlap). Не переписывается задним числом — правило
проекта: если механическая корзина `MECH_*` даст на вид странный результат,
он публикуется КАК ВЫЧИСЛЕН, интерпретация добавляется рядом, явно.

## §0. Рамка

Цель — НЕ найти лучший маршрут на 6 моделях HETEROSTEP. Цель — универсальный
механизм сборки/переноса/выживания: атомы → блоки → горизонтальный перенос →
отбор/смерть/архив → (опц.) автокатализ. HETEROSTEP+6 моделей — измерительный
полигон. Любой claim вида «нашли r=0.XX на этих шести» вторичен. Первичен
claim о законе, переносимом на произвольный пул атомов — формулируется в
терминах slot/block/donor/coverage/archive, без имён моделей.

**Честно зафиксировано перед §1**: таблица TRAIN PASS по 6 моделям × 4 рода
уже была видна на этапе разведки (нужна была, чтобы понять причину
tie-break в `agent_a5_live_m/BLOCKERS.md`). Ни одно число `N_A`/`N_AB`/
`P(B|A)`/`L`/`overlap` на момент написания этого протокола не посчитано —
только сырые PASS-счётчики по атомам, которые определяют геометрию
задачи (см. §1.3), а не исход эксперимента.

## §1. Определения (универсальные, без имён моделей)

### 1.1 Сигнатура слота
Для генотипа `g` и слота `s` (0=READ,1=FORMAT,2=LOOKUP,3=COMPUTE — позиция
в `ASSEMBLE.children`, фиксирована языком):

```
signature_s(g) = (op слота ∈ {SEQ, PAR}, sorted(model_id всех CALL внутри слота s))
```

Восстанавливается из `node_path` (`root/assemble[s]/...`) сохранённых
трасс — см. `agent_a5_live_m` forensic-находку: `n_children` на кадре
PAR/ASSEMBLE пишется ДО ленивого выхода, поэтому арность слота известна,
даже если вторая ветка ни разу не исполнилась.

### 1.2 Покрытие слота и Imp
`covered(s, model_id)` = множество task_id из панели, где `model_id`
проходит шов на роде `s` (прямой запрос к `live_grid`, живые данные A5,
не пересчитываются). Для SEQ(model) `covered(s,g) = covered(s,model)`. Для
PAR(m1..mk) `covered(s,g) = covered(s,m1) ∪ ... ∪ covered(s,mk)` — точно
для языка HETEROSTEP: PAR — ленивый OR по PASS, порядок веток не меняет
итоговое МНОЖЕСТВО решённых задач слота (только стоимость).

```
best_single(s) = max_m |covered(s, m)|      -- по панели
Imp(s, g) = 1  ⟺  |covered(s, g)| > best_single(s)
             0  иначе
```

`ImpSet(g) = {s : Imp(s,g)=1}`.

### 1.3 Геометрия полигона — факт измерения, не результат
Замер на живой сетке A5 (`agent_a5_live_m/metrics/live_grid/train_grid.json`,
панель = 80 из TRAIN, тот же состав, что использовал LA5):

- **FORMAT насыщен одним атомом** (одна модель уже даёт 100/100 на роде
  FORMAT) ⇒ `Imp(FORMAT)` структурно недостижим, `max |ImpSet| = 3` из 4.
- **READ имеет точную ничью первого порядка** между двумя моделями (98/98
  на TRAIN) и ничью второго порядка при выборе второй модели — 6 различных
  жадных маршрутов B1/B2/B3 (не 2, см. §5). Это свойство влияет на
  воспроизводимость затравки (см. Gate R), не на сам механизм.

Оба факта фиксируются здесь ДО подсчёта A/AB, чтобы при чтении отчёта было
ясно: «слот X никогда не даёт Imp» — это геометрия задачи, а не находка
про механизм.

### 1.4 A-событие и AB-генотип
**A-событие**: рождение (ребро `mutated_from`/`crossed_from`, направление
child→parent), где `ImpSet(child) ⊃ ImpSet(parent)` и
`|ImpSet(child)| = |ImpSet(parent)| + 1` — ровно один новый блок-слот.

**AB-генотип**: `|ImpSet(g)| ≥ 2` — совместное покрытие. НЕ требует
`r(g) ≥ r(B3)` и не привязан к конкретным моделям.

**Критическая оговорка (урок, повторявшийся 4 раза в этом проекте —
`agent_a5_live_m/BLOCKERS.md`, `handoff_snapshot/HANDOFF_CONTEXT.md` §9)**:
затравочная популяция (`build_seeds_pop20`, копия A4/A5) НАРОЧНО содержит
`P_par_*` затравки — генотипы с ≥2 слотами уже на уровне пары. Эти
затравки почти наверняка УЖЕ являются AB-генотипами по построению, не по
результату поиска. Поэтому:

- `N_A`, `N_AB`, `P(B|A)`, `L(A)`, `overlap` считаются ТОЛЬКО по
  эволюционно рождённым генотипам (`gen ≥ 1`, есть родитель через
  `mutated_from`/`crossed_from`);
- AB-статус затравочных генотипов (`gen = 0`) публикуется ОТДЕЛЬНО, как
  контекст, не смешивается со знаменателем/числителем механизма.

## §2. Порог корзины MECH_* (предрегистрирован, не двигается после чисел)

```
если N_A < 10 (суммарно по 5 seed, только evolved)      → MECH_UNKNOWN
иначе:
  если P(B|A) < 0.05  И  median L(A) ≥ 3                → MECH_RECOMB
  если P(B|A) ≥ 0.05  И  median L(A) < 3                → MECH_LIFETIME
  если N_AB ≥ 5  И  доля AB в элите < 0.2                → MECH_SELECT
  если сработали два условия одновременно                → MECH_MIXED
  иначе                                                    → MECH_UNKNOWN
                                                             (с указанием, какой порог не дотянут)
```

`P(B|A)` = доля A-событий, после которых у ТОЙ ЖЕ линии (потомки данного
child по `descendants()`) когда-либо появляется второй новый Imp-слот
(включая сам child, если он уже AB). `L(A)` = число поколений от рождения
до смерти (по `generations[].deaths`) либо до конца прогона (extinct/
last_gen), если линия дожила.

## §3. Reproduction Gate (перед тратой audit-усилий)

**R1 (мгновенно)**: из 6 вариантов tie-break `_greedy_order` (см. §5)
построить затравочную популяцию для каждого и сравнить `complex_id` трёх
эталонов с восстановленными из трасс архивного прогона (seed 20261201:
B1=`cx-7b8668`, B2=`cx-7ddd67`, B3=`cx-df47df`). Взять совпавший вариант.

**R2 (полный)**: инструментированный перепрогон всех 5 seed'ов A5
(20261201..05) на выбранном варианте; для каждого seed сравнить МНОЖЕСТВО
`complex_id` архива с именами файлов `agent_a5_live_m/runs/a5_live_s<seed>/
cx-*.jsonl` (ожидаемые размеры: 95/99/102/98/96 — совпадают с
`archive_size` в `agent_a5_live_m/metrics/per_seed_*.json`).

Прошло ⇒ субстрат audit доказанно тот же прогон, что дал LIVE_ROUTE_WINS.
Не прошло ⇒ запись в `BLOCKERS.md`, работа продолжается на
best-effort варианте с явной пометкой «пересобрано, не идентично» — Phase B
всё равно валиден, т.к. обе его руки (baseline и intervention) идут через
один и тот же харнесс.

## §4. Ветка Phase B (выбирается корзиной §2, ровно один рычаг)

| корзина | рычаг | точка вставки |
|---|---|---|
| MECH_RECOMB | `transfer_slot(donor,recipient,s)`: перенос целого слота, донор — по КОМПЛЕМЕНТАРНОМУ покрытию (`Imp(s,donor)=1 ∧ Imp(s,recipient)=0`), эталоны запрещены донорами, `p_slot_hgt=0.25` | `src/slot_hgt.py`, вызывается из `custom_reproduce` |
| MECH_LIFETIME | `PrecursorGrant`: линия с уникальным Imp-слотом, ещё не AB, получает K=3 поколения иммунитета к D1 + право быть донором вне Парето-фронта | переопределение `_d1_screen_deaths` |
| MECH_SELECT | `SynergyProxy`: `u_syn=|ImpSet(g)|` — независимая ось Парето (4-tuple), без свёртки в скаляр | переопределение `select_elite` |
| MECH_MIXED / MECH_UNKNOWN | новый evolve НЕ запускается; только более глубокий audit + список недостающих полей в логах | — |

Параметры Phase B (фиксированы, не сетка): pop=20 (состав как
`build_seeds_pop20`), max_gen=24, G_STALL=12, панель как в LA5 (80 задач,
тот же split), seeds **20261301..20261305** (новые, не пересекаются с LA5's
20261201..05), тот же live_grid (только чтение), эталоны никогда не
донорами.

## §5. Определение tie-break (устраняет находку 2 `agent_a5_live_m/BLOCKERS.md`)

`arch2/heterostep_seeds.py::_greedy_order` берёт `max(set(ds.models),
key=gain)` — при точной ничьей результат зависит от `PYTHONHASHSEED`
процесса. Замер на живой TRAIN-сетке A5:

- READ: первый выбор — ничья между двумя моделями (98/100 у каждой);
  второй выбор после каждой из двух — ещё ничьи (4-way после одной,
  2-way после другой) ⇒ **6 различных маршрутов** B2/B3-уровня, 2 —
  B1-уровня (только первый элемент).
- FORMAT/LOOKUP/COMPUTE: строгий максимум на каждом шаге, ничьих нет.

`src/deterministic_route.py` — копия `_greedy_order` с ЯВНЫМ детерминированным
тай-брейком (алфавитно по `model_id`, не через `set()`/`max()`), плюс
режим "форсированный вариант" (для Gate R1: перебор всех 6 вариантов без
полагания на хэш-порядок процесса).

## §6. Метрики успеха

Первичные: `Δ N_AB`, `Δ P(B|A)`, `Δ median L(A)`, `Δ overlap`, доля AB в
элите — Phase B vs Phase A baseline, ОБЕ руки посчитаны одним харнессом.
Вторичные, без claim: r на held-out против B1/B2/B3. Запрет формулировки
«достигли B3», если CI не исключает равенство.
