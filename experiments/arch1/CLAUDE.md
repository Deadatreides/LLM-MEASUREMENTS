# Проект: ARCH-1, реализация вертикального среза Мицелия

## Что это
Реализация по готовой спецификации в `../arch0/`. Спека authoritative —
её НЕ переобсуждаем, только реализуем.

## Жёсткие правила
1. Никаких LLM-судей. HARD-evidence только от детерминированных процедур.
2. Storage append-only: методов update/delete нет вообще.
3. Каждый модуль — со своими контрольными случаями (известный ответ).
   Модуль без прошедших контрольных случаев считается неготовым.
4. GRAPH CORE и STATE ENGINE не импортируют ничего про LLM.
5. Сырой вывод модели сохраняется ДО парсинга, всегда.

## Стек
Python 3.11, llama-cpp-python (GGUF, CUDA), без внешних зависимостей
сверх уже установленных. Никаких фреймворков.

## Где что
../arch0/          спецификация (НЕ читать целиком, только нужное)
./src/             код
./tests/           контрольные случаи
./STATUS.md        текущее состояние (читать в начале каждой сессии)

## Направление зависимостей (API_BOUNDARIES.md §1)

Строго однонаправленно сверху вниз, циклы между модулями запрещены:

```
уровень 6   API / ORCHESTRATOR
уровень 5   REPAIR PLANNER  │  ACTION EXECUTOR  │  BUDGET MANAGER
уровень 4   POLICY (заменяемая)   │   MODEL ADAPTER
уровень 3   SEAM ENGINE  │  EVIDENCE ENGINE
уровень 2   STATE ENGINE
уровень 1   GRAPH CORE
уровень 0   STORAGE (append-only)
```

Модуль уровня N может зависеть только от уровней < N. Обратные вызовы —
только через явные интерфейсы, передаваемые сверху (инверсия зависимостей).
Ни один модуль не импортирует конкретную реализацию LLM.

## Начало каждой сессии
```
1. /clear
2. Прочитать: arch1/CLAUDE.md + arch1/STATUS.md
3. Прочитать спеки ТОЛЬКО для текущего этапа (список в WORK_PLAN.md §3)
```

## Конец каждой сессии
```
1. Прогнать python run_checks.py, зафиксировать результат
2. Обновить STATUS.md
```
