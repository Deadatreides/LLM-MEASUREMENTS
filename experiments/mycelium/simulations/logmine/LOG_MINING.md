## Ж1. `c` — дополнительность. Порог не взят

`DEEP_ANALYSIS.md` §2: «Этот параметр измерим по уже имеющимся логам без
единого нового вызова. У тебя есть исход каждой модели на каждой из 200 задач
в пуле BoN».

**Поправка к заданию.** В пуле BoN этих исходов нет. Прогон `sh2_200` гонял
условие `BoN-G`, а оно по построению использует только `coder15`
(`lab/run_experiment.py:326`). Исходы остальных четырёх моделей лежат в другом
месте — в черновиках условия M. Отдельного поля «какая модель дала этот
кандидат» в записи нет, но `q_env_candidates` строится тем же фильтром и в том
же порядке, что и список G-вызовов (`run_experiment.py:361` и `:408`), поэтому
соответствие «модель ↔ исход» восстанавливается однозначно. Итого 424 попытки
слабых моделей и 3474 попытки лучшей на 199 задачах.

| оценка | что условие «лучшая провалилась» значит | c | 95 % ДИ | n |
|---|---|---|---|---|
| A | обе модели на одном шаге, лучшая провалила свою попытку | **0.0753** | [0.043, 0.130] | 146 |
| B | лучшая провалила **все** свои попытки на задаче, включая 8.4 генерации BoN-G | **0.0194** | [0.005, 0.068] | 103 |

Односторонний точный тест против `H₀: c ≥ 0.125` даёт p = 0.039 для оценки A и
p = 1.3·10⁻⁴ для оценки B.

**Вложенность подтверждается прямо, а не выводится из модели:**

```
P(слабая решает) безусловно          0.231   n=424
P(слабая решает | лучшая решила)     0.299   n=321
P(слабая решает | лучшая провалила)  0.019   n=103      отношение 0.065
```

Слабые модели решают в шестнадцать раз реже там, где лучшая не справилась. Это
не «слабее в среднем», это «решают строгое подмножество». Одномерная модель
силы из `DEEP_ANALYSIS` §1 не подгонка — она описывает пул.

Разбивка по моделям (решила при провале `coder15` на том же шаге): `smol17`
6/33 = 0.18, `qwen3` 3/37 = 0.08, `qwen05` 2/38 = 0.05, `smol360` 0/38 = 0.00.
Единственный кандидат в дополняющие — `smol17`, и его ДИ [0.086, 0.344] порог
накрывает. Это, если что-то и стоит проверять дальше, то только его.

Подстановка в модель `deep_complement.py` при фактической доле лучшей 0.402:

| c | потолок смеси | против 0.675 у BoN-G |
|---|---|---|
| 0.019 (оценка B) | 0.423 | проигрыш |
| 0.075 (оценка A) | 0.571 | проигрыш |
| 0.130 (верх ДИ оценки A) | 0.684 | выигрыш на грани |
| 0.185 (если бы независимо) | 0.772 | выигрыш |

При измеренном c оптимальная доля лучшей модели в смеси — **1.00**, то есть
оптимум смеси есть вырожденный «не смешивать». `σ_min = 0.2`, дающая 0.40,
не просто неоптимальна — она указывает в противоположную сторону от оптимума.

**Вывод по правилу принятия решения из `DEEP_ANALYSIS` §2:** `c < 0.125` →
на этом пуле оркестрация не окупится никаким исполнением. Вопрос закрыт
количественно, а не «вердиктом про этот пул». Оговорка про пул остаётся, но
теперь она конкретная: нужен пул, где `c > 0.125`, и это проверяемое свойство
состава, замеряемое за один прогон baseline до всякой оркестрации.

## Ж2. `f` — ложные приёмы. Порог превышен втрое, на обеих сторонах сравнения

`DECOMPOSITION.md` §4: «Что проверить в имеющихся логах: долю ложных приёмов
критика. Если она выше 0.11 — прошлый вердикт об оркестрации получен на
неработающей приёмке, и его надо переигрывать».

**Поправка к заданию.** Критик в Σ вердикта не выносит: `system_c` просит
текстовую критику (`orchestrator.py:530`), и его текст в записи не сохраняется.
Но приёмка в системе есть, и она в трёх других местах:

| | правило | код |
|---|---|---|
| F1 | BoN-G: `best = argmax q_ext` | `run_experiment.py:303` |
| F2 | M: `final_answer = s_ok[0]` — первый успешный синтезатор, **без отбора** | `orchestrator.py:577` |
| F3 | депт-луп: принять если `h_new ≤ h_old+ε` **или** `q_cand ≥ q_cur` | `orchestrator.py:1097` |

`q_ext` — статическая эвристика (`core/scorer.py::_q_code`): парсится ли AST,
есть ли `def`, есть ли `assert`, длина текста. Исполнения в ней нет.

**F1 — приёмка BoN-G.** Хотя бы один проходящий кандидат есть в 135 задачах из
199. Выбранный по `q_ext` не проходит в 31 из них.

```
f1 = 0.230  [0.167, 0.308]                  порог 0.11
взято 52.3 %   потолок отбора 67.8 %   потеряно 15.5 п.п.
случайный кандидат дал бы 46.9 %, argmax q_ext даёт 52.3 %
```

Эвристика лучше монетки на 5.4 п.п. и хуже идеального отбора на 15.5. Строго
не лучший по исполнению кандидат выбирается в 35.7 % задач.

**F2 — приёмка M.** Хотя бы один черновик прошёл тесты на 87 шагах. Итог не
проходит на 32 из них.

```
f2 = 0.368  [0.274, 0.473]                  порог 0.11
потеряно 32 готовых решения, спасено 3      чистый итог -29 задач = -14.5 п.п.
во что превратился потерянный ответ: ratio<=0.5 - 20, syntax/import_error - 8, partial - 4
```

Восемь раз из тридцати двух синтез превратил проходящее решение в код, который
не импортируется.

**Самое существенное, что видно только из логов.** Внешний результат каждого
кандидата на шаге **уже был вычислен** — `per_agent_reward` гоняет `q_env_fine`
по каждому черновику (`orchestrator.py:512`), `critic_loo` — по каждому
пересинтезу (`:1148`). Система исполнила тесты на всём, что произвела, положила
результат в награду бандита и **выбросила его при выборе ответа**: берётся
`s_ok[0]`, первый ответивший синтезатор.

Оракул по всему, что M произвела на шаге (2 черновика + до 4 синтезов + итог):

```
94/200 = 47.0 % могло быть отдано      58/200 = 29.0 % отдано фактически
разрыв приёмки = 18.0 п.п.             разрыв M против BoN-G = 23.0 п.п.
```

**F3 — депт-луп.** Единственное место, где приёмка работает: сломал
проходивший ответ 2 раза, починил 2 раза, `f3 = 0.071` [0.020, 0.227]. Порог
не превышен, но и делать депт-луп почти нечего — см. Ж11.

**Критики, замер по LOO.** `critic LOO` отработал на всех 200 шагах, 400 оценок
вида `r = 0.5 + (q_с_критикой − q_без_критики)`:

```
помогла 77    помешала 75    не изменила 248    медиана ровно 0.5000
```

Критика — симметричная монетка, а в 62 % случаев не меняет вообще ничего.
Не «плохой критик» — **никакой**.

**Что это значит для вердикта `RESULTS.md`.** Правило `DECOMPOSITION` §4
сработало: `f > 0.11` на обеих сторонах, значит замер надо переигрывать. Но
контрфактика считается прямо сейчас и знак не меняет:

| | как было | с идеальной приёмкой |
|---|---|---|
| M | 29.0 % | 47.0 % |
| BoN-G | 52.3 % | 67.8 % |
| разрыв | −23.0 п.п. | **−20.8 п.п.** |

Починка приёмки даёт M больше, чем BoN-G (+18.0 против +15.5), но отставание
сохраняется. **Вердикт `RESULTS.md` устоял, его величина завышена примерно на
2 п.п.** При этом починка приёмки — самая дешёвая правка из всех найденных за
две серии: +18 п.п. solved без единого дополнительного вызова модели, потому
что нужное число уже посчитано и лежит в том же шаге.

## Ж3. Ставка мутации: гипотеза `DIAGNOSE_HYPERCYCLE` опровергнута

Задание §4.1: «убедиться, что в прогоне на 200 задачах ставка мутации
действительно была 0.005 — по логам или по конфигу прогона, не по
`settings.yaml`».

Ставка не угадывалась по равновесию, а восстановлена точно. В записи каждого
шага есть `hypercycle_x_before`, `hypercycle_x_after`, `hypercycle_k` и
`lambda_L`, а обновление детерминировано (`core/hypercycle.py::update`), так
что неизвестный один и уравнение решается:

```
найденная ставка = 0.00500      RMS невязки = 0.0e+00 на 200 шагах
невязка при 0.03                = 2.19e-04
```

Ставка была 0.005. **Объяснение «мутация 0.03 воспроизводит измеренные 0.0174
с точностью до третьего знака» — совпадение.** Две разные комбинации
(контраст 1.42 + мутация 0.03) и (контраст 1.274 + мутация 0.005) дают
практически одно равновесие, и отчёт выбрал первую.

Прогон настоящей формулы до равновесия при измеренном `k` и ставке 0.005 даёт
`max|x−1/3| = 0.0199`; в логе финальное значение 0.0174 и оно ещё росло
(медиана по прогону 0.0111). Расхождения нет: прогон не дошёл до своего
равновесия сотню шагов.

## Ж4. Каст-контраст: 1.274, требуется 2.1

Задание §4.2: «Пересчитать каст-контраст по логам (`recompute_hypercycle.py`)».
Скрипт ожидал `mu_role`; в записях лежит прямо `hypercycle_k` — то, что
гиперцикл видит на самом деле, брать оценку через `mu_role` не нужно.

```
G: среднее 0.5205  ст.откл 0.0090        C: 0.4087  0.0159        S: 0.5097  0.0235
КАСТ-КОНТРАСТ = 1.274 (по финалу 1.254)   в отчётах фигурировало 1.42
```

1.42 — это спред baseline **моделей**. Гиперцикл его не видит: `k` касты — это
EMA от среднего `q_ext` касты за шаг (`orchestrator.py:754-758`), то есть
контраст **статической эвристики между кастами**, а не силы моделей. Величины
разные и совпадать не обязаны.

**Требуемый контраст в отчёте занижен.** `SIM_REPORT_2` §4 даёт минимум
1.59–1.62, но его ОДУ использовала шаг `a = 0.05`, а в коде
`hypercycle.alpha = 0.0207` (`config/settings.yaml`). Равновесие определяется
отношением скорости отбора (∝ alpha) к ставке мутации, поэтому число из отчёта
к этому коду не относится. Прогон настоящей формулы:

| контраст | равновесие при a=0.05 | равновесие при a=0.0207 (код) |
|---|---|---|
| 1.274 (измеренный) | 0.0346 | **0.0196** |
| 1.42 | 0.0556 | 0.0311 |
| 1.62 | **0.0854** ✓ | 0.0471 |
| 2.0 | 0.1469 | 0.0792 |
| 2.1 | 0.1637 | **0.0880** ✓ |

Порог квантователя 0.0833. При a=0.05 он берётся с контраста 1.62 — число
`SIM_REPORT_2` воспроизводится, реализация проверена. При настоящей alpha
нужен контраст **2.1**. Измерено 1.274.

**Дефицит 65 %, а не 14 %.** Вывод `SIM_REPORT_2` §5.4 («гиперцикл стоит одной
попытки, разрыв 14 % закрывается сменой состава пула») на этих числах не
держится: разрыв закрывается либо ростом `alpha` в 2.4 раза, либо контрастом
вдвое, либо вычитанием пола 0.25 из `k` (тогда контраст 1.70 — но всё ещё не
2.1). Дешёвая правка тут одна — `alpha`, и она ничего не стоит проверить.

Побочно, из тех же логов:

* раскладка каст за все 200 шагов: `G=2 C=2 S=2`, ни одного изменения;
* квантователь с накоплением остатков за 200 раундов сдвинул бы
  **G +9, C −13, S +3** слотов — работает, но эффект в пределах шума;
* раундов до 2σ от мультиномиального шума при наблюдаемом отклонении:
  **1349** (прогноз `DIAGNOSE_HYPERCYCLE` был 55 — он строился на контрасте
  1.42 и мутации 0.005);
* шум `k` по шагам 0.0162 при разрыве каст 0.1118, сигнал/шум 6.9 —
  заострение `β = 2` проходит по шуму (потолок 0.0198), `β = 3` не проходит.

## Ж6. Чистота сигнала: стенд чист, вырождена шкала

`SUMMARY` п.6: «Борьба со срывами тестов важнее расширения шкалы качества».
Значение `q_env` однозначно кодирует исход песочницы
(`core/scorer.py:300-331`), поэтому статус каждого из 3067 замеров прогона
восстановим из числа, ничего не исполняя:

| статус | замеров | доля |
|---|---|---|
| все тесты прошли (1.0) | 1270 | 41.4 % |
| `ratio ≤ 0.5` — схлопнуто в 0.4 | 1246 | **40.6 %** |
| не импортировался (0.2) | 372 | 12.1 % |
| частично > 0.5 | 165 | 5.4 % |
| **тесты не собрались (0.5)** | **9** | **0.29 %** |
| таймаут (0.1) | 5 | 0.16 % |

**Срывов стенда 0.29 %** — то есть пункт «бороться со срывами тестов» на этих
логах закрыт: бороться не с чем. Настоящая потеря информации в другом месте:
40.6 % замеров попадают в одну точку 0.4, где неразличимы «0 тестов из 4» и
«2 из 4».

По тонкой шкале (`q_env_fine`, та, что идёт в награду) из `runtime.log`:

```
шагов, где сигнал одинаков у ВСЕХ черновиков: 116/200 = 58.0 %
из них честная ничья (оба решили всё):         38
вырожденных:                                   78 = 39.0 % шагов
    оба прошли 0 тестов        65
    оба прошли 1/3 или 2/3      9
    оба не собрались            4
```

Даже тонкая шкала не спасает: 39 % шагов пер-агентная награда не различает
черновиков, и не потому, что шкала грубая, а потому что **оба черновика
одинаково провалились**. Это свойство пула, а не метрики.

Сорванные вызовы в прогоне: `Transient server error` 108 раз, из них 56 на
`bon_coder15` — то есть у BoN-G часть из 8.4 кандидатов была пустой. Фатальные
`Missing API key` (147 штук) относятся к прогону 2026-08-09, в `sh2_200` их нет.

## Ж7. `entropy_threshold`: подтверждено, порог должен быть 0.767

```
H_norm по 1025 блокам: медиана 0.8836, минимум 0.7155, максимум 1.0000
depth.entropy_threshold = 0.08 → ниже него 0 блоков из 1025
квантили: 0.01→0.7216  0.05→0.7236  0.10→0.7666  0.25→0.8375
```

Чтобы порог отсекал нижние 10 % шагов, он должен быть **0.767**. Сейчас депт-луп
запускается всегда.

Попутно найдено то, чего в отчётах не было: **PPR сошёлся в 436 блоках из 1025

AST не разобрался и структура бралась по абзацам.

> В первой редакции здесь стояло «вся термодинамика Пригожина посчитана по
> недосошедшемуся вектору PageRank». **Формулировка снята: замер её не
> подтвердил, см. Ж12.** «Не сошёлся» ничего не говорит о том, на сколько.

## Ж12. PPR: не дефект данных, а рассогласование tol и max_iter

Проверено тремя независимыми способами (`m7_ppr.py`).

**Теория.** Степенная итерация `π_{k+1} = α·Pᵀπ_k + (1−α)v` сходится как `α^k`.
При `α = 0.85` и `tol = 1e-8` нужно `ln(tol)/ln(α) = 113.3` итерации. В
`core/ppr.py` `DEFAULT_MAX_ITER = 100`. **Лимит не дотягивает до собственного
порога на 13 итераций** — при любом графе, всегда. Свойства данных тут ни при
чём: 1891 предупреждение выписано арифметикой, а не патологией.

**Невязки из самого лога.** Медиана 2.1·10⁻⁸, максимум 1.08·10⁻⁷ при пороге
1·10⁻⁸. Отсюда расстояние до истинной точки
`‖π_k − π*‖₁ ≤ residual·α/(1−α) ≤ 6.1·10⁻⁷` — в 10⁵ раз меньше собственного
масштаба `π` (1/13 при медианных 13 узлах).

**Прямой пересчёт.** 1377 блоков восстановлены из сохранённых текстов прогона
(черновики, синтезы, итоги), тот же `BlockGraph`, тот же `α`, лимит снят:

```
не сошлись при лимите 100:        780 = 56.6 %   (в прогоне было 57.5 %)
|H(лимит 100) − H(сошёлся)|:      макс 2.7e-08,  медиана 8.7e-10
|H_norm(100) − H_norm(сошёлся)|:  макс 1.5e-08,  медиана 3.2e-10
```

**Сопоставление масштабов.** Самый малый ненулевой `|ΔH|` прогона — 0.0008,
то есть в 5.2·10⁴ раз больше самой большой ошибки от лимита. Из 43 шагов с
ненулевым `ΔH` нет ни одного, где `|d_eS|` и `d_iS` расходились бы меньше, чем
на удвоенную ошибку: **гейт `alive` не мог перевернуться ни разу.**

**Вывод.** Величина ошибки — 10⁻⁸, на 4–5 порядков ниже самой мелкой величины,
которую термодинамика различает. Правка нужна, но косметическая:
`DEFAULT_MAX_ITER` 100 → 150. Смысл правки не в точности, а в том, что 1891
ложное предупреждение маскирует настоящие.

Остальные 157 шагов из 200 вырождены **не** из-за PPR, а из-за каузального
порядка: `ΔH ≡ 0`, потому что депт-луп кладёт `final_answer` в блок до замера
`H_old` (это и есть `depth.thermo_causal_fix`, включённый только в условии
`M-fixed`). Настоящие дефекты термодинамики — этот и тот, что `H` есть
статистика **одного** текста, а не распределения по кандидатам (`HANDOFF` §5.1).
Оба уже описаны, и ни один из них не про сходимость.

## Ж8. Частота крупных приростов: 3.5 %, локализация кредита дёшева

`SIM_REPORT_3` §5 и `SIM_REPORT_4` §5.4: перед тем как строить пробу с
дорезанием кредита до одного узла, надо померить, как часто вообще случаются
события крупного прироста — проба стоит ~7 лишних проходов на событие.

**Оговорка, которую надо держать явной.** Лестница расширения контекста в
Мицелии не запускалась ни разу, поэтому «прирост при расширении контекста» по
этим логам не измерим в принципе. Измерим ближайший аналог — прирост от
ступеней оркестрации:

| событие | частота |
|---|---|
| синтез дал ≥ +0.30 к лучшему черновику | 7/200 = 3.5 % |
| первый синтез (тот, что берётся) ≥ +0.30 | 3/200 = 1.5 % |
| итог решил там, где черновики не смогли | 3/200 = 1.5 % |
| депт-луп дал ≥ +0.30 | 2/200 = 1.0 % |

При 3.5 % событий проба в 7 вызовов стоит **0.25 вызова на задачу** — плюс
2.7 % к нынешним 9.2 вызовам на шаг. Ценовое возражение `SIM_REPORT_3` §5
(«на реальных моделях каждый проход — вызов LLM») снимается: на этой частоте
событий локализация кредита практически бесплатна.

## Ж11. Пять пунктов авторского критерия, которые «ни разу не мерились»

`VISION.md` §7 перечисляет, что отбросила редукция к `E_score > 0`, и даёт
измеримые прокси. Три из пяти считаются по этим логам.

### «I(t) растёт» — падает, и причина не та, что записана

```
I[0] = 0.499 → I[-1] = 0.375       наклон МНК -6.2e-04 за шаг
delta_I на шаге: отрицательных 200 из 200
```

`VISION` §7 объясняет падение тем, что «`max(0, E_total)` был всегда 0 из-за
ошибки в единицах бюджета». Бюджет починен (`R3`), и `E_total > 0` теперь в
76 шагах из 200 — а `I` всё равно падает монотонно. Настоящая причина
арифметическая:

```
I(t+1) = 0.9985·I + 0.0015·max(0, E_base)        core/memory.py::LeakyIntegrator
неподвижная точка = mean(max(0, E_base)) = 0.01803
старт 0.5, постоянная времени 667 шагов
предсказание модели: I[-1] = 0.375077     в логе 0.375000
```

Совпадение до пятого знака. Падение `I` — не дефект, а релаксация от
завышенного стартового значения 0.5 к точке, которую задаёт `E_base`. Чтобы
`I` росла, нужно `mean(max(0, E_base)) > 0.5`; сейчас 0.018. **Критерий «`I(t)`
растёт» на 200 шагах неизмерим в принципе** — при τ = 667 шагов прогон не
успевает выйти даже на четверть пути, и любой замер на такой длине показывает
только начальное условие.

### «специализация в ниши» — не возникает

Энтропия распределения выбора агентов по окнам в 50 шагов: 1.771 → 1.759 →
1.764 → 1.777 при максимуме 1.792. Ровно 98.8 % от максимума, тренда нет.
Живы все 6 агентов из 6.

Оговорка: прокси `VISION` — энтропия по **типам задач**, а в корпусе тип один
(`code`). Измерено то, что можно, — общая концентрация выбора; ниш здесь нет
по построению корпуса, а не потому что механизм не сработал.

### «растёт глубина» — переписывается обрамление

```
принятых шагов депт-лупа: среднее 1.22   (1 шаг - 157 раз, 2 шага - 43)
ответ изменился: 104/200 = 52.0 %, по окнам 50 % → 48 % → 52 % → 58 %
из 104 изменённых внешний результат не изменился у 79 = 76.0 %
```

Три четверти правок депт-лупа не трогают исполняемое поведение кода.

### Главная метрика `VISION` §9.4 — ноль

> «доля задач, решённых только композицией и никогда ни одним компонентом
> в одиночку»

| исход | задач |
|---|---|
| итог неверен | 142 (71.0 %) |
| итог верен, но черновик и так был верен | 55 (27.5 %) |
| композиция дала то, чего не дали её собственные черновики | 3 (1.5 %) |
| **композиция дала то, чего не дали ни черновики, ни 8.4 сэмпла лучшей модели** | **0 (0.00 %)** |

Зеркальная величина: задач, где композиция **потеряла** уже готовое решение —
32 из 200 = 16.0 %. Отношение потерь к приобретениям **32 : 1**.

`VISION` §9.4 формулирует правило чтения заранее: «Пусто — система не добавляет
ничего, как бы её ни называть». Строгая метрика пуста. Мягкая версия (без
условия про сэмплы BoN) даёт 1.5 % против 16.0 % потерь.

### Чего по этим логам посчитать нельзя

* **«граф предсказывает пути»** (`VISION` §7 п.3): в записи шага нет ни списка
  извлечённых трасс, ни их релевантности. Нужна инструментовка `memory.search`
  — одно поле в записи, но прогон новый.
* **`alpha_pos`** (`TASK_ALPHA_POS.md`): свойство модели, требует 2700 вызовов,
  из логов не выводится ни в каком виде.
* **частота прироста при расширении контекста**: лестницы расширения контекста
  в Мицелии не существует.

## Что из этого следует

Ранжировано по отношению «изменение вывода / цена».

1. **Приёмка по исполнению — сделать и переиграть замер.** Единственная правка,
   которая даёт +18 п.п. solved на M и +15.5 на BoN-G, не стоит ни одного
   дополнительного вызова: результат исполнения каждого кандидата уже
   вычисляется на шаге и выбрасывается. `orchestrator.py:577` заменить на выбор
   по `q_env_fine` среди `s_ok + g_ok`. После этого весь прошлый замер надо
   переигрывать — так предписывает `DECOMPOSITION` §4, и на этот раз предписание
   сработало по факту, а не гипотетически.
   *Оговорка, которую нельзя терять:* в лаборатории эталонные тесты есть, в
   продакшене их нет. Правка честна для замера и требует настоящего
   проверяющего для работы. Порог из `DECOMPOSITION` §2 — доля ложных приёмов
   ниже 0.10 — становится требованием к этому проверяющему.

2. **Пул: `c` измерено, порог не взят.** Не тратить время на механизмы, пока
   состав пула тот же. Критерий пригодности нового состава замеряется до
   оркестрации: `c > 0.125` на baseline-прогоне. Из нынешних пяти моделей
   отбор различает две; `smol17` — единственный кандидат в дополняющие
   (0.18 [0.086, 0.344]).

3. **Гиперцикл: сначала `alpha`, потом состав.** Требуемый контраст 2.1, а не
   1.62; измеренный 1.274. Поднять `hypercycle.alpha` с 0.0207 до 0.05 —
   одна строка, и это ровно та точка, где отчётная симуляция расходится с
   кодом. Квантователь с остатками ставить в любом случае (одна строка,
   эффект +9/−13/+3 слота за 200 раундов).

4. **`entropy_threshold` = 0.767** вместо 0.08. PPR при этом не трогать по
   существу — ошибка от лимита 10⁻⁸ (Ж12); поднять `DEFAULT_MAX_ITER` до 150
   только чтобы 1891 ложное предупреждение не маскировало настоящие.

5. **Локализация кредита дёшева** — 3.5 % событий, +2.7 % вызовов. Ценовое
   возражение снято, `probe_min=1` можно ставить.

6. **`I(t)` как критерий требует другого прогона.** τ = 667 шагов; на 200
   измеряется начальное условие. Либо стартовать `I` с 0, либо мерить не
   раньше 2000 шагов, либо признать критерий неприменимым к этой длине.

## Границы вывода

* Всё считано с одного прогона `sh2_200` (200 задач MBPP, GGUF-пул из 5
  моделей) плюс 172 шага более ранних прогонов для оценки `c`. Прогоны 1–3
  делались на другом состоянии кода; для `c` они объединены сознательно —
  состав пула и определение `q_env` в них те же, а объединение нужно для
  мощности. Оценка A на одном `sh2_200` даёт 0.093 [0.046, 0.180] при n=75 —
  тот же порядок и тот же вывод, но порог 0.125 её ДИ накрывает. Именно
  поэтому прогоны объединены: без объединения оценка A порог не отвергает.
  Оценка B на одном `sh2_200` даёт 0/59 = 0.000 [0, 0.061], p = 3.8·10⁻⁴ —
  без объединения она решающая сама по себе.
* Контрфактика «идеальная приёмка» — это оракул, а не достижимая величина.
  Она отвечает на вопрос «сколько теряет отсутствие приёмки», а не «сколько
  даст конкретный проверяющий».

  `run_experiment.py` строятся одним фильтром. Проверено на 372 записях:
  расхождений длин ноль. Если фильтр когда-то менялся, старые прогоны надо
  перепроверять отдельно.
* Все p-значения — точные биномиальные, доверительные интервалы — Уилсона.
  Множественность не корректировалась: здесь проверяются заранее объявленные
  в отчётах пороги, а не отбираются гипотезы.
