## [8.9] — 2026-05 (текущая)

### Изменено

**`core/blackboard.py` — PPR-энтропия на структурном графе G_B (замена cosine-proxy)**

- **Было**: `H = softmax(cosine_sims)` — метрика разброса в пространстве вложений. Не является энтропией в информационном смысле: значения не аддитивны, не связаны со структурой блока.
- **Стало**: `H(r) = -Σ p_i·log(p_i)` где `p = PPR(G_B, v(task), α=0.85)`. Строгая Shannon entropy от Personalized PageRank на структурном графе блока.
- **Физика**: Задание 14 (ТЗ). Разделение G_B (локальный граф блока) и G_M (глобальный Physarum-граф памяти).
- **Класс `BlockGraph`**: детерминированное построение графа из текста. Для кода: AST-узлы (FunctionDef, ClassDef, Call, Import, ...) + рёбра parent→child + call→def. Для текста: предложения + sequential + Jaccard-overlap.
- **Personalization vector `v`**: `v_i = softmax(Jaccard(node_i, task) / τ_v)`. Fallback на равномерный при отсутствии совпадений.
- **PPR**: power iteration `p = (1-α)v + α·Tᵀ·p`. Dangling nodes → self-loop. Гарантии: `p_i ≥ 0`, `Σp_i = 1`.

**`core/blackboard.py` — Термодинамика Пригожина**

- Добавлен `compute_thermodynamics()` со строгим каузальным порядком: H_old фиксируется ДО upsert, H_new считается ПОСЛЕ.
- `d_eS = -ρ_r·ΔH·Q_env` (≤ 0, внешний поток негэнтропии).
- `d_iS = L_r·(π_r - π̄)²` (≥ 0, внутреннее производство).
- `Φ = |d_eS| - d_iS` (критерий жизни: Φ > 0).
- `ThermodynamicState` — dataclass с полями H_old, H_new, delta_H, pi_r, d_eS, d_iS, Phi, alive.
- Репликатор-диффузия: `ρ̇_r = ρ_r·(π_r - π̄) + D·(ρ̄ - ρ_r)`.
- `system_entropy()`: `S = -Σρ·log(ρ) + Σρ·H(r)`.

**`orchestrator.py` — Интеграция термодинамики в каузальный цикл**

- Вызов `compute_thermodynamics()` теперь происходит ДО `memory.add()` и ПОСЛЕ получения `q_env`.
- Удалён аргумент embedding из `blackboard.upsert()` и `block.add_version()` — граф строится только из текста.
- `_update_agent_energy()` принимает `delta_H` и `q_env`: `r_ext_combined = r_ext + η·max(0,ΔH)·Q_env` (ТЗ §5).
- Поле `'thermo'` добавлено в возвращаемый результат `run_step()`.

**`config/settings.yaml` — Новые параметры**

- `blackboard.ppr_alpha: 0.85` — параметр PPR.
- `blackboard.replicator_diffusion: 0.05` — коэффициент диффузии.
- `blackboard.tau_v: 1.0` — температура personalization vector.
- `energy.eta_thermo: 0.30` — вес термодинамического вклада в энергию агентов.

### Сохранено без изменений

- `main.py`, `core/bandit.py`, `core/chaos.py`, `core/hypercycle.py`, `core/memory.py`, `core/scorer.py`, `agents/trainer.py` — не тронуты.
- Depth loop: сохранён, теперь работает на PPR-энтропии через `block.entropy` (псевдоним `block.H`).
- `entropy_from_embeddings()` — помечена deprecated, сохранена для обратной совместимости тестов.

### Математическая строгость

## [8.8.1] — 2026-05 (текущая)

### Исправлено

**`core/blackboard.py` — Shannon entropy вместо метрики разброса**

- **Было**: `H = 1 − mean(cosine_similarity)` — это метрика разброса, не энтропия. Значения не нормированы как вероятность, не аддитивны. Depth loop «слепо» оптимизировал неправильный сигнал.
- **Стало**: Информационная энтропия Шеннона через softmax: `p_k = softmax(4·s_k)`, `H = −∑p_k·log(p_k) / log(n_pairs)`. Результат строго ∈ [0,1], аддитивен, интерпретируем.
- **Причина**: GPT и Meta в рецензиях указали на то, что система не может корректно сравнивать блоки и принимать решения об итерациях при некорректной метрике.

**`orchestrator.py` — Depth loop привязан к глобальному E_total**

- **Было**: Цикл останавливался только по локальной энтропии блока. Мог «полировать» бесполезный блок пока глобальная эмерджентность падала.
- **Стало**: Двойной критерий остановки: `|ΔH| < ε_local` ИЛИ `E_total_approx < E_total_ref − ε_global`. При глобальном регрессе — `GLOBAL STOP` в логах и немедленный выход.
- **Причина**: GPT указал на нарушение принципа оптимальности Беллмана — каждый шаг глубины должен улучшать глобальную ценность, а не только локальную метрику.

**`core/blackboard.py` — Нижняя граница температуры**

- **Было**: `temp = max(self.temperature(lambda_L), 1e-6)` — при низкой температуре все ресурсы уходили в один блок, разрушая exploration.
- **Стало**: `temp = max(self.temperature(lambda_L), self.temp_min)` где `temp_min = 0.25` из конфига.
- **Причина**: При `temp < 0.1` softmax вырождается в argmax → система «залипает» в одном блоке и перестаёт исследовать другие.

**`orchestrator.py` — Добавлен метод `_split_into_blocks()`**

- **Было**: Метод отсутствовал. Grok указал что depth loop работал без явного разбиения на семантические единицы.
- **Стало**: AST-разбиение для кода (по `FunctionDef`/`ClassDef`), параграфное разбиение для текста, fallback по предложениям. Минимальный блок 50 символов.
- **Причина**: Без чёткого разбиения blackboard работал с монолитными ответами, что снижало точность энтропийной оценки.

**`orchestrator.py` — Исправлен комментарий `_compute_r_ext`**

- **Было**: Комментарий утверждал "сумма весов = 1.0". Фактически: `0.4 + 0.125 + 0.35 = 0.875`.
- **Стало**: Явно указано что R_ext ∈ [0.125, 0.875], это не вероятностное распределение.
- **Причина**: Некорректный комментарий вводил в заблуждение при настройке системы (Gemini).

**`core/hypercycle.py` — Добавлен класс `NoveltySignal`**

- **Было**: Класс был в спецификации v8.5 но не попал в базовый код v8.7.
- **Стало**: `NoveltySignal.compute()` через L2-расстояние до ближайшего соседа в FAISS. `r_ext()` возвращает энергетический бонус.

## [8.7.1] — 2026-04

### Исправлено

**`orchestrator.py` — `delta_I` всегда = 0 (P0)**

- **Было**: `delta_I = self.memory.I - self._prev_I` вычислялся ДО `memory.add()`. Поскольку `memory.add()` обновляет `I(t)`, разность всегда равнялась нулю. Пятое слагаемое E_total не работало.
- **Стало**: Двухэтапный паттерн: `I_before = self.memory.I` → `memory.add(e_total=e_base)` → `delta_I = self.memory.I - I_before` → `apply_delta_i()` → `update_trace_e_total(trace_id, e_total_final)`.
- **Причина**: Критический каузальный баг. Все консолидированные рецензии (GPT, Grok, Meta, Gemini) указали на него.

**`core/chaos.py` — Утечка памяти в `ChaosController.history` (P0)**

- **Было**: `self.history = {'lambda': [], 'k_act': [], 'energy': []}` — списки росли без ограничений. При работе 48+ часов потребление RAM достигало нескольких GB.
- **Стало**: `deque(maxlen=1000)` — хранит последние 1000 шагов ≈ 1.7 часа.
- **Причина**: Очевидная утечка при любом длительном запуске.

**`core/scorer.py` — Отсутствие sandbox для кода (P1)**

- **Было**: Код LLM выполнялся напрямую через `subprocess.run(['python', ...])` на хосте без каких-либо ограничений.
- **Стало**: `_q_code_safe()`: `TemporaryDirectory` + `resource.setrlimit` (256MB RAM, 5s CPU на Linux), timeout=5s, градуированная оценка 1.0/0.7/0.4/0.2/0.1/0.0.
- **Причина**: RCE-уязвимость. LLM может генерировать код с побочными эффектами.

**`orchestrator.py` — R_ext не включал `q_env` (P1)**

- **Было**: Вес `q_env` в формуле R_ext был 0.25. Качество исполнения кода слабо влияло на энергетику агентов.
- **Стало**: `_compute_r_ext(novelty, q_env)` с весом `q_env = 0.35`.
- **Причина**: Агенты, генерирующие нерабочий код, не получали достаточного штрафа.

**`main.py` — JSON парсинг ломался на multiline (P2)**

- **Было**: `for line in sys.stdin: data = json.loads(line)` — падало на любом многострочном JSON.
- **Стало**: `json.JSONDecoder().raw_decode()` + fallback на JSON Lines.

**`core/hypercycle.py` — Нестабильный `hc_bonus`**

- **Было**: `hc_bonus = bonus * x_prev / x_mean`. При `x_prev = 0.87`: `0.11 * 0.87/0.33 = 0.287`, что равно стоимости 287 токенов → нейтральный эффект, нет стимула.
- **Стало**: `hc_bonus = bonus * (x_prev - 1/3) * 3`. Поощряет рост доли касты, штрафует за сжатие.

## [8.5] — 2026-02

### Исправлено

**E_score всегда = 0 (критический баг с v6.6)**

- **Было**: `E_score = r_ens - r_base` где `r_base = Q(выбранная модель)`. Роутер выбирает лучшую модель → `r_base ≥ r_ens` всегда → `E_score ≤ 0` всегда.
- **Стало**: `E_score = Q(Y_syn) - max_i Q(Y_i)`. Истинное сравнение синтеза с лучшим одиночкой.

**Thompson precision 4 → 16**

- **Было**: `precision_obs = 4` предполагало `σ_obs = 0.5`. Реальный шум API reward ≈ 0.25.
- **Стало**: `precision_obs = 16` (= 1/0.25²). Система корректно усваивает опыт.

**Exp3 переназначен как drift detector**

- **Было**: Exp3-IX и Thompson Sampling оба выбирали модели. Фундаментальное противоречие: Thompson предполагает стационарную среду, Exp3 — адверсариальную.
- **Стало**: Thompson выбирает. Exp3 мониторит расхождение `|μ_Thompson - ŵ_Exp3| > 0.15` → сброс уверенности.

### Добавлено

- Physarum граф памяти (заменил простой FAISS без структуры)
- PPR (Personalized PageRank) re-ranking результатов поиска
- Гибридный эмбеддер BGE-m3 + E5-small (1408d)
- Leaky Integrator I(t) с устойчивым аттрактором
- Конфигурационные файлы settings.yaml / models.yaml

## [6.6] — 2026-01 (первый публичный прототип)

### Известные баги при выпуске

Все перечисленные баги зафиксированы рецензиями GPT, Grok, DeepSeek, Gemini, Meta.

| Компонент | Баг |
|-----------|-----|
| E_score | Всегда ≤ 0 (r_ens - r_base) |
| TI-формула | Undefined переменные ρ̄ и H_s |
| Thompson precision | 4 вместо 16 |
| Exp3 + Thompson | Конфликт двух selector-алгоритмов |
| dI/dt | Нет затухающего члена -λI → интегратор без аттрактора |
| LinUCB | O(d³) инверсия матрицы вместо Sherman-Morrison |
| H(π) как diversity | Энтропия роутера ≠ семантическое разнообразие ответов |

### Архитектурная основа (сохранена во всех версиях)

- Multi-provider async API с Thompson Sampling
- Три касты (G/C/S) как концепция
- Ночной DPO цикл
