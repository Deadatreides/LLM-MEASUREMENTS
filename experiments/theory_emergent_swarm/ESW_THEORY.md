# ESW: эмерджентный рой через консенсус по полям совместного ответа

Синтез 15 пакетов (A2–A5, LIFE-1..9, DELTA-0, FORK-1). Не пакет-кампания —
теоретический документ + один уже проведённый нулевой по стоимости замер.

**СТАТУС (обновлено 2026-08-26, после LB2)**: на **LongBench v2
Multi-Doc QA / hard** (реальный бенчмарк, контекст физически не влезает в
окно) **ни один арм не превзошёл случайное угадывание**: TRUNC 0.182,
SOLO 0.182, SWARM 0.250 при базе 0.250. **Эйген-консенсус опровергнут**:
Spearman −0.600/−0.314 — спектральная оценка **инвертируется**, когда пул
делит форматное смещение (gemma A×40/44, llama B×35/44) и сидит на уровне
монеты. Главный вывод, ограничивающий всю линию: **агрегация усиливает
сигнал; на уровне случайности усиливать нечего**. Диапазон применимости
пула — не «слабые модели вообще», а **«слабые, но уже работающие»**
(GSM8K: 0.37–0.67 → рой помогает; LB2: 0.16–0.30 → не помогает). См. §9.11.

## 0. Утверждение в одном абзаце

Пятнадцать пакетов оптимизировали **маршрутизацию внутри факторизации,
которая сама неверна**. Шаговая сетка (изолированный вызов на шаг)
разрушает взаимное ограничение между шагами и потому не является
гомоморфизмом в способность решить задачу. Правильный объект — **поля
СОВМЕСТНОГО ответа**, а правильная операция — не `PAR` (∪, «первый PASS
побеждает»), а **мода по множеству голосующих, допущенных условием
Кондорсе**. Рой возникает не из разнообразия покрытия, а из **гашения
дисперсии независимых оценок одной и той же скрытой величины**.

Измерено, held-out, 40/40 разбиений: **0.861 против 0.783** у лучшей
одиночной модели, и **выше оракульной границы «хоть одна из 6 решила
целиком»** — то есть выше потолка любой стратегии выбора.

## 1. Аномалия, которая всё лицензирует

LIFE-9, измерено:

| величина | значение |
|---|---|
| UNION (потолок ЛЮБОГО шагового маршрута), test | **0.570** |
| whole-task одной моделью, test | **0.700** |
| `α_B2` = доля решённых среди `U_dead` | **0.721** |

`U_dead` — 43 задачи, где хотя бы один род шага не проходит **ни одной**
из 6 моделей. В шаговой парадигме они **доказуемо нерешаемы**: нет
маршрута, нет сборки, нет эволюции, которые их возьмут. И при этом одна
модель, спрошенная целиком, решает **72%** из них.

Это не шум и не поправка. Это **опровержение факторизации**:

```
старая модель мира:   Y  =  Π_s S_s        (задача решена ⟺ каждый шаг прошёл)
измерено:             P(Y=1 | Π_s S_s = 0)  =  0.721  ≠  0
```

Отображение «производительность на изолированном шаге» → «производительность
на задаче» **не гомоморфизм**. Изоляция шага уничтожает распространение
ограничений: в совместном промпте правдоподобие финального ответа
ограничивает промежуточные значения, в изолированном — нет.

Отсюда центральное различение, на котором стоит вся теория:

| | **ШАГ** (старое) | **ПОЛЕ** (новое) |
|---|---|---|
| как получено | отдельный вызов, свой промпт | координата, извлечённая из ОДНОГО совместного ответа |
| контекст | только этот шаг | вся задача |
| распространение ограничений | разрушено | сохранено |
| агрегация | `PAR` = ∪ = первый PASS | мода по допущенным Кондорсе |
| потолок | UNION = 0.570 | измерено **0.861** |

Одинаковые имена (`parcels`, `tariff`…) — принципиально разные измерения.

## 2. Диагноз: неверная алгебра и неверный уровень измерения

### 2.1 Неверная алгебра

Язык `arch2/ASSEMBLE` содержит ровно один способ соединить несколько
моделей: `PAR` = «исполняй ветви, первый доверенный PASS побеждает» —
это **дизъюнкция**. Дизъюнкция усиливает **recall** и разрушает
**precision**.

А все измеренные с DELTA-0 отказы — **precision-ограниченные**:

| DELTA-0 FILTER, измерено | |
|---|---|
| recall | **0.819** |
| precision | **0.545** |
| superset (все золотые + лишние) | 19/40 |
| частичное пересечение | 18/40 |
| subset | 2/40 |
| **полностью мимо** | **0/40** |

Пятнадцать пакетов применяли recall-усилитель к precision-ограниченной
проблеме. В языке нет ни ∩, ни медианы, ни моды — **нет ни одного
оператора, гасящего дисперсию**.

### 2.2 Неверный уровень измерения

PTG-урок проекта («один скаляр — источник багов») не был применён к
самой метрике. `r` уровня задачи — это **конъюнкция 4 полей**: одно
плохое поле обнуляет всю задачу. Что это скрывало (измерено):

```
qwen3-1.7b-q4_0-unsloth :  r_задачи = 0.08   ← «бесполезна»
                           parcels  = 0.98   ← ЛУЧШАЯ В ПУЛЕ (у победителя 0.91)
                           ship_date= 0.11   ← единственное поле, которое её убивает
```

Модель, являющаяся **лучшим экстрактором пула по одному полю**,
пятнадцать пакетов числилась мусором. Конъюнктивная метрика уничтожила
сигнал, ради которого весь проект и затевался.

## 3. Матаппарат

### 3.1 Постановка

Задача `t`. Ответ раскладывается на поля `f ∈ F`, заданные **схемой
задачи** (не изобретаемые LLM — урок LIFE-9: планировщик 1.5B выбирает
нужную величину лишь в 22% случаев). Модель `m` возвращает совместный
ответ `ŷ_m`; детерминированный шов извлекает координату `v_{m,f}`.

**Надёжность**  `π_{m,f} = P( v_{m,f} = y*_f )` — оценивается на train.

**Допустимое множество Кондорсе**  `A_f = { m : π_{m,f} > 1/2 }`.

**Оценщик ESW**  `ŷ*_f = mode{ v_{m,f} : m ∈ A_f }`.

### 3.2 Сходимость

Теорема (присяжные Кондорсе, форма Хёфдинга). Если ошибки независимы и
неверные значения **рассеяны** (не концентрируются на одном
альтернативном значении), то

```
P( ŷ*_f = y*_f )  ≥  1 − exp( −2 k_f γ_f² ),    γ_f = min_{m∈A_f} (π_{m,f} − 1/2)
```

где `k_f = |A_f|`. Задача целиком: `P = Π_f P_f` при независимости ошибок
по полям.

**Условие рассеянности — несущее.** Именно оно объясняет, почему мода
работает даже когда большинство голосующих неверны: верные ответы
**совпадают** (их один), неверные **расходятся** (их много). Мода — это
детектор совпадения, а не подсчёт правоты.

### 3.3 Корреляция: единственное, что может убить рой

Реальные модели не независимы (общие корпуса, общие семейства). Стандартная
поправка:

```
k_eff = k / (1 + (k−1) ρ)          →  насыщается на 1/ρ
```

**Никакое количество моделей не даёт больше `1/ρ` эффективных голосов.**
Отсюда единственное число, решающее судьбу роя на атоме `a`:

```
                    Swarm Gain:    G_f  =  k_eff,f · γ_f²
```

`ρ` измерим напрямую как внутриклассовая корреляция бинарных ошибок:

```
ρ_f = [ P(обе модели неверны) − P(неверна)² ] / [ P(неверна)(1 − P(неверна)) ]
```

### 3.4 Дисперсия против смещения — трёхсторонний маршрутизатор

**Консенсус гасит дисперсию, но не смещение.** Если все модели ошибаются
ОДИНАКОВО, голосование бессильно. Это не слабость теории — это её
предсказательная сила, и она объясняет FORK-1:

| атом | тип ошибки | признак | что делать |
|---|---|---|---|
| F2 FILTER | **дисперсия** | 0/40 полностью мимо, ошибки идиосинкратичны | **рой** |
| T_hard SUM | **смещение** | 0/155 верных при верном формате у ВСЕХ 6 | **инструмент** (det = 1.000) |
| план (LIFE-9) | **смещение** | 22% выбора нужной величины | **схема**, не LLM |

Правило маршрутизации:

```
G_f велик              →  консенсус роя
A_f = ∅, есть формула  →  детерминированный инструмент
A_f = ∅, формулы нет   →  INAPPLICABLE          (правило arch1: не угадывать)
```

Третья ветвь — прямое наследование трихотомии PASS/FAIL/INAPPLICABLE:
рой имеет право **отказаться**, и это не провал, а корректный исход.

### 3.5 Сертификат — вектор, не скаляр (PTG)

Кандидат-ответ получает **вектор**, который никогда не сворачивается:

```
c(ŷ) = ( min_f γ_f ,        слабейшее звено согласия
         σ_det(ŷ) ,         детерминированная перепроверка производных полей
         seam(ŷ) ,          PASS / FAIL / INAPPLICABLE
         #{f : γ_f > 0} )   сколько полей вообще имеют большинство
```

`σ_det` — это **распространение ограничений, возвращённое на этап
проверки**: пересчитать `shipping_cost = parcels × tariff` из уже
принятых консенсусом полей и сравнить. Точно, бесплатно, детерминированно.
Это ровно те det-атомы FORK-1 (`r=1.000`), но применённые как **верификатор,
а не генератор**.

Отбор среди кандидатов — **Парето-недоминируемость по `c`**, а не argmax.

### 3.6 Адаптивная остановка

Мода не перевернётся, пока разрыв ≥ 2 голосов. Отсюда правило:

```
опрашивать следующую модель, пока   min_f | n_top,f − n_second,f | < 2
порядок опроса                  =   B3 greedy_order_deterministic
```

**Изоморфизм**: жадное покрытие максимизирует предельный прирост покрытия
= максимизирует комплементарность = **минимизирует корреляцию ошибок**.
`build_b1_b2_b3` уже является декоррелирующим селектором голосующих —
его просто никогда так не использовали.

`validate_esw0.py` — перечитывает `whole_grid.json` (100 задач × 6 моделей,

| оценщик | среднее | [min..max] |
|---|---|---|

| **консенсус по Кондорсе** | **0.861** | [0.82..0.92] |

**`condorcet > best_single` на 40/40 разбиениях.**

**Жюри оказались крошечными** (измерено, `π` на всех 100):

| поле | `|A_f|` | допущены |
|---|---|---|
| `parcels` | 3 | qwen2.5-coder, internvl3, qwen3 |
| `ship_date` | **2** | qwen2.5-coder, internvl3 |
| `tariff` | 3 | qwen2.5-coder, internvl3, qwen3 |
| `shipping_cost` | **2** | qwen2.5-coder, qwen3 |

При `|A_f| = 2` «большинство» вырождается в тай-брейк при любом
разногласии. То есть **+0.078 получены в наислабейшем возможном режиме**,
`k_eff ≈ 2–3`. По §3.3 выигрыш растёт с `k_eff` до насыщения на `1/ρ` —
значит связывающее ограничение сейчас не корреляция, а **дефицит
допущенных голосующих**. Это единственный результат всего корпуса,
который даёт *измеренное* обоснование расширять реестр моделей
(LIFE-8 хотела этого и не смогла обосновать: там добавление моделей
искало покрытие, здесь — голоса выше порога, совсем другая величина).

Три вывода, каждый нетривиален:

1. **Наивное большинство ПРОИГРЫВАЕТ** (0.743 < 0.783). Условие Кондорсе
   несущее, а не декоративное: 4 из 6 моделей нарушают `π > 1/2` на
   большинстве полей и, будучи допущенными, топят сигнал.
2. **Фильтр Кондорсе выигрывает устойчиво**, +0.078, без единого поражения.
3. **Эмерджентность доказана буквально**: на полных 100 задачах консенсус
   верен на **5 задачах, где НИ ОДНА модель не верна целиком**
   (`HS_011, HS_055, HS_059, HS_087, HS_113`), и превышает оракульную
   границу «хоть одна из 6» (0.870 против 0.840). Ответ роя **не является
   ответом ни одного из участников** — это определение эмерджентности,
   а не метафора.

```
   1. ОПРОС (совместный, не факторизованный)
      m ← B3 greedy_order            ŷ_m = whole_call(m, t)
      останов: min_f |n_top − n_second| ≥ 2
                                   │
   2. ПОДЪЁМ В ПРОСТРАНСТВО ПОЛЕЙ
      v_{m,f} ← det_seam(ŷ_m)        (шов, не LLM-судья)
                                   │
   3. КОНСЕНСУС ПО ПОЛЮ
      A_f = {m : π_{m,f} > 1/2}      ŷ*_f = mode{v_{m,f} : m ∈ A_f}
      A_f = ∅  →  инструмент, если есть формула;  иначе INAPPLICABLE
                                   │
   4. СЕРТИФИКАТ (вектор, не скаляр)
      c = (min γ_f, σ_det, seam, #{γ_f>0})
                                   │
   5. ПАРЕТО-ФИЛЬТР по c   ←  изоморфен LIFE-7 _d2_subsidy_deaths
                                   │
   6. ВЫДАЧА либо честный INAPPLICABLE
```

**Три слоя, каждый назначен измеренным числом:**

| слой | кто делает | обоснование |
|---|---|---|
| **восприятие** (читать поля из грязного текста) | **рой + консенсус** | ESW-0: 0.861 > 0.783 |
| **вычисление** (арифметика над полями) | **детерминированный инструмент** | FORK-1: det 1.000 против LLM 0.000 |
| **план** (какие поля вообще нужны) | **схема задачи** | LIFE-9: LLM-планировщик 22% |

## 9. Конъюнкция по K полей — почему E1/E2 не прошли, а механизм жив

Измерено (`reports/REPORT_E1E2E3.md`), 2026-08-24, 480 живых вызовов.

### 9.1 Консенсус выигрывает там, где и должен — на уровне одного голоса

| семья | consensus per-id accuracy | лучшая одиночная модель | выигрыш |
|---|---|---|---|
| F2 (n=720 решений) | **0.840** | qwen3-1.7b, 0.799 | **+0.042** |
| T_hard (n=560 решений) | **0.782** | internvl3-2b, 0.780 | +0.002 |

Тот же качественный эффект, что в ESW-0 (`condorcet > best_single`), не
отрицательный ни разу. Фильтр Кондорсе отработал штатно: исключил
`smollm2-1.7b` (TPR=0.000 — «всегда НЕТ», сбалансированная точность
0.489, раздельная accuracy 0.215 выглядела бы прилично) и оставил
сильнейший голос (`qwen3-1.7b`, 0.806).

### 9.2 Но чек-поинт — это K-арная конъюнкция, а не одно поле

F2 требует ВСЕ K=18 id-решений верными одновременно (exact-set);
T_hard — те же K_HARD=14 через SUM (одна неверная id меняет сумму на
15-480, допуск 0.01 — почти никогда не прощает). Возведение измеренной
per-id точности в степень K предсказывает итоговую долю почти без
подгонки:

```
F2:     0.840^18 = 0.043   (измерено 0.025)
T_hard: 0.782^14 = 0.032   (измерено 0.025)
```

Обе оценки — того же порядка, что и измеренное значение (наблюдаемое
чуть ниже — согласуется с `ρ_FILTER` §9.3: решения по разным id ВНУТРИ
одной задачи не полностью независимы). **Это не сломанный рой — это
реальный, положительный, попольный выигрыш, возведённый в степень,
которая его стирает.** ESW-0 (HETEROSTEP, K=4 поля) сидит в режиме, где
эта степень выживаема (`0.84^4≈0.50`, порядок величины совпадает с
измеренными 0.861 на уровне задачи, если учесть что поля HETEROSTEP не
были настолько однородны по точности, как id-решения F2/T_hard).
K=14-18 — нет.

Это уточняет теорему сходимости §3.2: граница `P(ŷ*_f=y*_f) ≥
1-exp(-2k_f γ_f²)` верна ПО ПОЛЮ, но неявно читалась как переносящаяся
на уровень задачи, если `A_f≠∅` для достаточного числа полей. Не
переносится. Ничто в §3 не описывает, что происходит с `P(все поля
верны) = Π_f P_f` при росте `|F|` — это произведение убывает, даже если
каждый отдельный `P_f` растёт.

### 9.3 ρ_SUM: не вычислим — это предельный случай смещения, а не опровержение

`P(неверна) = 1.000` точно (0/240 — все 6 моделей неверны на всех 40
задачах T_hard, побитово совпадает с forensics FORK-1: 0/155
однострочных + 85 многострочных, 0 верных в обоих случаях). Знаменатель
формулы `P(неверна)(1-P(неверна))` — точно 0. Это предельный случай
самого смещения (универсальный, детерминированный провал сильнее любой
конечной `ρ<1`), а не его опровержение. Механическая метка в
`run_e3.py` (`..._bias_claim_falsified`) вводит в заблуждение вне этого
абзаца — путает «формула не определена» с «утверждение ложно».

`ρ_FILTER_F2=+0.150` и `ρ_FILTER_Thard=+0.103` — обе ниже порога 0.4,
подтверждают дисперсионную (не смещённую) природу ошибок FILTER.
**Маршрутизатор §3.4 был прав насчёт РЕЖИМА (дисперсия vs смещение) —
он ничего не говорил о ширине конъюнкции, а именно она решила исход
E1/E2.**

Некритично: диагноз конъюнкции — апостериорное объяснение с
подтверждающей арифметикой (`p^K`), не отдельное предрегистрированное
предсказание — гипотеза для будущего замера (доля на уровне задачи как
функция K напрямую), а не подтверждённая теория.

## 9.4 E4: конъюнкция была не тем объектом. Правильная операция — декодирование

Измерено (`reports/REPORT_E4.md`), 2026-08-24, **0 новых вызовов** —
переигрывает уже собранные 516 строк `filter_calls.jsonl`.

§9 винила ширину конъюнкции. Это верно, но недостаточно: **конъюнкция
вообще не тот объект**. Поля не независимы — они лежат на дискретном
многообразии допустимых структур. 18 записей F2 разбиваются в среднем на
**12.5 классов** `(category, region)`, и золотой ответ — всегда ровно
один класс. Истинная размерность ответа ≈ 1, а не 18.

```
было:  P(задача) = Π_f P_f                    -> p^K, гибнет с ростом K
стало: P(задача) = P( C* = argmin_C |S △ C| ) -> зависит от РАЗДЕЛЕНИЯ
                                                 кодовых слов, не от числа бит
```

`agreement(s,C) = Σ_i [s_i если i∈C иначе 1−s_i]` при бинарных голосах
равно `K − |S △ C|`, то есть argmax согласия **есть декодирование по
ближайшему кодовому слову**. Классы дизъюнктны, `|C|≈2–5`, поэтому запас
`|S△C| − |S△C*| ≈ |C|+|C*| − 2|S∩C| ≈ 3–7` переживает 2–3 ошибки на 18
позициях. **Рост K теперь помогает** (больше позиций-свидетелей на то же
число гипотез) — прямо противоположно плоскому режиму §9.

Условие работоспособности было измерено заранее: **низкая ρ** (E3,
`+0.150`/`+0.103`) означает идиосинкратические, а не общие ложные
срабатывания — они не концентрируются в одном соседнем классе и не
уводят декодер. **E3 была предпосылкой E4, а не утешительным призом.**

Результат:

| | плоско (E1/E2) | + декодирование | whole-task `r_m*` |
|---|---|---|---|
| F2 exact-set | 0.025 | **0.525** | — |
| F2 финал ДА/НЕТ | — | **0.875** | 0.525 → **Δ=+0.350** |
| T_hard SUM | 0.025 | **0.500** | 0.000 → **Δ=+0.500** |

**Первая положительная Δ за 16 пакетов.** Шестнадцать пакетов искали её,
меняя маршрутизацию внутри плоской факторизации; она нашлась при смене
операции.

### 9.5 Но рой при этом НЕ подтверждён

Пред-регистрированный чистый тест (обе стороны получают идентичное
декодирование, поэтому разрыв — вклад ровно роя) дал **`SWARM_NULL`**:

| | рой + декод | лучшая одиночная + декод | вклад роя |
|---|---|---|---|
| F2 exact-set | 0.525 | **0.725** | **−0.200** |
| F2 финал | 0.875 | **0.975** | **−0.100** |
| T_hard exact-set | **0.500** | 0.425 | +0.075 |

На F2 одна `qwen3-1.7b` с декодированием бьёт весь рой; Δ=+0.450 против
whole-task достигается **вообще без роя**. Прорыв дало **структурное
декодирование**, а не рой.

Найденный дефект (forensics, не гипотеза): `gemma-3-it-1b` допускалась
**39/40** раз при сбалансированной точности ≈0.503 и собственной
декодированной ставке **0.000**. При support≈0 функция согласия
максимизируется на наименьшем классе — почти-нулевой голос активно тянет
декодер к неверной мелкой гипотезе. **Порог `π > ½` перенесён из E0 без
проверки**, а там голоса агрегировались модой по полю, не в непрерывный
вектор поддержки. Для декодирования критерий допуска обязан учитывать
**маржу**, а не факт превышения ½.

Post-hoc развёртка порога (на тех же 40 задачах, **не** пред-регистрирована,
как подтверждение не засчитывается) даёт при `π>0.60`: F2 exact-set 0.750,
T_hard 0.650 — рой обходит лучшую одиночную на обоих полигонах, и это
плато (0.60/0.65/0.70 совпадают), а не острый пик. Проверяется
out-of-sample в E5 на никогда не использованных train-сплитах.

### 9.6 E5: порог удержался, рой — нет (out-of-sample, 720 вызовов)

Гипотеза §9.5 проверена на **train-сплитах, невиданных в E1–E4**

**`THRESHOLD_HELD_OOS`** — порог 0.60 не был переподгоном: F2 exact-set

мягок для декодера» реален и исправим.

**`SWARM_REJECTED`** — но исправление рой не спасает. Вклад роя,
четыре независимых замера при идентичном декодировании по обе стороны:

|---|---|---|

### 9.7 E6: структура + адресный вопрос. Лучший результат проекта, и окончательное закрытие роя

Два бесплатных зонда (`probe_specialize.py`) перед постройкой:

- **Зонд A — дифференциации нет.** Маршрутизация «поле → свой специалист»
  даёт 0.775 против 0.861 у кондорсе-моды, **0/40** побед; специалистов
  на 4 поля всего **2** (`qwen2.5-coder` владеет тремя). Пул — шесть
  выборок одной способности, а не разные органы. Аналогия «нейроны →
  мозг» здесь ломается точно в этом месте: мозг строится на **обученной
  дифференциации**, а не на ансамблировании.
- **Зонд B — margin декодера предсказывает собственную правоту.**
  Воспроизведено 4 раза на обоих сплитах обеих семей: верхняя половина
  по margin 0.85–1.00, нижняя 0.30–0.45, разрыв +0.40…+0.60.

Отсюда E6: **не спрашивать всех обо всём, а спрашивать точечно там, где
структура колеблется.**

| F2 test, n=40 | было | стало |
|---|---|---|
| exact-set | 0.750 | **0.925** |
| нижняя половина по margin | 0.500 | **0.850** |
| финал ДА/НЕТ | — | **1.000** (`r_m*` = 0.525 → **Δ=+0.475**) |

Верхняя половина по margin не получила **ни одного** дополнительного
вызова. Вся линия на одном полигоне: DELTA-0 `0.025` → E1 `0.025` →
E4 `0.750` → **E6 `0.925/1.000`**.

**Рой закрыт окончательно.** E6 был устроен так, чтобы дать рою
наилучшие возможные условия: на лёгком вопросе `γ = π − ½` велик, и по
`G = k_eff·γ²` выигрыш обязан быть максимальным. Измерено:

| | точность |
|---|---|
| мода 6 моделей | **1.000** |
| лучший одиночный верификатор (`qwen3-1.7b`) | **1.000** |
| **вклад роя** | **+0.000** |

> **Область выигрыша Кондорсе пуста на практике.** Где `γ` мал —
> выигрыш ≈0 (измерено −0.025 при n=200). Где `γ` велик — лучшая
> одиночная уже на потолке 1.000, добавлять нечего.

`G = k_eff·γ²` описывает выигрыш над **средним** участником, не над
**лучшим**: растёт γ — быстрее растёт π лучшего. Собственный non-claim
§10 предупреждал («при π → 1 выигрыш роя стремится к нулю по
построению»); E6 это **измерил**.

**Стоимость, обязательная к раскрытию**: 600 вызовов на 40 задач = **15
на задачу** против 1 у whole-task. Δ=+0.475 куплена пятнадцатикратной
ценой. По §4 отчёта достаточно 1–2 моделей вместо 6 (оценочно 3–5
вызовов), но эта конфигурация **не прогонялась**.

`filter_det = 1.000` по exact-set остаётся непобитым (E6: 0.925);
совпадение по финалу — следствие мягкости булева ответа.
Полностью: `reports/REPORT_E6.md`.

### 9.8 G1: рой выигрывает на GSM8K — и §9.5 требует пересмотра границ

Справедливое возражение к E6: он работает по **перечислимому кодбуку**,
который дала структура генератора. На задаче без такого пространства
(GSM8K) E6 неприменим в принципе. Это не устраняется настройкой — это
граница метода, и её надо было заявлять громче.

G1 проверил рой там, где кодбука нет вовсе. Реальный GSM8K, 200 задач,
2400 вызовов, кандидатов порождают сами модели.

| оценщик (40 сплитов 50/50, выбор на train) | среднее |
|---|---|
| best single (выбран на train) | 0.646 |
| plain — мода по всем 6 | 0.721 |
| **filtered — `π_m ≥ 0.5·π_best`** | **0.726** |
| weighted — лог-оддс | 0.725 |

**`+0.079`, побед 40/40.** Против оракульно-лучшей модели (0.670) —
`+0.040`. Основной выигрыш даёт **plain-мода, не требующая калибровки
вообще**; фильтр добавляет лишь +0.005, то есть результат не держится на
правиле допуска.

**Почему здесь, а не в E1–E6** (всё измерено):

| | F2/T_hard | GSM8K |
|---|---|---|
| конъюнкция | K=14–18, штраф `p^K` | **K=1, штрафа нет** |
| рассеянность | набор из 18 id | **единогласие лишь 4.5%** |
| насыщение | E6: лучшая уже 1.000 | **0.670, потолка нет** |

**Правка §3.2, зафиксированная ДО прогона**: `π > ½` выведено для
БИНАРНОГО выбора и на GSM8K даёт пустое `A` всегда. Для многозначного
ответа условие — `P(верный) > max_w P(конкретный неверный)`; при
рассеянных ошибках 0.30 против ≈0.02. Порог ½ был унаследован из
бинарного случая и уже подводил в E4 с обратным знаком (слишком мягок
для декодера). **Это исправление области определения, не послабление.**

**Два провала, один предсказанный.** Раунд верификации: 0.510 → **0.460**
на низко-маржинальной половине. Принцип «атом должен быть строго легче
целого» предсказал это заранее: в E6 атомом был поиск одной строки
(1.000 у двух моделей), а «правилен ли ответ X?» на GSM8K требует заново
решить задачу. Провал подтверждает принцип. Второй провал мой: эвристика
det-ремонта арифметики дала 0.632 против 0.721 — правило «последнее
уравнение» слишком грубое.

**Потолок метода.** Оракул «хоть одна из 6» = 0.870, консенсус 0.710,
добрано **20%** запаса, эмерджентных задач **0** — и это структурная
неизбежность: мода выбирает значение, которое кто-то уже произнёс, и
превысить оракул не может. В отличие от E0, где сборка шла ПО ПОЛЯМ и
потому рождала ответ, которого не дал никто (0.870 против оракула 0.840).
**Оставшиеся 80% запаса — задачи, где верный ответ произнесла ровно одна
модель; модой они не берутся в принципе, нужен отбор, а не голосование.**

`ρ = +0.217` (положительна, в отличие от отрицательных ρ в E0),
`k_eff = 2.9`: рой работает даже при заметной корреляции, если ошибки
рассеяны по ЗНАЧЕНИЯМ.

Полностью: `reports/REPORT_G1.md`, `PROTOCOL_G1.md`.

### 9.9 K1: декомпозиция контекста по схеме Кана. Работает. Эмерджентности по-прежнему нет

**Измеренная предпосылка** (`probe_lost_middle.py`, 0 GPU, на уже
собранных данных E1+E5): полнота извлечения падает **монотонно по
позиции** — 0.609 на позиции 0 → **0.214** на позиции 17. Это не
«потеря внимания в середине»: U-образного провала нет, точность почти
плоская (0.762 край против 0.739 середина). Модель **перестаёт
находить**, всё чаще отвечая «нет» на поздние записи — что чинит
истинные отрицания и обрушивает полноту.

**Разбиение 18 записей на 3 блока по 6** (дисциплины по Кану):

| | полный контекст | блоки |
|---|---|---|
| recall хвоста (поз. 12–17) | **0.304** | **0.574** |
| **разрыв голова−хвост** | **0.204** | **0.021** |
| exact-set после декодирования | 0.750 | **0.900** |
| финал ДА/НЕТ | — | **1.000** (`r_m*` = 0.525) |

Разрыв схлопнулся вдесятеро: позиция записи перестала определять, найдут
ли её. **Декомпозиция помогает слабым сильнее, чем сильным** —
qwen2.5-coder 0.175 → 0.700 (вчетверо), llama 0.400 → 0.725, а лидер
qwen3 лишь 0.725 → 0.850. Это тезис Кана в численном виде: правильное
деление работы поднимает посредственностей до складывающегося уровня.

**Эмерджентности нет — и я опроверг собственную заявку на том же
прогоне.** Пред-регистрированный порог был сформулирован неудачно
(«ни одна модель не взяла набор целиком на ПОЛНОМ контексте») и дал
34/40 — артефакт сравнения полного конвейера с сырым извлечением.
Корректная мера — одиночная модель через **идентичный** конвейер:

| | |
|---|---|
| собранный конвейер (6 моделей) | 0.900 |
| лучшая одиночная через тот же конвейер | 0.850 |
| вклад роя | **+0.050** |
| оракул «хоть одна из 6» | 0.975 |
| **строгая эмерджентность** | **0** |

**Что из семи дисциплин Кана реально несло нагрузку: одна** — деление на
блоки (+0.150 к exact-set). МДП **вырождена** (блоки F2 независимы,
на швах проверять нечего), консультация и ревизии не понадобились, ВДП
поймала 5 галлюцинаций, рой дал +0.050. Выдавать K1 за подтверждение
схемы Кана целиком нельзя.

**Сводная формулировка трёх последних пакетов:**

> Выигрыш даёт **декомпозиция** — контекста (K1), структуры ответа (E4),
> вопроса (E6). Пул даёт от 0 до +0.08 сверху и **никогда не даёт
> эмерджентности**.

Эмерджентность измерена ровно один раз — E0, где сборка шла **по полям
одного совместного ответа**. Ни мода по финальному числу (G1), ни
композиция по блокам входа (K1) её не воспроизвели. Если она достижима,
то только там, где разные модели вносят разные **ЧАСТИ одного ответа**,
а не разные мнения о целом и не разные куски входа.

Полностью: `reports/REPORT_K1.md`, `PROTOCOL_K1.md`, `probe_lost_middle.py`.

### 9.10 M1/M2: МДП на настоящих швах. Пул — источник кандидатов, не избиратель

K1 оставил МДП вырожденной: блоки F2 независимы, на швах проверять
нечего. M1/M2 строят задачу, где **выход дисциплины является входом
следующей** (отдел с макс. бюджетом → его менеджер → его сотрудники), и
шов физически нарушим.

| хоп 1, «максимум среди 8 строк» | TEST | TRAIN (OOS) |
|---|---|---|
| мода по 6 | 0.275 | 0.325 |
| лучшая одиночная (`internvl3-2b`) | 0.525 | 0.525 |
| **лучшая одиночная + МДП-откат в пул** | **0.600** | **0.575** |
| Δ над лучшей одиночной | +0.075 | **+0.050 `CONFIRMED_OOS`** |
| МДП сработала / **сломала** | 13/40 / **0** | 10/40 / **0** |

**Два воспроизведённых вывода.** (1) **МДП безопасна по конструкции**:
23 срабатывания, ноль сломанных верных ответов — проверка интерфейса
может отбраковать только нарушителя шва, а верный ответ шов не нарушает.
(2) **Голосование вредит**: мода хуже одной хорошей модели на 0.20–0.25.
Отсюда роль пула: **кандидаты для ремонта, а не голоса**.

**Урок о вырожденности, стоивший целого пакета**: в M1 у каждого отдела
был менеджер, поэтому референциальная проверка проходила всегда и
`Δ_МДП` на хопе 1 был +0.000 **по построению генератора**. МДП ловит
ошибки только там, где ограничение **нарушимо**; убрав нарушимость, я
измерил собственный генератор, а не механизм. В M2 (3 отдела из 8 без
менеджера, ошибка детектируема с p≈0.43) тот же механизм дал +0.125.

**Настоящее узкое место — не архитектура.** Найти максимум среди 8 строк
модели 1–2B умеют в **15–52%** случаев. Трёхзвенная цепочка при этом
даёт оракул 0.075–0.100, и никакая маршрутизация поверх такого основания
сквозной задачи не вытянет. Это тот же класс дефекта, что позиционный
распад полноты §9.9: базовое чтение таблицы ненадёжно, архитектура его
подпирает, но не заменяет.

**Класс роя.** Кривая «размер → качество» одним стендом (200 задач
GSM8K, 8 точек 0.36–2B): `acc = 0.671·log10(B) + 0.336`, **R²=0.508**,
рой 0.726 → **implied ≈3.8B**. Верить умеренно: R² на границе, размер
плохо предсказывает качество (`smollm2-1.7b` 0.125 против `gemma-3-1b`
0.565 при вдвое меньшем размере), и это экстраполяция за 2B. Формулировка:
**рой из шести 0.36–2B держится на уровне одиночной ~3–4B** ценой шести
вызовов.

Полностью: `reports/REPORT_M1M2.md`, `PROTOCOL_M1.md`, `PROTOCOL_M2.md`.

### 9.11 LB2: граница применимости всей линии

LongBench v2, срез Multi-Doc QA / hard / short: 44 вопроса, 8.3k–32k слов,
4 варианта, случайная база **0.250**. Контекст физически не влезает в
`n_ctx=2048` — декомпозиция здесь не приём, а единственный способ прочитать
задачу. Проверялась вся схема разом: чанкование (K1) → распределённое
покрытие → ВДП → сборка → **эйген-консенсус без меток** → МДП → строб.

| арм | best single | plain | EIGEN | Spearman |
|---|---|---|---|---|
| TRUNC | 0.295 | 0.205 | **0.182** | **−0.600** |
| SOLO | 0.205 | 0.227 | **0.182** | +0.543 |
| SWARM | 0.250 | 0.250 | **0.250** | **−0.314** |

**Ни один арм не превзошёл случайность.** `DECOMP=+0.000`,
`vs best single=+0.000`, `SWARM−SOLO=+0.068` (≈1 SE, не разрешимо).

**Эйген опровергнут, и механизм важен.** Спектральная оценка надёжности
требует условной независимости ошибок и точности выше 1/K. Здесь не
выполнено ни то, ни другое: `gemma` отвечает A в 40 случаях из 44,
`llama` — B в 35 из 44, три модели делят смещение к «A» и **соглашаются
на предрассудке, а не на истине**. Матрица согласия становится рангом 1
по смещению; самая точная `qwen3` (0.295, самое равномерное
распределение) соглашается с остальными реже всех и получает
**наименьший вес**. Метод не деградирует до случайного — он
**инвертируется**, то есть уверенно указывает не туда. Это режим
«смещение, а не дисперсия» §3.4, впервые измеренный на спектральной
оценке.

**Найденный мной дефект.** ВДП v1 сравнивал предложения дословно и
отбраковал 362/870; ручная проверка показала **~60% ложных отказов**
(верная цитата с зачином или переформатированная). ВДП v2 (самый длинный
дословный фрагмент ≥8 слов) поднял опору: swarm 129→**222**, solo
197→**344**. **Но точность не выросла** (SWARM 0.318→0.250): узким местом
было не количество опоры, а неспособность рассуждать по ней. Исходные
0.318 при пересчёте не устояли — были шумом.

**Главный вывод, ограничивающий весь корпус:**

> **Агрегация усиливает сигнал. На уровне случайного угадывания усиливать
> нечего.**

Консенсус, декомпозиция, эйген, МДП работают **над** способностью
моделей, а не вместо неё. Это ограничивает и прочтение G1 (+0.079 на
GSM8K): пул помогает при одиночных 0.37–0.67 и не помогает при 0.16–0.30.
**Диапазон применимости — «слабые, но уже работающие», а не «слабые
вообще».**

Полностью: `reports/REPORT_LB2.md`, `PROTOCOL_LB2.md`.

**Обязательная маркировка**: все числа E4/E5/E6 несут `STRUCTURE_DET=true` —
перечисление гипотез и развёртка детерминированы. `filter_det = 1.000`
(FORK-1) остаётся недостижимым потолком: **E4 не бьёт инструмент и не
претендует.** Это гибрид ровно той трёхслойной формы, которую §5 уже
описывала — E4 впервые пользуется слоем «схема» по назначению.

## 10. Non-claims

- ESW-0 — **одно семейство задач** (HETEROSTEP), 100 задач, один сплит-протокол,
  **K=4 поля**. Перенос на F2/T_hard **проверен и не подтверждён на
  уровне задачи** при K=14-18 (см. §9) — при этом сам механизм
  консенсуса (per-id) выигрывает и там.
- Поля здесь **заданы схемой задачи**. На задаче без известной схемы
  выделение полей само становится проблемой — и LIFE-9 говорит, что
  маленькая LLM с этим не справляется.
- `π_{m,f}` в ESW-0 оценены на 50 задачах; в E1/E2 — leave-one-out на 40
  (самоопределённый выбор, `PROTOCOL_E1E2E3.md` §1). Оба малы по
  абсолютному числу.
- `ρ` **измерена** — на пуле ESW-0 (`rho_holdout.py`, все 4 поля
  отрицательны) и на F2/T_hard FILTER (§9.3, обе ниже 0.4). `ρ_SUM` —
  не вычислима (см. §9.3), не измерена в смысле конечного числа.
- Превышение оракульной границы «хоть одна из 6» (0.870 > 0.840) измерено
  на полных 100 задачах, то есть **без holdout**; на 40 CV-разбиениях
  проверялось только `condorcet > best_single`.
- Ничего из этого **не воскрешает** эволюцию/HGT/Pareto-отбор как
  механизм. Заимствована только *форма* Парето-фильтра LIFE-7, применённая
  к ответам на инференсе.
- Всё измеренное — на локальных моделях 1–2B. Перенос на большие модели
  не показан и теорией не предсказывается: при `π → 1` выигрыш роя
  стремится к нулю по построению.
