# PROTOCOL — G1: рой на GSM8K, без кодбука

Написан ДО единого замера (смок-гейт уже пройден: извлечение 30/30,
точность пула 0.400, 1.79 с/вызов). Пороги ниже не двигаются.

## 0. Почему GSM8K, и почему E6 сюда не переносится

Справедливая критика: **E6 работает по перечислимому кодбуку**, который
дала структура генератора F2. На GSM8K такого пространства нет — область
ответов неограниченна. E6 неприменим, и это не устраняется настройкой.

Но именно поэтому GSM8K — правильный полигон для роя, и по трём
измеренным причинам:

1. **Конъюнкции нет.** То, что убило E1/E2 (`p^K`, K=14–18), здесь
   отсутствует: ответ один, K=1.
2. **Условие рассеянности §3.2 выполняется.** Неверные ответы расходятся
   (у каждой модели своя арифметическая ошибка), верный совпадает.
3. **Ортогональность измерена**: ρ была ОТРИЦАТЕЛЬНОЙ на всех 4 полях E0.

**Теоретическая правка, фиксируется здесь:** классическое условие
Кондорсе `π > ½` выведено для БИНАРНОГО выбора и на GSM8K неприменимо —
ни одна модель туда не дотягивает, `A` было бы пусто всегда. Для
многозначного ответа корректное условие:

```
мода верна, если   P(верный)  >  max_w P(конкретный неверный w)
```

а не `P(верный) > ½`. При рассеянных ошибках `π=0.30` против
`P(конкретный неверный)≈0.02` — запас в 15 раз. **Это не ослабление
критерия задним числом, а исправление его области определения**: §3.2
всегда опиралась на рассеянность, а порог ½ был унаследован из бинарного
случая (и уже один раз подвёл в E4, где `π>½` оказался слишком мягок для
декодера — тот же класс ошибки, обратный знак).

## 1. Архитектура (PTG-граф, без таблиц ответов)

```
узел ЗАДАЧА
   │  (6 параллельных ветвей, независимо)
узел РЕШЕНИЕ_m      сырой CoT каждой модели -- хранится, но НИКОГДА
   │                 не передаётся другой модели как есть
узел ЧИСЛО_m        детерминированный шов: extract_answer()
   │
узел РЕМОНТ_m       safe_arith переоценивает собственные уравнения модели;
   │                 расхождение = арифметическая описка (урок FORK-1:
   │                 det-арифметика 1.000 против LLM 0.000)
узел КОНСЕНСУС      мода по числам + margin = n_top − n_second
   │
узел ВЕРИФИКАЦИЯ    только при низком margin: топ-2 кандидата уходят
                     ВСЕМ моделям как YES/NO вопрос -> пересчёт
```

**Данные между моделями идут только через разобранные узлы, никогда
сырым текстом** — это ровно та дисциплина, без которой граф становится
свалкой. Кандидаты порождают сами модели; перечислимого пространства нет
нигде.

## 2. Оценщики (все на одних и тех же вызовах)

| код | что | |
|---|---|---|
| `single_m` | каждая модель отдельно | база «все слабы» |
| `best_single` | лучшая, выбранная НА TRAIN | честный конкурент |
| `plain` | мода по всем 6 | |
| `filtered` | мода среди `π_m ≥ 0.5·π_best(train)` | замена неприменимому `π>½` |
| `weighted` | лог-оддс взвешивание | как в E0 |
| `repaired` | то же, но после det-ремонта арифметики | |
| `verified` | + раунд верификации на низком margin | |

Правило допуска `π_m ≥ 0.5·π_best` фиксируется СЕЙЧАС: безмасштабное,
не подбиралось, отсекает заведомо бесполезных участников (смок: smollm2
дал 0/5) не требуя неприменимого порога ½.

Протокол сплитов — как в E0: 40 случайных 50/50, модель для
`best_single` и надёжности `π_m` оцениваются на train, всё меряется на
test. Тай-брейк моды: при равенстве голосов побеждает значение от модели
с большей `π_m`; детерминированно.

## 3. Пред-регистрированные пороги

| код | предсказание | фальсификация |
|---|---|---|
| **G1-swarm** | `filtered` > `best_single` | **≤ 0 → рой не работает и на K=1 при рассеянных ошибках; тезис закрыт окончательно** |
| G1-margin | margin предсказывает правоту (spread > 0) | ≤ 0 → верификацию строить не на чем |
| G1-verify | раунд верификации поднимает низко-маржинальную половину | ≤ 0 |
| G1-repair | det-ремонт арифметики не ухудшает | падение > 0.02 |

**G1-swarm — главный.** Это последняя конфигурация, в которой рой ещё
может выиграть: реальный тяжёлый бенчмарк, K=1, рассеянные ошибки,
измеренная ортогональность, отсутствие насыщения (модели 0–60%). Если
он не выигрывает и здесь, вопрос закрыт не «не на тех задачах», а по
существу.
