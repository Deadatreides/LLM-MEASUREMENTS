# PROTOCOL — K1: контора Альберта Кана как архитектура роя

Написан ДО единого нового вызова. Пороги не двигаются.

## 0. Измеренная предпосылка (0 GPU, `probe_lost_middle.py`)

Полнота извлечения падает **монотонно по позиции записи в контексте**:
recall 0.609 на позиции 0 → **0.214** на позиции 17. Втрое.

Это **не** «потеря внимания в середине» (U-образного провала нет:
точность 0.762 по краям против 0.739 в середине). Это распад
нахождения: модель всё чаще говорит «нет» на поздние записи, что
поднимает истинные отрицания и обрушивает полноту.

Отсюда прямое следствие: **разбиение длинного контекста на блоки
переносит каждую запись в зону высокой полноты.** 18 записей → 3 блока
по 6 → каждая запись на позиции 0–5, где recall 0.46–0.61 вместо
0.21–0.31 в хвосте. Это измеренное обоснование декомпозиции, а не
гипотеза.

## 1. Отображение схемы Кана на измеренные способности

| Кан | компонент | на чём основано (измерено) |
|---|---|---|
| ГИП / деление на дисциплины | **схема задачи, не LLM** | LIFE-9: LLM-планировщик 22% |
| дисциплина | **блок контекста** (6 записей) | распад полноты по позиции, §0 |
| исполнитель | 1–6 моделей на блок | Зонд A: пул не дифференцирован → выбор по измеренной π, не по «специальности» |
| консультация главспеца | **точечный вопрос по одной строке** | E6: атом легче целого, 1.000 у qwen3/internvl3 |
| ВДП (внутридисциплинарная) | id принадлежит своему блоку + формат | детерминированно, 0 вызовов |
| МДП (междисциплинарная) | согласованность на швах между блоками | детерминированно, 0 вызовов |
| нормоконтроль | валидация формата перед выдачей | детерминированно, 0 вызовов |
| сборка альбомов | **композиция блоков** | E0: композиция по полям превысила оракул |
| 3 ревизии | итерации, пока margin низкий | margin-сигнал воспроизведён 5 раз |

**Ключевое, ради чего вся конструкция**: композиция — единственный
механизм, способный дать эмерджентность. Мода структурно не может
(G1: 0 эмерджентных задач, потолок = оракул «хоть одна»). Сборка из
блоков может: если модель A взяла блок 1, а B блок 2, собранный ответ
верен, хотя целиком его не дал никто.

## 2. Конвейер

```
СХЕМА -> 3 блока по 6 записей (детерминированно, не LLM)
   │
ИСПОЛНИТЕЛИ: 6 моделей x 3 блока, независимо
   │
ВДП: id вне своего блока -> отбросить (галлюцинация), формат -> нормоконтроль
   │
СБОРКА: голоса по записи берутся из ЕЁ блока -> вектор поддержки по всем 18
   │
КОНСЕНСУС + ДЕКОДИРОВАНИЕ (как в E4, pi>0.60)
   │
КОНСУЛЬТАЦИЯ: при низком margin -- точечный да/нет по одной строке (E6)
   │
ВЫДАЧА
```

## 3. Пред-регистрированные пороги

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| **K1-recall** | recall на исходных позициях 12–17 (сейчас **0.28**) | ≥ 0.45 | **< 0.35** |
| K1-flat | разрыв recall между позициями 0–5 и 12–17 (сейчас **0.32**) | ≤ 0.12 | > 0.20 |
| **K1-set** | exact-set после сборки + декодирования (E4 даёт **0.750**) | ≥ 0.85 | < 0.78 |
| **K1-emergence** | задач, где сборка верна, а НИ ОДНА модель не взяла набор целиком на полном контексте | **≥ 3** | **0 → композиция не даёт эмерджентности** |

**K1-emergence — главный.** Это единственный порог во всём проекте,
проверяющий эмерджентность напрямую, а не через прокси. G1 дал ноль по
построению; если и композиция даёт ноль, то эмерджентности нет нигде.

## 4. Бюджет

40 задач F2 TEST (те же, что несут `r_m*=0.525`, E1 и E4 — сравнение без
допущения переноса) × 3 блока × 6 моделей = **720 вызовов**.
Блок ~400 токенов вход, ~40 выход → ≈0.86 с/вызов → **≈10 минут**.
База (полный контекст) уже на диске, 0 новых вызовов.

Суммарный объём токенов почти не растёт: 3 блока по 1/3 контекста ≈ тот
же контекст, плюс тройные накладные на промпт. **Декомпозиция здесь
почти бесплатна по токенам и должна окупиться полнотой.**

## 5. Non-claims

- Блоки в F2 независимы (записи не ссылаются друг на друга), поэтому
  **МДП здесь вырожден** — проверять на швах нечего. Настоящую нагрузку
  МДП несёт только на задачах с зависимостями между блоками; здесь он
  реализован, но его вклад не измеряется. Не выдавать за проверку МДП.
- `STRUCTURE_DET = true`: декодирование и ВДП/нормоконтроль
  детерминированы. `filter_det = 1.000` — непобитый потолок.
- Порядок записей внутри блока сохраняется исходный; блоки нарезаются
  подряд, без перемешивания — иначе замер позиционного эффекта потерял
  бы смысл.
- 40 задач, одна семья, один сплит.
