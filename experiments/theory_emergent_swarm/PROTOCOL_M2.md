# PROTOCOL — M2: M1 с исправленными дефектами дизайна

Написан ДО единого вызова M2. Пороги не двигаются.

## 0. Что именно чинится (дефекты MOI, не выводы про МДП)

M1 дал все армы на полу (WHOLE 0.000, CHAIN_SINGLE 0.050, CHAIN_SWARM
0.000, +МДП 0.025). Диагностика по хопам вскрыла три моих дефекта:

1. **Шов 1 был ненарушим.** Каждый отдел имел менеджера, поэтому
   референциальная проверка проходила всегда: `Δ_МДП` на хопе 1 = +0.000
   **по построению генератора**, а не потому что МДП не работает.
   → M2: 3 отдела из 8 без менеджера (у целевого — всегда есть).
   Ошибочный хоп 1 детектируем с вероятностью ≈0.43.
2. **WHOLE был обнулён арифметикой.** Финал требовал точной суммы, а
   FORK-1 уже измерила там **0/240** для этих моделей. База измеряла не
   рассуждение, а неспособность складывать.
   → M2: финал — **множество ID сотрудников**, арифметики нет нигде.
3. **Конъюнкция трёх хопов лишила ablation разрешения.**
   → M2: **основная метрика — по хопам**, сквозная идёт вторым номером.

Что при этом в M1 уже измерено и переносится как знание: МДП на хопе 2
дала **+0.075** (исправила 3 задачи, сломала 0), а при верном хопе 1 хоп 2
с МДП верен **13/13**. Узкое место — хоп 1 (0.325): найти максимум среди
8 чисел моделям удаётся в трети случаев.

## 1. Пред-регистрированные пороги

Основные (по хопам, где МДП физически действует):

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| **M2-mdp1** | `hop1(+МДП) − hop1(swarm)` — теперь шов нарушим | ≥ +0.05 | **≤ 0** |
| **M2-mdp2** | `hop2(+МДП) − hop2(swarm)` | ≥ +0.05 | ≤ 0 |
| **M2-mdp-safe** | задач сломано МДП | **0** | **≥1 сломанная → проверка интерфейса небезопасна** |

Вторичные (сквозные, exact-set):

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| M2-decomp | `CHAIN_SINGLE − WHOLE` | > 0 | ≤ 0 |
| M2-swarm | `CHAIN_SWARM_MDP − лучшая CHAIN_SINGLE` | > 0 | ≤ 0 |
| M2-emergence | верна сборка, но **ни одна** CHAIN_SINGLE не верна | ≥ 3 | 0 |

`M2-mdp-safe` — новый и важный: в M1 МДП не сломала ни одной задачи, и
это свойство надо подтвердить, а не считать данностью. Проверка
интерфейса обязана быть монотонной.

## 2. Правила, унаследованные без изменений

- Ремонт МДП стоит **ноль вызовов**: переупорядочивание уже собранных
  кандидатов по валидности шва.
- МДП проверяет **интерфейс**, не переделывает работу соседа. На хопе 3
  фильтрации по `mgr` нет — это было бы вычислением ответа.
- Провалили проверку все кандидаты → дисциплина отказывается
  (INAPPLICABLE), задача FAIL, **без подстановки золотого значения**.
- Схема из трёх хопов задана, не изобретается LLM (LIFE-9: 22%).

## 3. Бюджет

40 задач TEST, кэш по `(задача, хоп, вход, модель)`. Оценка ≈2500
вызовов, ≈28 минут.

## 4. Non-claims

- Чистый `det`-конвейер решил бы M2 на 1.000; потолок инструмента не
  оспаривается.
- M2 — исправленная итерация M1, а не независимое подтверждение: числа
  M1 остаются опубликованными рядом.
- Одна семья, один сплит, n=40.
