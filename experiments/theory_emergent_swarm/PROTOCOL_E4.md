## 1. Что именно не так с E1/E2 (и почему это не «рой не работает»)

E1/E2 требовали ВСЕ K id-решений верными одновременно (K=18 для F2,
K_HARD=14 для T_hard). Но 18 записей — **не 18 независимых бит**. Они
разбиваются на классы эквивалентности по паре атрибутов
`(category, region)`, и золотой ответ — ВСЕГДА ровно один такой класс
(свойство генератора F2/T_hard, см. §6 «ограничения»).

Значит истинная размерность ответа ≈ 1 (какой класс), а не 18.
Плоское поid-голосование выбрасывает эту структуру и платит `p^K`.

**Правильная операция — не голосование, а декодирование**: спроецировать
шумный ответ роя на ближайший допустимый класс. Как в коде, исправляющем
ошибки: не нужно, чтобы каждый бит был верен — нужно, чтобы принятое
слово было ближе к верному кодовому слову, чем к любому другому.

## 2. Механизм E4 (микро → макро → обратно к микро)

```
1. ВОСПРИЯТИЕ (LLM, уже собрано)   каждая модель читает грязный текст БД
                                     -> свой id-набор
2. КОНСЕНСУС (уровень 1)            s_i = доля допущенных Кондорсе
                                     моделей, проголосовавших YES за id i
3. ГИПОТЕЗЫ (схема)                 перечислить все непустые классы
                                     C_(c,r) = {записи с этими category и region}
4. ДЕКОДИРОВАНИЕ (уровень 2)        S' = argmax_C  agreement(s, C)
5. РАЗВЁРТКА (детерминированная)    S' -> aggregate_det -> derive_det -> ответ
```

`agreement(s, C) = Σ_i [ s_i, если i∈C; (1−s_i), если i∉C ]`. При бинарных
голосах это в точности `K − |S △ C|`, то есть **argmax agreement =
argmin расстояния Хэмминга** — декодирование по ближайшему кодовому слову.

Тай-брейк детерминированный: при равном score побеждает класс с
лексикографически меньшим ключом `(category, region)`.

Консенсус на шаге 2 — **plain мода среди допущенных Кондорсе**, не
лог-оддс: это собственный измеренный выбор E0 (лог-оддс там проиграл
0.806 против 0.861). Переиспользуется, не изобретается заново.

## 3. Пересчёт математики

Плоский режим (E1/E2):
```
P(задача) = Π_i p_i ≈ p^K          F2: 0.840^18 = 0.043
```

Режим декодирования: успех ⟺ `|S △ C*| < |S △ C|` для всех `C ≠ C*`.
При дизъюнктных классах, |C*|=t, |C|=m, |S| = размер шумного набора:
```
E|S △ C*| = FP + FN
E|S △ C |  = m + |S| − 2·|S ∩ C|
```
Ключевая величина — **концентрируются ли ложные срабатывания в одном
соседнем классе**. DELTA-0 измерила precision 0.545 / recall 0.819 на
одиночной модели: |S| ≈ 6.4 против t ≈ 3.5, то есть ~3.5 лишних записи.
Если они собраны в одном соседнем классе — декодирование уедет туда и
провалится. Если рассеяны — консенсус их гасит, |S| стягивается к t,
декодирование срабатывает.

**Именно это и измерено в E3**: `ρ_FILTER_F2=+0.150`,
`ρ_FILTER_Thard=+0.103` — низкая корреляция ошибок, то есть ложные
срабатывания **идиосинкратичны, а не общие**. Низкая ρ — не утешительный
приз E3, а **предпосылка, которая лицензирует E4**.

## 4. Пред-регистрированные пороги (не двигаются)

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| **E4a-set** | F2 exact-set после декодирования (против плоских 0.025 в E1) | ≥ 0.30 | **< 0.15** |
| **E4a-fin** | F2 сквозной финал ДА/НЕТ, `Δ = r − r_m*_F2 (0.525)` | Δ ≥ 0.05 | Δ < 0.05 → `DELTA_NONPOS` |
| **E4b** | T_hard SUM, `Δ = r − r_m*_B (0.000)` | ≥ 0.25 | Δ < 0.05 |
| **E4-gain** | `G = r_set(рой+декод) − r_set(лучшая одиночная+декод)` | G > 0 | **G ≤ 0 → `SWARM_NULL`** |

**E4-gain — единственный чистый тест на рой.** Обе стороны получают
ИДЕНТИЧНОЕ детерминированное декодирование, поэтому любой разрыв между
ними — вклад именно роя, а не проекции. Если `G ≤ 0` — структура помогает,
а рой не нужен, и это должно быть сказано прямо.

«Лучшая одиночная» выбирается **честно**: для каждой отложенной задачи —
модель с наибольшей LOO-сбалансированной точностью по ОСТАЛЬНЫМ 39
задачам, без подглядывания в её собственную метку. Дополнительно отчёт
покажет по-модельные ставки, чтобы оракульный максимум был виден и не
был выдан за честный выбор.

## 5. Обязательная маркировка (правило TOOL_PIPELINE)

Шаги 3 и 5 — **детерминированные**. Перечисление классов читает
`record["category"]`/`record["region"]` из структуры записей, то есть тот
же табличный текст, который видит модель, но разобранный кодом.

Поэтому в отчёте ОБЯЗАТЕЛЬНО:
- флаг **`STRUCTURE_DET=true`** на всех результатах E4;
- рядом, в той же таблице, чистый инструментальный потолок
  `filter_det = 1.000` (FORK-1), чтобы никто не прочитал E4 как победу
  над инструментом — это **гибрид**, а не рой в вакууме;
- фраза «E4 не превосходит детерминированный конвейер и не претендует на это»
  в разделе non-claims.

Это ровно тот же режим, что §5 ESW_THEORY уже описывал как трёхслойную
архитектуру (восприятие = рой, вычисление = инструмент, план = схема) —
E4 впервые пользуется слоем «схема» по назначению, а не игнорирует его.

## 6. Ограничения, заявленные заранее

- Гипотезы = все непустые классы `(category, region)`, **без** фильтра по
  размеру. Генератор гарантирует 2–5 совпадений, но использовать это
  знание — привилегированная информация, поэтому не используется.
- «Золотой ответ — ровно один класс» верно **по построению этого
  генератора**. На задаче, где ответ — объединение классов или
  произвольное подмножество, пространство гипотез так не сворачивается.
  Это ограничение переносимости, а не дефект замера.
- `op`/`threshold`/`comparator` (F2) берутся из постановки задачи — они
  сформулированы в самом запросе, ровно как их использовала цепочка
  DELTA-0. Не золотые промежуточные значения.
- Никаких новых вызовов: если `filter_calls.jsonl` не содержит все
  (задача, модель) строки — HARD_STOP, а не досбор.
