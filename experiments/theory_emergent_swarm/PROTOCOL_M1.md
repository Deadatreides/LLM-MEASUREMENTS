# PROTOCOL — M1: швы, на которых МДП перестаёт быть вырожденной

Написан ДО единого вызова. Пороги не двигаются.

## 0. Что чинится

K1 показал: из семи дисциплин Кана нагрузку несла одна — деление на
блоки. **МДП была вырождена, потому что блоки F2 независимы**: запись 3
в блоке 1 ничего не знает о записи 10 в блоке 2, на швах проверять
нечего.

M1 строится так, чтобы шов существовал физически: **выход одной
дисциплины является входом следующей.**

```
Блок A  отделы      DEP-#### | name | budget | region
Блок B  менеджеры   MGR-#### | name | dept=DEP-#### | years
Блок C  сотрудники  EMP-#### | name | mgr=MGR-#### | salary

хоп 1 (A): отдел с наибольшим бюджетом        -> dep_id
хоп 2 (B): менеджер этого отдела              -> mgr_id
хоп 3 (C): сотрудники этого менеджера         -> сумма зарплат
```

Инварианты по построению (проверены на всех 80 задачах): максимум
бюджета единственен, менеджер отдела единственен, у целевого менеджера
2–4 сотрудника, золотая цепочка воспроизводит ответ, все швы валидны.

## 1. МДП: проверяет ИНТЕРФЕЙС, не переделывает работу соседа

Это принципиальная граница. Кан не заставляет смежника пересчитывать
чужую балку — он проверяет, не сталкиваются ли они в одной точке.

| проверка | что именно | почему это не «переделать работу» |
|---|---|---|
| **МДП шов 1→2** | `dep_id` из хопа 1 обязан встречаться как `dept` хотя бы у одного менеджера в блоке B | референциальная целостность; не ищет максимум заново |
| **МДП шов 2→3** | `mgr_id` из хопа 2 обязан (a) существовать в B, (b) иметь `dept == dep_id` из хопа 1, (c) встречаться как `mgr` в блоке C | (b) — классическая коллизия: две дисциплины разошлись об общем объекте |
| **ВДП хоп 3** | возвращённые `EMP-####` обязаны существовать в блоке C | ловит галлюцинации, не проверяет принадлежность менеджеру |

**Ремонт стоит НОЛЬ вызовов**: кандидаты уже собраны со всех моделей,
МДП лишь переупорядочивает их — берётся следующий по числу голосов
кандидат, проходящий проверку шва. Если провалились все — дисциплина
объявляет отказ (INAPPLICABLE), а не угадывает.

**Явно НЕ делается**: МДП хопа 3 не фильтрует сотрудников по `mgr ==
mgr_id`. Это было бы вычислением ответа, а не проверкой шва, и превратило
бы замер в `det_filter` (который и так даёт 1.000).

## 2. Четыре арма, чтобы вклад каждого элемента был изолирован

| арм | что | измеряет |
|---|---|---|
| **WHOLE** | одна модель, вся база, один вызов | база «лучшая одиночная» |
| **CHAIN_SINGLE** | одна модель ведёт все 3 хопа, свой выход в свой вход, без МДП | вклад декомпозиции |
| **CHAIN_SWARM** | на каждом хопе мода по 6 моделям, без МДП | вклад роя поверх декомпозиции |
| **CHAIN_SWARM_MDP** | то же + МДП на швах | **вклад МДП** |

Вызовы кэшируются по `(задача, хоп, входное значение, модель)`, поэтому
армы переиспользуют совпадающие вызовы.

## 3. Пред-регистрированные пороги

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| **M1-mdp** | `CHAIN_SWARM_MDP − CHAIN_SWARM` | ≥ +0.05 | **≤ 0 → МДП не работает даже на настоящих швах** |
| **M1-swarm** | `CHAIN_SWARM − лучшая CHAIN_SINGLE` | > 0 | ≤ 0 |
| **M1-decomp** | `лучшая CHAIN_SINGLE − лучшая WHOLE` | > 0 | ≤ 0 |
| **M1-emergence** | задач, где CHAIN_SWARM_MDP верна, а **ни одна** CHAIN_SINGLE не верна | ≥ 3 | **0 → эмерджентности нет и на швах** |

**M1-mdp — главный.** Это единственная возможность проверить
междисциплинарный контроль по существу: в K1 он был вырожден. Порог
ремонта в ноль вызовов делает проверку честной — МДП не может выиграть
за счёт дополнительного бюджета.

**M1-emergence** формулируется строго, с учётом ошибки K1: сравнение идёт
с одиночной моделью, прошедшей **тот же конвейер** (CHAIN_SINGLE), а не с
сырым whole-task.

## 4. Бюджет

40 задач TEST. Хоп 1 — 6 вызовов/задача; хопы 2 и 3 — по 6–12 (зависит от
числа различных входов после кэша); WHOLE — 6. Оценка ≈1100 вызовов,
≈22 минуты.

## 5. Non-claims

- Детерминированные компоненты: суммирование зарплат, МДП, ВДП. Чистый
  `det`-конвейер решил бы M1 на 1.000 — как и везде, **потолок
  инструмента не побит и не оспаривается**.
- Три хопа — фиксированная схема задачи, а не план от LLM (LIFE-9: 22%).
- Одна семья, один сплит, n=40.
- «Отказ дисциплины» при провале всех кандидатов считается FAIL задачи,
  без подстановки золотого значения (правило DELTA-0, применяется здесь
  без изменений).
