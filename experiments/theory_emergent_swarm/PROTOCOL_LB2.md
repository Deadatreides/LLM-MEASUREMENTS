# PROTOCOL — LB2: вся схема разом на LongBench v2 (Multi-Doc QA / hard)

Написан ДО единого вызова. Пороги не двигаются.

## 0. Полигон и почему он честнее прежних

LongBench v2, срез **Multi-Document QA + hard + short**: 44 вопроса,
8.3k–32k слов (медиана 20k), 4 варианта ответа, случайная база **0.250**.

Контекст **физически не влезает** в `n_ctx=2048` — даже самый короткий
вопрос это ~12 окон. То есть декомпозиция здесь не приём для улучшения
метрики, а **единственный способ вообще прочитать задачу**. Это ближе к
продуктовым задачам, чем всё, что мерилось раньше.

**Ограничение мощности, заявленное заранее**: при n=44 и 4 вариантах
SE ≈ 0.065. **Различимы только крупные эффекты (≥0.15).** Поэтому
основные метрики ставятся на уровень чанков (n≈870), уровень вопроса —
вторичный. Это прямой перенос урока M1, где разрешение было у per-hop, а
не у сквозной метрики.

## 1. Схема из схем — каждый слой обоснован измерением

```
0  СХЕМА (детерминированно)      контекст -> ~870 чанков по 1000 слов
                                  обоснование: K1, позиционный распад полноты
1  ИСПОЛНИТЕЛИ                    чанки РАСПРЕДЕЛЕНЫ по моделям round-robin
                                  (параллельное покрытие, НЕ избыточность)
2  ВДП (детерминированно)         цитата обязана дословно встречаться в чанке,
                                  иначе отбрасывается -- фильтр галлюцинаций
3  СБОРКА (альбом)                выжившие цитаты -> один короткий контекст
                                  здесь длинный контекст СЖИМАЕТСЯ
4  ОТВЕТ                          все 6 моделей отвечают по сборке
5  ЭЙГЕН-КОНСЕНСУС                надёжности из главного собственного вектора
                                  матрицы согласия -- БЕЗ МЕТОК
6  МДП (детерминированно)         выбранный вариант обязан пересекаться по
                                  содержательным словам со сборкой;
                                  иначе -- следующий кандидат, который пересекается
7  СТРОБ ПО MARGIN                margin<=0 -> INAPPLICABLE, а не догадка
```

**Эйген — новый элемент и он снимает главное практическое ограничение.**
Все прежние правила (Кондорсе в E0, `π ≥ 0.5·π_best` в G1, ранжирование в
M2) требовали РАЗМЕЧЕННЫХ данных для оценки `π_m`. На реальной задаче
меток нет. Но при условно независимых голосующих

```
P(i согласен с j) = p_i·p_j + (1−p_i)(1−p_j)/(K−1)
```

монотонно растёт по обоим `p`, поэтому внедиагональная матрица согласия
приближённо ранга 1, и её главный собственный вектор **упорядочивает
голосующих по надёжности, ни разу не увидев эталона**.
Проверено на синтетике до прогона: три голосующих, один случайный —
эйген поставил случайного последним (0.184 против 0.408).

## 2. Армы при РАВНОМ бюджете чтения

| арм | что | измеряет |
|---|---|---|
| **TRUNC** | без декомпозиции: каждая модель видит только первый чанк | база «как есть при n_ctx» |
| **SOLO** | ОДНА модель (`internvl3-2b`, сильнейшая по M2/GSM8K, зафиксирована заранее) читает ВСЕ чанки | вклад декомпозиции |
| **SWARM** | те же чанки распределены round-robin по 6 моделям | **вклад роя при равном числе чтений** |

`SOLO` и `SWARM` делают **одинаковое число чтений чанков**. Разница
только в том, один читатель или шесть. Это первый замер, где рой
проверяется не как избыточность, а как **параллельное покрытие**.

## 3. Пред-регистрированные пороги

| код | величина | предсказание | фальсификация |
|---|---|---|---|
| **LB2-eigen** | Spearman(эйген-веса, истинные надёжности) | ≥ +0.6 | **≤ 0 → эйген не оценивает надёжность** |
| **LB2-decomp** | `SOLO − TRUNC` | ≥ +0.15 | ≤ 0 |
| **LB2-swarm** | `SWARM − SOLO` при равном бюджете | > 0 | ≤ 0 |
| LB2-vs-single | `SWARM − лучшая одиночная в арме SWARM` | > 0 | ≤ 0 |
| LB2-mdp-safe | сломанных МДП верных ответов | 0 | ≥1 |

**LB2-eigen — главный.** Если собственный вектор ранжирует модели без
меток, снимается ограничение, из-за которого весь корпус до сих пор
требовал калибровочной выборки. Это проверяется прямо: сравнением с
надёжностями, посчитанными по эталону ПОСЛЕ прогона.

## 4. Бюджет

870 чанков × 2 арма покрытия + 3 раунда ответов × 6 моделей × 44 ≈
**2530 вызовов**, ≈80 минут. Трафик уже потрачен (465 MB).

## 5. Non-claims

- Эталонная буква идёт ТОЛЬКО в скоринг: не показывается модели, не
  участвует ни в чанковании, ни в сборке, ни в эйген-весах.
- n=44: различимы только крупные эффекты; величины ниже 0.15 приводятся,
  но значимыми не заявляются.
- Срез `short` выбран по бюджету: medium/long (33k–1.1M слов) требуют на
  порядок больше вызовов. Перенос на них не показан.
- `internvl3-2b` как SOLO-модель зафиксирована ДО прогона по прошлым
  замерам, а не выбрана по результату LB2.
- Детерминированные компоненты: чанкование, ВДП, МДП, эйген. LLM отвечает
  только за извлечение цитат и выбор буквы.
