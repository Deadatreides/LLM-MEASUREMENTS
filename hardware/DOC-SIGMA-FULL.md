## 0. Инвариант

```
W = W                    канонические веса точны и неизменны, всегда
R(t) ≠ const             динамично только присутствие: что материализовано сейчас
```

Из этого следует главное разграничение полномочий, которое нельзя нарушать:

> **Наш рантайм решает, ЧТО доступно.
> Модель решает, КАК это смешать.**

| | что определяем мы | что определяет модель |
|---|---|---|
| dense | какие каналы материализованы | `silu(⟨W_gate[c],x⟩)` — точный вес канала |
| MoE | какие эксперты материализованы | `softmax(x·W_router)` — точный вес эксперта |

Наш роутер **никогда не вычисляет выходной вес**. Он пишет только маски присутствия.
Это проверяемый инвариант, и он должен быть в тестах.

### Цели

| Цель | Значение |
|---|---|
| основная | GPT-OSS-120B (116.8 B) на GTX 1660 Super 6 ГБ |
| вторая | DeepSeek-70B dense на P40 24 ГБ |
| скорость | 60–105 tok/s (GPT-OSS), 10–13 tok/s (70B dense) |
| качество | −1…−3 % ppl одним проходом; выше базы при гиперцикле ценой скорости |

### Соотношение памяти и скорости — через коэффициент носителя

```
скорость:  tok/s ≈ BW / B_token           B_token — байт, прочитанных НА ТОКЕН
память:    VRAM_weights ≈ R               R — резидентный набор = носитель за эпоху
коэффициент носителя:  k_supp = R / B_token
```

**Это две разные величины, связанные `k_supp`.** Уровень 2 (рой) читает лишь часть
резидентного, поэтому выигрыши по памяти и скорости расходятся, и расходятся сильно:

| | `k_supp` | Выигрыш по памяти | Выигрыш по скорости |
|---|---|---|---|
| GPT-OSS (MoE, эпоха 15, перекрытие ~70 %) | **≈ 6** | 60.8 / 4.64 = **13×** | 2.70 / 1.59 = **1.7×** |
| DeepSeek (dense, ядро 26 % стабильно) | **≈ 1.1** | 42.4 / 18.4 = **2.3×** | 18.4 / 16.7 = **1.1×** |

У MoE память выигрывает многократно, скорость — умеренно: разрежённость по compute у модели
уже есть, мы добавляем разрежённость по **хранению**. У dense обе величины почти совпадают,
потому что стабильное ядро нужно на каждом токене.

Отсюда формулировка целей, которая не противоречива:

> «×5 VRAM» и «×2–3 скорости» — **не один и тот же коэффициент** и не конкурируют.
> Против конфигурации, где модель вообще не помещается (текущая реальность для GPT-OSS на
> 6 ГБ), обе величины улучшаются несопоставимо; сравнение имеет смысл только с явно
> названной базой.

И второе: «качество выше базы» и «скорость ×2–3» **взаимоисключающи в одном прогоне**.
Маскирование качество снижает; поднимает его только гиперцикл (≥3 прохода), который
съедает ускорение. Выбирается один режим:

| Режим | Результат |
|---|---|
| Throughput | 14B-класс в 6 ГБ, ×2.4 скорости, качество −1…−3 % |
| Quality | то же в памяти, скорость ≈ базовой, гиперцикл 2–3 прохода, качество выше |

## 1. Объекты и единицы

### 1.1 Атом — наименьшая неделимая единица резидентности

**Не слой. Не нативный эксперт.** Срез по промежуточной размерности.

```
FFN-атом  = 64 канала:  строки gate/up  +  столбец down
attn-атом = одна голова: строки q  +  столбцы o    (kv-проекции общие → в якорь)
```

| | GPT-OSS-120B | DeepSeek-70B |
|---|---|---|
| FFN-атом, параметров | `3×2880×64 = 552 960` | `3×8192×64 = 1 572 864` |
| размер | 293 КБ (MXFP4 0.53 Б/п) | 943 КБ (Q4 0.6 Б/п) |
| атомов на эксперт/слой | 45 | 448 |
| FFN-атомов всего | `36×128×45 = 207 360` | `80×448 = 35 840` |
| attn-атом, параметров | `2×2880×64 = 368 640` | `2×8192×128 = 2 097 152` |
| attn-атомов | `36×64 = 2 304` | `80×64 = 5 120` |
| **всего атомов** | **209 664** | **40 960** |

**Ограничение по формату квантования.** Атом должен извлекаться независимо, значит его
граница обязана совпадать с границей блока кванта:

| Формат | Блок | Требование |
|---|---|---|
| MXFP4 | 32 элемента | размер атома кратен 32 ✓ (у нас 64) |
| Q4_K (GGUF) | супер-блок 256 | **кратен 256** |
| Q8_0 | 32 | ✓ |

И направление среза:

```
gate, up:  [d_ffn, d_model]  — блоки вдоль d_model
           срез по d_ffn = срез по строкам  →  блоки целы ✓

down:      [d_model, d_ffn]  — блоки вдоль d_ffn
           срез по d_ffn = срез по столбцам →  блоки разрезаются ✗
```

**`down`-проекцию хранить транспонированной.** Делается при офлайн-перекладке, бесплатно.

### 1.2 Псевдоэксперт (PE) — кластер атомов через все слои

Не полоса слоёв, не нативный эксперт. **Вертикальный срез всей модели**, собранный по
соактивации.

Почему нативная нарезка не годится даже для настоящего MoE:

```
L_aux = N · Σ_i f_i · P_i        вспомогательный loss балансировки
                                  минимален при равномерном использовании
```

Обучение **целенаправленно выравнивает маржинальное** распределение экспертов:
`P(эксперт i) ≈ 4/128 = 3.1 %` для всех `i`. Значит кэширование «самых горячих экспертов»
даёт hit rate ровно `N_cached/128` — линейно, без выигрыша. Неравномерна только
**условная** структура `P(эксперт | режим)`, которую aux loss не трогает.

> Локальность, которую обучение уничтожило в маржинале, восстанавливается только
> собственной кластеризацией по условной соактивации.

**Размер PE выводится из потребности токена:**

```
GPT-OSS, на слой:  4 эксперта × 45 атомов × 0.30 (контекстная разрежённость) = 54 атома
на токен:          54 × 36 слоёв = 1 944 атома
```

Отсюда: **PE ≈ 2 000 атомов** покрывает примерно один токен целиком по всем слоям.

Размер библиотеки при среднем перекрытии 1.5:

```
P = (207 360 − якорь) × 1.5 / 2 000 ≈ 153   →   P = 160
```

### 1.3 Якорь — не «все слои», а домен-общий костяк

Возникает из энтропии принадлежности при кластеризации:

```
S_u = −Σ_σ p_u(σ) ln p_u(σ)          энтропия маргинала атома u по кластерам

S_u → ln P   атом принадлежит всем одинаково  →  домен-общий  →  ЯКОРЬ
S_u → 0      принадлежит одному               →  специалист   →  свопится

anchor = { u : S_u > θ_S },   θ_S под бюджет якоря
```

Гарантия §13 («dense anchor всегда существует») выполняется **по построению**, а не
декларацией. Якорь всегда резидентен и всегда получает ≥3 % веса в распределении отбора.

### 1.4 Коридор и эпоха

```
коридор  = резидентный набор = якорь ∪ {выбранные PE}
эпоха    = отрезок в 15 токенов, внутри которого коридор заморожен
```

## 2. Пространство состояний

```
x(t) = [ R(t), E(t), K(t), F(t), G(t), B(t), S(t), M(t), C(t) ]
```

| | Что |
|---|---|
| `R` | резидентность: какие атомы в VRAM |
| `E` | состояние эпохи: фаза, счётчик, отложенная очередь |
| `K` | KV-кэш: занятость, теплота ячеек, фрагментация |
| `F` | потоки: `J_i`, `X_i`, `σ_flow` |
| `G` | граф связей PE: `J_ij`, спины `s_i` |
| `B` | поведение: `B(t)`, дрейф `D_B`, инерция `I_s` |
| `S` | спекуляция: `k_draft`, `r_acc` |
| `M` | аттракторы памяти: библиотека PE, центроиды |
| `C` | конфигурация коридора: маски присутствия |

Система управляет **траекторией `x(t)`**, а не ответом.

Ограничение:

```
W_canonical(t) = const          ∀t
```

## 3. Наблюдение: что измеряется, с каким покрытием, какой ценой

Это фундамент. Всё остальное — производные.

### 3.1 Таблица источников

| Величина | Источник | Покрытие | Цена | Задержка |
|---|---|---|---|---|
| `s_i = cos(h_l, c_i)` | скрытое состояние × центроиды PE | **полное, все 160 PE** | 0.004 % | текущий слой |
| `d_t` — спрос по (слой, эксперт) | логиты роутера (MoE) | **полное, 36×128** | **0** | пост-фактум |
| профиль полос эксперта | активации | только исполненные | 0 | пост-фактум |
| `H_attn(l,h)` | материализованный softmax | все головы (внимание резидентно) | 3 опа/слой | пост-фактум |
| KV: hit/miss/occupancy | учёт ячеек | полное | 0 | текущий шаг |
| `r_acc` | верификация спекуляции | когда драфт включён | 0 | текущий шаг |
| `leak` | `Σ_{i∉resident} u_i` | полное | 160 опов | текущий шаг |

### 3.2 Главный датчик — скрытое состояние, а не роутер

Для SwiGLU вклад канала `c`:

```
contribution(c) = silu(⟨W_gate[c], x⟩) · ⟨W_up[c], x⟩ · W_down[:,c]
```

Канал зависит от `x` **только через два скалярных произведения**. Отсюда:

> Множество активных каналов **полностью определяется направлением `x`.** Точно, не
> приближённо.

Значит роутинг сводится к тому, в каком кластере направлений находится текущее `h_l`:

```
s_i = cos(h_l, c_i)          c_i — центроид PE i в пространстве скрытых состояний
```

| | Значение |
|---|---|
| покрытие | **полное** — скорится всё, резидентность не нужна |
| обучение | **нет** — центроид это EMA наблюдённых `h_l` |
| стоимость (d=8192, 4 точки зондирования) | `4 × 160 × 8192 = 5.2 M MAC/токен` |
| доля от форварда (141 GFLOP) | **0.004 %** |
| хранение | `4 × 160 × 8192 × 2 Б = 10.5 МБ` |

**Это работает одинаково для dense и MoE.** Именно оно снимает зависимость от нативного
роутера и открывает плотные модели.

### 3.3 Роутер MoE — уточнение, не основа

Роутер считает логиты для всех 128 экспертов каждый слой каждый токен, независимо от
резидентности. Читаем **все**, а не top-4:

```
d_t = concat_l softmax(router_logits[l])  ∈ R^{36×128} = R^4608
      36 × 128 × 4 Б = 18 КБ на токен
```

**Softmax, а не top-4 маска.** Маска теряет «почти выбранных» — а это лучшие кандидаты на
следующий токен и источник раннего предвестника смены режима.

### 3.4 Двухуровневая наблюдаемость — только для MoE

Роутер даёт спрос на `(слой, эксперт)`. Полосы внутри эксперта видны только из активаций
исполненных экспертов. Разрешается факторизацией:

```
MoE:    demand(l,e,c) = demand(l,e) · profile(c | l,e)
                         ▲ полное      ▲ частичное, накапливается

dense:  demand(l,c)    = |⟨W_gate[c], h_l⟩| ≈ |⟨Z[c], Λ^{−1/2}Uᵀh_l⟩|
                         экспертов нет; факторизация неприменима, работает §10.8
```

**Размерность `d_t`.** Наблюдается вектор уровня эксперта, а не атома:

```
MoE:    d_t ∈ R^{36×128} = R^4608           наблюдается напрямую, 18 КБ/токен
        атомный уровень ВЫВОДИТСЯ через profile — это не наблюдение
dense:  d_t не существует; сравнение идёт по cos(h_l, c_i), 160 значений
```

Размещение в библиотеке (§7.2) поэтому работает **на 4608-мерном векторе** для MoE и на
160 косинусах для dense, а не на 209 664-мерном атомном векторе. Так дешевле и честнее.

Профиль полос — EMA-вектор длины 45 на эксперта:

```
4 608 экспертов × 45 полос × 4 Б = 829 КБ
```

И здесь балансировка нагрузки **работает на нас**: каждый эксперт выбирается ≈3.1 %
токенов, значит за 10 тыс. токенов получает ~310 исполнений — достаточно для устойчивого
профиля. Ни одна часть модели не остаётся ненаблюдаемой дольше ~30 токенов.

### 3.5 Негэнтропия на группу весов — с поправкой на стоки

Наивная `J = 1 − H/H_max` переоценивает головы-сливы (attention sinks: низкая энтропия,
нулевой вклад). Правильная форма:

```
m(l,h)  = 1 − Σ_{j∈sink} p_j                      доля массы вне стоков
H̃(l,h) = H(ренормированного не-sink распределения)
J_attn(l,h) = m · (1 − H̃ / ln(n_kv − n_sink))
```

| Случай | `m` | `H̃` | `J` | Вердикт |
|---|---|---|---|---|
| слив в sink | →0 | — | →0 | холодная ✓ |
| острый фокус на реальном токене | ≈1 | ≈0 | ≈1 | горячая ✓ |
| размазана по реальным | ≈1 | ≈max | ≈0 | холодная ✓ |

Для полос FFN — тот же вид:

```
p_c = |a_c| / Σ_{c∈b}|a_c|
J_ffn(l,b) = (1 − H(p)/ln w_b) · (Σ_{c∈b}|a_c| / Σ_all|a|)
             ▲ специфичность      ▲ доля массы
```

### 3.6 Окно EMA теплоты — критическая константа

Логиты роутера **на токен** остры (top-4 из 128). Усреднённые по всей сессии они
выравниваются обратно в плоский маржинал, навязанный aux loss.

> Слишком длинная EMA теплоты возвращает однородное поле — ровно тот отказ
> (`n_structures = 0`), от которого уходим.

| α | окно `1/(1−α)` | Что происходит |
|---|---|---|
| 0.88 (в коде) | 8.3 токена | шум доминирует, поле дрожит |
| **0.99** | **100 токенов** | ✓ режим виден, маржинал не успевает выровняться |
| 0.999 | 1000 | балансировка смывает структуру в плоскую |

**`MYC_EMA_FIELD` = 0.99.**

## 4. Термодинамическое ядро

### 4.1 Негэнтропия

Энтропия измеряется, негэнтропия управляет.

```
H(p) = −Σ_i p_i ln p_i
J(p) = H_max − H(p)
J̃(p) = 1 − H(p)/ln n                нормированная
```

Компоненты и свёртка (**веса ваши, сохранены**):

```
J_attn      = EMA(J_attn, m·(1 − H̃/ln(n_kv−n_sink)), 0.99)
J_kv        = clip(0.65·(1 − miss) + 0.35·(1 − occupancy), 0, 1)
J_graph     = clip(p_conn, 0, 1)
J_behavior  = clip(1 − D_B, 0, 1)
J_spec      = clip(r_acc, 0, 1),   0.5 при drafted = 0 (нейтраль, не затухание)

J_total = 0.28·J_attn + 0.20·J_kv + 0.18·J_graph + 0.20·J_behavior + 0.14·J_spec
```

#### Недоступная компонента исключается из знаменателя, а не подставляется нулём

Критично. `J_attn` недоступна при flash attention (softmax не материализуется). Подстановка
нуля даёт молчаливую катастрофу:

```
типично:       J_total = 0.28·0.65 + 0.20·0.70 + 0.18·0.65 + 0.20·0.70 + 0.14·0.65 = 0.68
при J_attn=0:  J_total = 0 + 0.140 + 0.117 + 0.140 + 0.091                          = 0.49

a = 2·0.49 − 1 = −0.02   →   η → 0   →   система НАВСЕГДА в режиме шума
```

`J_total = 0.5` — точка бифуркации. Потеря члена с весом 0.28 сажает систему ровно под неё,
и выйти она не может. Ни одна тревога не сработает: все величины «в пределах».

**Обязательная форма:**

```
A = множество доступных компонент
J_total = Σ_{i∈A} w_i·J_i  /  Σ_{i∈A} w_i

без J_attn:  (0.20 J_kv + 0.18 J_gr + 0.20 J_beh + 0.14 J_spec)/0.72 = 0.68  ✓
```

То же правило для `J_spec` при выключенном черновике и для любой другой компоненты.

### 4.2 Открытая система: приток обязан быть внешним

Это правка, без которой всё остальное самозамыкается.

**Внешняя верификация `q_ext`** — множитель, а не слагаемое (как `q_env` в 8.9.2):

```
префилл:            q_ext = clip(1 − H_out/ln V, 0, 1)   на реальном токене промпта
decode + drafting:  q_ext = clip(r_acc, 0.1, 1.0)         согласие с canonical dense
decode без draft:   q_ext = 0.5                           нейтраль, проверки нет
```

**Внешний приток `ν` = утечка спроса за границу структуры:**

```
ν = leak(t) = Σ_{i ∉ resident} u_i(t)
```

Это буквально поток через границу, измеренный на границе. (Ранее рассматривался прокси по
возрасту KV-ячеек — утечка прямее и лучше.)

**Собранный баланс.** `j_delta` перестаёт быть сиротой — он и есть `ΔH` с обратным знаком.

Важно: **`χ` и `Φ` — два разных диагностика, и их нельзя выводить друг из друга.**
В первой редакции документа они были склеены, это была ошибка.

```
j_delta = J_total(t) − J_total(t−1)

── контур негэнтропии (порт Mycelium 8.9.2) ────────────────────────────
π_r  = max(0, j_delta) / c_r · q_ext             c_r = стоимость шага
π̄   ← 0.9·π̄ + 0.1·π_r
d_eS = −ρ_blk · j_delta · q_ext                  ≤ 0, приток организованности
d_iS = L·(π_r − π̄)²  +  σ_spatial  +  diss_KV    ≥ 0
Φ    = |d_eS| − d_iS                             ЖИВОСТЬ коридора: производит ли он
                                                 больше порядка, чем разрушает

── контур неравновесия (матописание §3) ────────────────────────────────
Φ_in   = ν = leak                                СЫРЬЁ: неорганизованный спрос
Φ_diss = d_iS
χ = (Φ_in − Φ_diss) / max(Φ_diss, ε)             хватает ли притока на самоорганизацию
```

| | Что отвечает | Потребитель |
|---|---|---|
| `Φ` | «этот коридор жив?» | dormant / supersede в библиотеке PE |
| `χ` | «есть ли чем питаться, чтобы структура возникла?» | вход в `a`, вес 0.08 |

Система с нулевой утечкой полностью организовала свой вход — это стационарное, закрытое
состояние, и в нём самоорганизация невозможна. Утечка — не поломка, а топливо.

`L` — число активных рёбер графа PE (у предка — рёбра `G_B`).

**Временнóй член `L·(π_r − π̄)²` обязателен.** Он и есть фильтр нестабильности: система,
производящая негэнтропию **ровно**, диссипирует почти ноль; дёргающаяся — много.
Пространственный член `σ_spatial` (дирихлева форма по окрестности `J_ij`) его не заменяет:
первый говорит «поле неровное» (норма для работающей системы), второй — «производство
турбулентно» (признак срыва).

`Φ > 0` = коридор жив. Гейтит углубление и продолжение.

### 4.3 Параметр порядка η и рабочая полоса

Уравнение Ландау, нормальная форма вилки:

```
τ_η · dη/dt = a·η − b·η³ + ξ(t)         b = 1, τ_η = 6, η_init = 0.35
a = (2·J_total − 1) + 0.08·χ
η* = √a  при a ∈ (0,1)
```

| `J_total` | `a` (χ≈0) | `η*` | Режим |
|---|---|---|---|
| 0.50 | 0.00 | 0 | **точка бифуркации** |
| 0.58 | 0.16 | 0.40 | нижняя рабочая |
| 0.65 | 0.30 | 0.55 | **цель** |
| 0.75 | 0.50 | 0.71 | верхняя рабочая |
| 0.85 | 0.70 | 0.84 | предупреждение |
| 1.00 | 1.00 | 1.00 | жёсткость |

**Целевая полоса телеметрии: `J_total ∈ [0.58, 0.75]`.** Тревога ниже 0.55 и выше 0.85.

**Проверка знаков на смене домена** — и здесь коэффициент 0.08 оказывается несущим:

```
рост утечки → набор плохо обслуживает спрос → J_graph↓, J_attn↓ → J_total↓
             → χ↑ (малый вклад, вес 0.08)
a = (2·J_total − 1) + 0.08·χ    →  доминирует падение J_total  →  a↓  →  η↓
```

`η↓` → **больше PE, мельче полосы** → разведка. Правильная реакция на переход.
При весе `χ` = 1.0 знак был бы обратный: система на переходе сжималась бы, цепляясь за
старую структуру.

### 4.4 η управляет шириной против глубины резидентности

```
bands_per_PE  = бюджет / (n_PE × атомов_на_PE)
```

### 4.6 Ляпуновский показатель λ — отсутствующий контур

`V(R)` (функция, энергия) и `λ` (показатель, скорость расхождения) — **разные объекты**.
Порт имеет первое и не имеет второго. Без λ нет удержания края хаоса, есть только пороговая
авария.

```
λ = (1/N) Σ ln( (|ΔJ_total,k| + ε) / (|ΔJ_total,k−1| + ε) ),   окно 20

PID каждые 50 шагов (разделение масштабов 2.5×):
    e = −λ
    I ← 0.97·I + e                          anti-windup
    u = 0.5·e + 0.1·I + 0.05·Δe
```

λ идёт в четыре места — прямой перенос из 8.9.2:

| Потребитель | Формула | Знак |
|---|---|---|
| температура роутера роя | `T = T_min + (T_max−T_min)·tanh(3\|λ\|)`, `[0.25, 1.50]` | хаос → шире поиск |
| температура Изинга | `β = β₀/(1 + 0.5·\|λ\|)` | хаос → больше разведка |
| скорость хеббовского обучения | `η_pl ← η_pl·(1 + 0.5\|λ\|)` | хаос → сильнее координация |
| испарение рёбер | `decay = clip(0.02(1+0.3\|λ\|), 0.01, 0.08)` | хаос → быстрее забывание |
| глубина спекуляции | `k_draft ← k_draft·(1 − 0.5\|λ\|)` | хаос → короче черновик (§12) |

Последняя строка — единственная с **обратным** знаком относительно предка
(`depth_scale = 1 + 0.5λ`), потому что §12 требует гасить спекуляцию при росте дрейфа.

### 4.7 Свободная энергия — не декорация

`F = −β⁻¹ ln Z` на спиновой системе отбора есть мера **вырожденности решения**:

```
Z = Σ_s exp(−β·H(s))
F = −β⁻¹ ln Z

F низкая, Z сконцентрирована  →  один явный набор PE  →  нагрузка однозначна
                                  →  эпоху МОЖНО удлинить
F высокая, много почти-равных →  режим меняется
                                  →  эпоху УКОРОТИТЬ
```

```
L_epoch = 15 · (1 + 0.5·(F_ref − F)/F_ref),   клип [8, 32]
```

`partition_log`, `free_energy`, `entropy` в текущем коде считаются и ни на что не влияют.
Здесь они получают потребителя.

## 5. Отбор: два уровня, один подход

| | **Уровень 1 — отбор** | **Уровень 2 — рой** |
|---|---|---|
| решает | что **лежит в VRAM** | что **считается на токене** |
| частота | граница эпохи (~4 Гц) | каждый слой каждого токена |
| из скольких | 160 PE | резидентные 4–5 |
| во сколько | 4–5 | 1–2 |
| ограничение | **жёсткое**: бюджет VRAM | мягкое: всё доступно |
| взаимодействия | сильные (соактивация, co-residency) | слабые |
| **алгоритм** | **Изинг / BP** | **softmax-семплирование** |
| общие входы | `h_i`, `topology_bias`, `T(λ)` | те же |

Разные алгоритмы не по прихоти: наверху комбинаторная задача с жёстким ограничением и
парными связями — спиновое стекло; внизу нужны **веса смеси**, а не подмножество — softmax.

### 5.1 Уровень 1 — основное состояние спинового стекла

```
s_i ∈ {−1, +1},  i = 1..160          холодный / горячий PE

H(s) = − Σ_{i<j} J_ij·s_i·s_j − Σ_i h_i·s_i − μ·Σ_i s_i
```

| Величина | Источник |
|---|---|
| `h_i` | теплота PE: `w_pred·h_router + w_real·h_activation`, EMA α=0.99 |
| `J_ij` | PMI соактивации, Physarum-обновляемая |
| `μ` | химпотенциал, подбирается так, чтобы `Σ(1+s_i)/2 = n_PE(η)` |
| `β` | `β₀/(1 + 0.5\|λ\|)` |

Решение — **cavity/BP, аппарат Паризи**:

```
h_{i→j} = h_i + μ + Σ_{k ∈ ∂i \ j} m_{k→i}
m_{i→j} = (1/β)·atanh( tanh(β·J_ij)·tanh(β·h_{i→j}) )
```

Стоимость: 160 узлов × степень ~20 × 20 итераций = **64 тыс. операций на эпоху** = 0.26 Mop/s.

**Почему строго лучше top-K:** top-K берёт PE, горячие поодиночке. Основное состояние берёт
**кластер** — набор одновременно горячий и внутренне соактивированный. У MoE соактивация
структурна, поэтому разница не косметическая.

**Что заменяется.** Бандит (`bandit.py`, Thompson/LinUCB) → Изинг:

| | Thompson / LinUCB | Изинг + BP |
|---|---|---|
| взаимодействия между PE | **игнорирует** (руки независимы) | `J_ij` в гамильтониане |
| бюджетное ограничение | комбинаторный бандит, обрабатывается плохо | `μ` — точно |
| разведка | по дисперсии апостериора на руку | **`β` от `λ`** — по состоянию системы |
| стоимость | 160 сэмплов Beta | 64 kop |

Теряется попруковая оценка неопределённости; взамен разведка привязывается к фактическому
режиму, а не к независимым верованиям о каждой руке.

### 5.2 Уровень 2 — рой, готовый код

`blackboard.probabilities` из 8.9.2, буквально:

```
score_i = h_i · (1 + 0.1·topology_bias_i)
score  /= max(score)
p_i     = softmax(score / T(λ))
T(λ)    = 0.25 + 1.25·tanh(3·|λ|)
```

Затем `y(x) = Σ_i p_i(x)·E_i(x)` — §13. `p_i` определяет **маску присутствия**, не выходной
вес (см. §0).

**Анти-коллапс**, перенос `x ← 0.97x + 0.03/3`:

```
p ← 0.97·p + 0.03·p_anchor
V > V_crit  →  p := p_anchor           жёсткий откат
```

Гарантирует, что якорь никогда не умирает и неуверенность роутера не даёт коллапса.

`hypercycle.allocate` остаётся на распределении бюджета между классами PE (якорь /
специалисты / разведка) с минимумом каждому.

### 5.3 Смещение нативного роутера (только MoE)

Для нативного MoE **перебивать веса роутера нельзя** — эксперты обучались под него.
Смещаем выбор к резидентным:

```
cov_e = доля нужных атомов эксперта e, лежащих в VRAM
b_e   = κ · (cov_e − mean_e cov)
selection_probs += b_e            перед argsort_top_k
κ     = κ₀ / (1 + 0.5·|λ|)
```

**Это единственная точка интеграции, и она в коде уже есть** — `llama-graph.cpp`, смещение
после всех архитектурных веток и групповой маскировки, поэтому применяется единообразно и
не может быть искажено маскировкой.

Для dense роутера нет — отбор PE **сам является** роутером, на шаг короче.

#### Смещение — источник вырождения. Две обязательные защиты

Без ограничений смещение образует самоподтверждающийся контур:

```
смещённый роутер → выбирает резидентное → наблюдаем резидентное →
→ библиотека подтверждает себя → смещение усиливается → …
```

Здесь и происходит настоящее схлопывание 120 B: не потому, что веса потеряны, а потому что
модель перестаёт их **просить**. Та же болезнь, что была в замкнутом `Φ_in` и в дистилляции.

**Защита 1 — наблюдение читается ДО смещения.** Порядок операций обязателен:

```
selection_probs_raw ──► ggml_set_output ──► d_t        НАБЛЮДЕНИЕ, чистое
        │
        ├─ += b_e
        ▼
   argsort_top_k                                        ИСПОЛНЕНИЕ, смещённое
```

Библиотека учится тому, чего модель **хочет**, а не тому, что мы заставили её выбрать.
Контур разорван у источника, независимо от силы смещения.

**Защита 2 — бюджет переворотов.** Смещение допускается только там, где роутеру почти
всё равно:

```
gap_45(l) = logit[4-й] − logit[5-й]              уверенность роутера
κ₀ = квантиль(gap_45, q_flip),   q_flip = 0.05   не более 5 % перевёрнутых решений
q_flip ↓ автоматически при падении r_acc
```

Распределение `gap_45` снимается тем же прогоном на 5 000 токенов (§15, замер 4). Если
разрывы велики, смещение бесполезно и опираться надо на FETCH; если малы — работает и
безопасно.

### 5.4 Порог конденсации диссипативных структур — из перколяции

Текущий `θ = 1.25·Ā` даёт **обе** аварии и никогда рабочий режим:

| Поле | Занято выше порога | Средняя степень после перколяции | Итог |
|---|---|---|---|
| однородное | 0 % | — | `n_structures = 0` (текущее состояние кода) |
| `heat ~ N(0.4, 0.22)` | 33 % | 3.3 | гигант охватывает 94 % → 1 структура, `order→1`, жёсткость |

Правильный порог — квантильный, привязанный к перколяционному критерию (`p_conn`/`p_c` из §7
матописания, который сейчас считается впустую):

```
z    = средняя степень окрестности ≈ 10
p_c  = 1/z = 0.10
p*   = α_p · p_c ,  α_p = 2.0   →   p* = 0.20
```

```
order = 0.7·(0.5 + 0.2) = 0.49          ровно в полосе
```

Стоимость: частичная сортировка 32 чисел. Самонормирующийся, не зависит от формы
распределения теплоты.

## 6. Cavity-компенсация

### 6.1 Почему диагональ даёт ровно ноль

```
δw_rest = − F⁻¹_{rest,rest} · F_{rest,S} · δw_S
```

Если `F` диагональна, то `F_{rest,S}` — блок вне диагонали между непересекающимися
множествами индексов — **тождественно нулевая матрица**. Значит

```
δw_rest ≡ 0
```

`mycelium-cavity.cpp` считает `h_diag_ema[i] = EMA(a_i²)` — чистую диагональ. LSBCC
(`Δlogits = clip(1/(h_diag+ε),0,5)·max(0, 1.05−CEP)`, в C++ ещё и тайлится по `i % bias_size`)
— это глобальное смещение в пространстве словаря, эвристическое демпфирование.

> **§11 не реализована нигде — ни в C++, ни в Python.** Имя общее, математика разная.

### 6.2 Правильная форма: кросс-ковариация активаций

Оставляем горячее подмножество `A`, выбрасываем холодное `C`, хотим

```
X_A·(W_A + ΔW_A) ≈ X_A·W_A + X_C·W_C
```

МНК даёт:

```
ΔW_A = (X_Aᵀ X_A)⁻¹ · X_Aᵀ X_C · W_C
```

Нужна **кросс-ковариация активаций между горячими и холодными группами**, а не диагональ.

Полная `Σ` для `d_ffn = 14336` — 205 M элементов, 822 МБ на слой. Невозможно.

**Полосовое приближение** — ковариация на средних по полосам:

```
Σ_bb' ← EMA(Σ_bb', ā_b·ā_b', 0.95)              16×16 = 256 float на слой
ΔW_b  = Σ_{b'∈C} (Σ_AA⁻¹ Σ_AC)_{bb'} · W_b'     ранг |C|, на границе эпохи
```

`O(n_bands²) = 256` операций против 205 M. Грубо, но **ненулево**.

### 6.3 Применение — эпилог GEMM

```
Output = Activation × W_hot  +  (Activation × U_k) × V_kᵀ
```

Одним проходом ядра (single-pass fused kernel), низкоранговый эпилог к операции Tensor Core.
Оверхед ~3 %.

### 6.4 Ключевое следствие: промах не догружается, а компенсируется

Если бы промахи тянулись по PCIe:

```
промах на токен = 36 × 4 эксп × 24.88M × 0.33 × 0.53 Б = 0.63 ГБ
при 12 ГБ/с = 52 мс/токен  →  19 tok/s, шина доминирует
```

Поэтому **на 6 ГБ путь промаха — cavity, а не PCIe**. Внутри эпохи не-резидентное просто не
используется, оставшиеся полосы деформируются. PCIe работает только на **ротации набора
между эпохами**.

### 6.5 Контроль качества

```
CEP = ‖ΔW_hot(t)‖ / (‖ΔW_hot(t−1)‖ + ε)          скорость роста компенсации
```

Guardian: пятая проверка по `CEP`. Рост CEP означает, что компенсация перестаёт справляться
— повод сузить маскирование (поднять `η`) или откатиться на якорь.

## 7. Библиотека PE: жизненный цикл (механика PTG)

Никакого офлайн-обучения. Структура возникает из потока наблюдений, инкрементально, с
затуханием — механизм `ptg_core.py`, пороги ваши.

### 7.1 Единица наблюдения

Не атом весов (они все существуют с начала), а **вектор спроса за токен**.

Размерность — уровня эксперта, не атома (см. §3.4):

```
MoE:   d_t ∈ R^4608 = softmax логитов роутера, точно и бесплатно
dense: 160 косинусов cos(h_l, c_i), нет промежуточного d_t

атомное членство PE ВЫВОДИТСЯ:
       MoE   — через profile(c | l,e), накопленный по исполнениям
       dense — через Z (и потому подвержено дрейфу, §10.8)
```

### 7.2 Размещение — пороги PTG

```
s* = max_i cos(d_t, c_i)

s* > 0.78          →  continues:  c_i ← EMA(c_i, d_t);  activation_i ↑
0.60 < s* ≤ 0.78   →  branches:   новый PE, seed = d_t   (если I_s не запрещает)
s* ≤ 0.60          →  off_root:   в якорь
dormant, s* > 0.83 →  returns_to: воскрешение
```

### 7.3 Затухание и анти-коагуляция

```
каждые 25 токенов:
    activation ← γ·activation                      γ = 0.98

    activation < 0.10           →  выгрузка из библиотеки
```

```
160 PE × ~72 КБ = 11.5 МБ            вся библиотека, персистится на диск
```

### 7.5 Граф связей `J_ij` — Physarum, полное покрытие

**Откуда данные.** Из `d_t`, который имеет полное покрытие. Значит соактивация наблюдаема
для **любой** пары, включая PE, никогда не бывшие резидентными вместе. Самоподтверждения нет.

```
u_i(t) = Σ_{(l,e) ∈ PE_i} d_t[l,e] · w_{i,(l,e)}

J_ij = ln( EMA[u_i·u_j] / (EMA[u_i]·EMA[u_j]) )      PMI
```

Обновление на границе эпохи — **полная форма Physarum**, а не только хеббовский член:

```
J_ij ← clip( γ·J_ij + η_pl·co_act_ij − c·(Σ_out(i) − J_ij),  J_min, J_max )
       γ = 0.98,  c = 0.02,  η_pl = 0.10,  J_min = 0.01,  J_max = 1.0

Levy: с вероятностью 0.005·L_epoch — случайное ребро весом 0.1
```

Без конкуренции и испарения накопление монотонно: сильные пути толстеют, слабые не умирают.
Без Levy топология замерзает.

Размерность: 160 узлов, степень ~20 → **3 200 рёбер**, 12 800 пар EMA. Обновление раз в
эпоху — 51 kop/s.

### 7.6 Смежность для конденсации — из `J_ij`, не из фазовой близости

Это структурная правка. В реакционно-диффузионной системе соседство означает **перенос**,
а не сходство состояния:

> Два атома соседи не потому, что у них одинаковая температура, а потому, что активация
> одного влечёт нужду в другом.

`heat`, `usage`, `kv_pressure` остаются, но как **скаляры `h_i`**, а не как координаты.
Метрика для скаляров не нужна. Онлайн-геометрия исчезает как задача.

Это восстанавливает правило 8.9.2: `G_B ≠ G_M`, «они не пересекаются». Порт слил обе роли
в одно гильбертово поле.

## 8. Эпохи, границы, переходы

### 8.1 Инвариант

```
L_active(t) = L_snapshot          ∀t ∈ epoch
```

Внутри эпохи заморожены: топология, маски коридора, резидентность, политика KV.
Изменения копятся и применяются атомарно на границе.

### 8.2 Длина эпохи сходится с трёх сторон

| Ограничение | Значение |
|---|---|
| разделение масштабов предка (окно 20 : контроль 50 = 2.5), `τ_η = 6` | **15** |
| амортизация пересборки графа (1–3 мс при 15 × 15 мс = 225 мс) | < 2 % ✓ |
| окно перекрытия PCIe | 250 мс, достаточно ✓ |

**`L_epoch` = 15, диапазон [8, 32].** Не [8, 256]: при 256 параметр порядка успевает
срелаксировать 40 раз внутри замороженной структуры — он живёт, а подействовать на него
нечем.

### 8.3 Принудительные коммиты

```
границa хода (новый промпт)          →  коммит немедленно
конец генерации                       →  коммит (ответ может быть короче эпохи!)
leak_fast > leak_base + 2σ            →  ранний коммит, смена регистра
V(R) > V_crit и вето активно          →  коммит + EMERGENCY
```

Ответ на «привет» — токенов десять, короче одной эпохи. Механика обязана это переживать.

### 8.4 Три масштаба переходов и механизм на каждом

| Масштаб | Что происходит | Механизм |
|---|---|---|
| граница хода | полная смена домена | **префилл даёт спрос до первого токена** |
| внутри ответа | смена регистра каждые ~150–300 токенов | **leak-предвестник + теневой буфер** |
| внутри регистра | дрейф top-4 | эпоха 15 токенов |

**Граница хода.** Роутинг устойчив к плохой резидентности: вход роутера слоя 0 — эмбеддинг,
точен при любом наборе; ошибка накапливается с глубиной, но остаточный поток доминирует над
вкладом FFN, поэтому даже на слое 30 корреляция ~0.8–0.9. **Одного деградированного
префилл-прохода достаточно** для оценки спроса.

```
t=0     промпт (8 токенов)
t=0     префилл на устаревшем наборе:
          чтение весов 1.59 ГБ / 252 ГБ/с        =  6 мс
          компьют 8 × 10.2 GFLOP / 3 TFLOPS      = 27 мс      →  33 мс
t=33    Изинг, 64 kop                                          →  <1 мс
t=34    подкачка 3 из 4 PE = 1.4 ГБ
          из RAM  @12 ГБ/с   → 117 мс
          из NVMe @3.5 ГБ/с  → 400 мс
t=150…434   первый токен
```

**TTFT = 150–430 мс.** Один раз за ход. Приемлемо.

**Внутри ответа.** Предвестник уже в данных, потому что `d_t` — softmax, а не маска:

```
leak(t)   = Σ_{i ∉ resident} u_i(t)
leak_fast ← 0.7·leak_fast + 0.3·leak(t)          окно 3.3 токена
leak_fast > leak_base + 2σ  →  ранний коммит
```

Задержка обнаружения 3–5 токенов вместо 15.

**Теневой буфер** — тот самый префетч. Шина простаивает:

```
эпоха 250 мс, плановая ротация 40–120 мс
свободно 130–210 мс × 12 ГБ/с = 1.5–2.5 ГБ на эпоху
запас VRAM = 1.06 ГБ

shadow = 2 PE (0.94 ГБ), непрерывно подтягиваются
кандидат = argmax_{i ∉ resident} u_i(t)
```

Деградация на переходе: без буфера 3–5 токенов обнаружения + 7 подкачки ≈ 10 токенов на
якоре ≈ 167 мс. С буфером — 3–5 токенов.

**Чего НЕ нужно:** упреждающего прогона черновика. Он потребовал бы MTP-голов (у GPT-OSS их
нет) или обученной EAGLE-головы — то есть дистилляции. Резидентность заморожена на эпоху,
значит предсказывать надо **носитель**, а не выбор:

| | горизонт | стабильность |
|---|---|---|
| выбор конкретных экспертов на `t+k` | 2–3 токена | низкая, ~70 % перекрытие |
| **носитель (объединение) за 15 токенов** | 15+ | **высокая** — режим живёт сотни токенов |

Наблюдённого спроса за завершившуюся эпоху достаточно для выбора набора на следующую.

## 9. Транспорт и раскладка

### 9.1 Почему эпохи решают задачу префетча

**Потокенный префетч невозможен.** Чтобы PCIe (12 ГБ/с реальных на 3.0 x16) не доминировал
над VRAM (252 ГБ/с достижимых):

```
допустимый промах на токен = 12 × 6.3 мс = 76 МБ при холодных 2.96 ГБ
                            →  точность префетча ≥ 97.4 %
```

Недостижимо.

**Эпохальная ротация — задача другого класса:**

```
эпоха 15 токенов при 60 tok/s = 250 мс
перекрытый PCIe: 12 ГБ/с × 0.25 с = 3.0 ГБ
резидентный MoE = 2.83 ГБ  →  ротируемо до 106 % за эпоху
```

При гистерезисе меняется 15–25 % → 0.5–0.85 ГБ → 42–70 мс, 20–28 % эпохи, полностью
прячется.

> Эпохальная согласованность вводилась ради качества (устранение jitter). Её главная
> ценность оказалась инженерной: она превращает «предсказать с точностью 97 % на каждый
> токен» в «прокачать 20 % набора за 250 мс».

### 9.2 Раскладка на диске — спектральный порядок, не Гильберт

Задача §9 матописания

```
min Σ_{(u,v)} w_uv · |π(u) − π(v)|
```

— это **Minimum Linear Arrangement, NP-трудная**. Её L2-версия `Σ w_uv (π_u − π_v)²` имеет
точное релаксированное решение: **вектор Фидлера**, второй собственный вектор лапласиана.

(§7 `C_graph = uᵀLu` и §9 `C_Hilbert` — L2- и L1-версии одной задачи. В порте реализованы
обе, и нигде не отмечено, что это один объект.)

```
Ланцош на графе 209 664 узла, степень ~20, 4.2 M рёбер:
50 итераций × (matvec 4.2 M + ортогонализация 4.2 M) = 420 MFLOP  ≈  1 секунда
многоуровневое уточнение (METIS-style): O(E log N), ещё несколько секунд
```

**Секунды офлайн против гильбертова приближения с 25 % полноты.**

### 9.3 Почему кривая Гильберта отброшена

**Фрагментация окрестности растёт как `r^(D−1)`** (Moon et al., 2001: куб стороны `r`
распадается на `Θ(r^{D−1})` интервалов индекса):

| D | соседей `3^D−1` | интервалов при r=2 | **полнота одной кривой** | m=4 кривых |
|---|---|---|---|---|
| 2 | 8 | 2 | 50 % | 94 % |
| 3 | 26 | 4 | 25 % | 68 % |
| **4 (в коде)** | **80** | **8** | **12.5 %** | 41 % |

**Шум измерения ограничивает разрешение.** При EMA α=0.88 и `σ_1 ≈ 0.3`:

```
σ_eff = σ_1·√((1−α)/(1+α)) = 0.253·σ_1 ≈ 0.076
осмысленное разрешение = log₂(1/0.076) = 3.7 бита
```

При `B = 8` четыре с лишним младших бита — чистый шум, и это худшее место: индекс Гильберта
не липшицев, младшие биты управляют переходами через швы.

**Точка перелома против полного перебора** (`N²·D/2` против `N·10BD + N log N + N·K`):

| N | перебор | Гильберт | Кто быстрее | Точность Гильберта |
|---|---|---|---|---|
| 32 (в коде) | 2 048 | 10 400 | **перебор ×5** | 12.5 % |
| 160 | 76 800 | 26 500 | Гильберт ×2.9 | 25 % |
| 209 664 | 6.6·10¹⁰ | 3.5·10⁷ | Гильберт ×1900 | 25 % |

**При 32 коридорах кривая в пять раз дороже перебора и в восемь раз менее точна.**

**Ошибка в форме квантователя.** `q(v,α) = round(clamp(v·α,0,1)·(2^B−1))` применяет вес оси
как масштаб перед клампом: при `α>1` сатурация, при `α<1` теряется `log₂(1/α)` бит. В кривой
ось утяжеляется **числом бит**, а не масштабом:

```
нормализация:  u_a = (v_a − v_min,a)/(v_max,a − v_min,a)      бегущие min/max
метрика:       B_a = B_base + round(log₂ α_a)
ключ:          интерливинг по расписанию B_a
```

**Итог:** онлайн — метрика не нужна вообще (смежность из `J_ij`, состояние — скаляры);
офлайн — спектральный порядок. `C_hilbert` как член давления заменяется **прямым счётчиком
перемещённых байт** — измерение вместо прокси.

### 9.4 NVMe: перекладка — двоичное различие, не 20 %

GPT-OSS-120B — 60.8 ГБ. RAM 24 ГБ, полезных ~20. **67 % модели на NVMe.**

```
PE = 2 000 атомов × 293 КБ = 586 МБ

нативный порядок:   2 000 случайных чтений по 293 КБ
                    NVMe random ≈ 1.5 ГБ/с   →  391 мс
после перекладки:   одно последовательное
                    NVMe seq ≈ 3.5 ГБ/с      →  167 мс

эпоха при 60 tok/s = 250 мс
167 < 250  ✓  подкачка прячется
391 > 250  ✗  шина становится узким местом, скорость падает вдвое
```

Перекладка также чинит выравнивание квантования (`down` транспонируется).

## 10. Холодный старт и зонд `Σ_x`

### 10.1 Почему изотропно-случайный вход бесполезен

Для `x ~ N(0, σ²I)`:

```
E[a_c²]      = σ²·‖W_gate[c]‖²
E[a_c·a_c']  = σ²·⟨W_gate[c], W_gate[c']⟩
```

Оба выражения читаются прямо из весов. **Изотропный шум восстанавливает только `Σ_x = I`.**
Вся полезная информация — в анизотропии реального остаточного потока, то есть ровно в том,
чем случайный вход не является.

### 10.2 Что надо измерить: только `Σ_x`, ранг ~256

Линеаризуя `silu` в режиме больших активаций:

```
Cov(a_c, a_c') ≈ W_gate[c]ᵀ · Σ_x · W_gate[c'],      Σ_x = E[x xᵀ]
```

Вся структура соактивации определяется весами (точны) и `Σ_x`. Больше ничего.

```
Σ_x ≈ U Λ Uᵀ,      U ∈ R^{d×256}
C = W_gate Σ_x W_gateᵀ = Z Zᵀ ,   Z = W_gate·U·Λ^{1/2} ∈ R^{d_ffn×256}
```

**`Z` — эмбеддинг канала.** Соактивация = скалярное произведение строк. Кластеризация в PE
= k-means на `Z`. И это **для всех каналов, включая никогда не активировавшиеся** — полное
покрытие структуры аналитически.

### 10.3 Стоимость

**Шаг 1: `Σ_x` — чистый префилл, без генерации, послойный стриминг.**

| N токенов | Компьют (70B) | @3 TFLOPS | Качество `Σ_x` |
|---|---|---|---|
| 1 000 | 1.4e14 FLOP | 47 с | ведущие ~20 направлений |
| **5 000** | 7.1e14 | **4 мин** | **устойчивый top-256** |
| 20 000 | 2.8e15 | 16 мин | с запасом |

Требование по выборке `n ≳ r_eff·log r_eff/ε²`. При степенном спектре `λ_i ~ i^{-1}`
эффективный ранг `tr(Σ)/‖Σ‖ = 6.1` — ведущие направления сходятся за сотни токенов, весь
top-256 за тысячи.

`Σ_x` — свойство языка и модели, **не темы**. Переносится между доменами, при смене темы не
пересчитывается.

**Шаг 2: проекция `Z` — аналитическая, упирается в диск.**

```
DeepSeek-70B:  W·U = 28672×8192×256 = 6.0e10 MAC / слой / матрица
               × 2 матрицы × 80 слоёв = 1.92e13 FLOP = 19.2 TFLOP  →  6.4 с
               чтение FFN 33.8 ГБ @ 3.5 ГБ/с                        →  9.7 с
               перекрытие                                            →  ~12 с

GPT-OSS-120B:  39 TFLOP → 13 с;   чтение 60.8 ГБ → 17 с             →  ~30 с
```

`Z` не материализуется целиком: слой посчитали → кластеризовали → выбросили. Остаётся только
назначение канал→PE: **2.3 МБ**.

### 10.4 Это не дистилляция — тест

> **Тест: выкинуть артефакт — система сломается или замедлится?**

Выкинули `Z` и назначения → библиотека PE строится онлайн механикой PTG → **медленнее, но
корректно.** Проходит.

`Z` — линейная проекция точных весов на собственное подпространство измеренной ковариации.
Ни одного подогнанного параметра. `Σ_x` — статистика, а не модель. Рентген, а не ученик.

**Правило, которое надо зафиксировать:** ни один параметр отбора не должен иметь состояния,
которое нельзя выкинуть без потери корректности.

### 10.5 Разрежённость ≠ экономия

> Разрежённость даёт экономию **compute**. Экономию **памяти** даёт разрежённость +
> **предсказуемость структуры**. `Z` даёт вторую половину.

DeepSeek-70B, FFN 56.4 G, Q4 = 33.8 ГБ. Структура плотной FFN двухчастная (PowerInfer,
Llama-семейство):

```
стабильное ядро:   ~26 % каналов, активны почти всегда   →  якорь
переменный хвост:  ~4 % на токен, меняется
```

| Сценарий | Резидентно | ГБ (Q4) |
|---|---|---|
| без структуры: объединение по эпохе 15 | 26 % + 15×4%×0.7 = **68 %** | 23.0 |
| **с `Z`: якорь + 4–5 PE из ~30** | 26 % + 7 % = **33 %** | **11.2** |

**2.05× по резидентности** — вот что покупает знание геометрии.

### 10.6 Спектр `Σ_x` — go/no-go за 4 минуты

После шага 1 есть спектр `λ_i`, и он отвечает на главный вопрос до всякой разработки:

```
λ_i ~ i^{-α}

α > 1.2   структура сильная, кластеризация сработает, схема жизнеспособна
α ≈ 1.0   пограничный, PE будут размытыми
α < 0.7   структуры нет, каналы не группируются — схема не даёт памяти
```

Второе число — **эффективный ранг** `tr(Σ)/‖Σ‖`. Он задаёт разумное число псевдоэкспертов:
`P ≈ 10…30 × r_eff`.

Работает для обеих архитектур, снимается за четыре минуты. **Делать первым, до кода.**

### 10.7 Два пути промаха. Решение принимается ПО АТОМУ, не по режиму

Compensate работает, перераспределяя **среднеполевой** вклад выброшенных весов на
оставшиеся через `Σ_AC`. Для атома, никогда не исполнявшегося, `Σ_AC` неизвестна; и даже
оценённая аналитически через `Z`, она поглощает лишь среднюю часть вклада, а не зависящую
от входа. Эксперт, несущий редкое знание, не восстанавливается перераспределением на
соседей ни при какой `Σ`.

> **Компенсировать можно только охарактеризованное. Неизвестное — загружать.**

```
атом u востребован:
    u ∈ resident                →  считать
    u ∈ known  ∧  u ∉ resident  →  COMPENSATE   (профиль есть, Σ_AC оценима)
    u ∉ known                   →  FETCH ОБЯЗАТЕЛЕН, компенсация НЕ ОПРЕДЕЛЕНА

known(u):
    MoE    n_samples(профиль эксперта u) ≥ 30
    dense  residual(h_l) = ‖h_l − U Uᵀ h_l‖ / ‖h_l‖ < 0.25
```

Глобального переключения режима нет — это была ошибка первой редакции. `coverage`
остаётся как **телеметрия и порог тревоги**, но не как управляющий переключатель.

**FETCH — потоковый путь, не накопительный.** Загруженное считается и выбрасывается, в
резидентный набор не попадает:

```
зона приземления = двойная буферизация на 2 слоя
                 = 2 × 4 эксперта × 13.19 МБ = 106 МБ      внутри буфера 0.30 ГБ
```

**Резидентный набор остаётся 4.64 ГБ при любой доле промахов.** Память не всплеснёт.

Деградация по скорости, качество постоянно:

| Доля неизвестного | Байт по PCIe | мс/токен | tok/s | Качество |
|---|---|---|---|---|
| 0 % | 0 | 6.3 | 105 | точное |
| 10 % | 190 МБ | 22 | 45 | точное |
| 25 % | 475 МБ | 46 | 22 | точное |
| 50 % | 950 МБ | 85 | 12 | точное |
| **100 % (новый домен)** | **1.90 ГБ** | **164** | **6.1** | **точное** |
| 100 %, эксперт на NVMe | 1.90 ГБ | 543 | 1.8 | точное |

Это и есть заявленный принцип: **при плохом предсказании система деградирует по
пропускной способности, а не по качеству.**

**Эпохальная согласованность не нарушается.** FETCH меняет транзитный буфер, а не
закоммиченную топологию. Возникает временнóй джиттер, но он не меняет, *какие* веса
участвуют — выход побитово тот же, отличается только задержка. Эпоха защищает вычисление,
а не тайминг.

### 10.7.1 Эффективный размер модели — что на самом деле происходит

| | GPT-OSS-120B | DeepSeek-70B dense |
|---|---|---|
| номинально | 116.8 B | 70.5 B |
| **активных на токен — свойство модели** | **5.1 B** | **70.5 B** |
| доступно за сессию при корректном FETCH | **116.8 B, всё** | **70.5 B, всё** |
| материализовано одновременно | ≈ 6.3 B-экв. (4.64 ГБ) | ≈ 30 B-экв. (18.4 ГБ) |
| эффективная модель при FETCH | **5.1 B — как у оригинала** | зависит от cavity |
| при COMPENSATE на неизвестном | деградирует → **запрещено** | деградирует → **запрещено** |

GPT-OSS **и есть** модель с 5.1 B активных: это её архитектура, а не наше усечение. Мы
меняем только то, где живут остальные 111.7 B — на диске вместо VRAM. Вырождения в
«дистиллят» не происходит, потому что неохарактеризованное никогда не приближается.

Для dense картина иная и её надо назвать явно: там активны все 70 B, и маскирование 70 %
FFN — **реальное усечение**, держащееся только на cavity. Поэтому для dense порог `known`
строже, а `residual(h_l)` — вето-сигнал Guardian, а не просто телеметрия.

Скорости холодного старта:

```
всё неизвестно:  1.9 ГБ/токен / 12 ГБ/с = 158 мс  →  6.3 tok/s
разогрев:        ≈ 20 000 токенов при средних 15 tok/s  →  ~22 минуты
```

### 10.8 Дрейф подпространства и его отслеживание

**Дрейф реален и для dense он непрерывен, а не одноразовый.** Это правка к §10.2.

Различие по архитектурам:

| | Где используется `Z` | Дрейф |
|---|---|---|
| MoE | только посев библиотеки; членство форков выводится из `d_t` (точен) × профиля полос | **одноразовый**, безвреден |
| **dense** | **в горячем контуре: членство КАЖДОГО форка** | **непрерывный, накапливается** |

Для dense при `s* < 0.60` рождается новый PE, и его атомы — каналы с большим
`|⟨W_gate[c], h_l⟩|`. Точно посчитать нельзя (нужен весь `W_gate`), считается через `Z`:

```
⟨W_gate[c], h_l⟩ ≈ ⟨Z[c], Λ^{−1/2}·Uᵀ·h_l⟩       точно только при h_l ∈ span(U)
ошибка = ‖h_l − U Uᵀ h_l‖
```

Доля дисперсии, захваченная рангом 256, при `λ_i ~ i^{−α}`:

| α | Захвачено | Комментарий |
|---|---|---|
| 1.5 | 95 % | дрейф пренебрежим |
| 1.2 | 82 % | приемлемо |
| **1.0** | **62 %** | **треть состояния невидима, трекер обязателен** |

**Решение — двухтемповое.** Накапливать надо не активации, а **подпространство**:

```
БЫСТРО (онлайн, правило Ойя, ранг 256):
    U_l ← ортонормировать( U_l + γ·h_l·(h_lᵀ U_l) ),   γ = 0.001

    стоимость:  80 слоёв × 8192 × 256 = 168 M MAC/токен = 0.12 % форварда
                при обновлении каждый 10-й токен       →  0.012 %
    хранение:   80 × 8192 × 256 × 2 Б = 335 МБ в RAM   (GPT-OSS: 53 МБ)

МЕДЛЕННО (MGE, вне горячего контура):
    drift(U) = ‖U_now U_nowᵀ − U_ref U_refᵀ‖_F / √(2·256)     ∈ [0,1]
    drift > 0.15  →  пересчёт Z и перекластеризация, 12–30 с
```

Пересчёт `Z` — это ровно исходная калибровка; она уже принадлежит медленному контуру MGE,
новых механизмов заводить не нужно.

**Хранить буфер сырых активаций бессмысленно** — для обновления `Z` нужно подпространство,
а не выборка. Ойя даёт его за 0.012 % при 335 МБ RAM.

### 10.9 Весовка при кластеризации: `Λ^{1/2}` восстанавливает, но не различает

Правка к §10.2. `C = Z Zᵀ` при `Z = W·U·Λ^{1/2}` точно воспроизводит **величину**
соактивации. Но для **кластеризации** это плохо: `Λ^{1/2}` усиливает доминирующие
направления, общие для всех каналов, и кластеры получаются по отклику на то, что одинаково
у всех.

Разделяем:

```
Z_glob = W · U_{1:k}      · Λ^{1/2}_{1:k}        k ≈ 5–20, домен-общая часть
Z_cond = W · U_{k+1:256}  · Λ^{1/2}_{k+1:256}    условная часть

ЯКОРЬ:  ‖Z_glob[c]‖ / ‖Z_cond[c]‖ > θ_anchor     всегда-активные каналы
PE:     k-means на Z_cond[c] / ‖Z_cond[c]‖        направление условного отклика
```

Это заодно связывает два критерия якоря, живших в документе порознь: энтропию маргинала
Поттса (§1.3) и «стабильное ядро 26 %» из данных PowerInfer (§10.5) — теперь это одно и то
же множество, полученное одним вычислением.

Библиотека персистится на диск и переиспользуется между сессиями. Возврат к теме бьёт в
`RETURN_THRESH = 0.83` и **воскрешает дремлющий PE мгновенно**.

Сценарий «четыре разных домена подряд» — worst case, описывает **первую** сессию.
К двадцатой библиотека покрывает реальное распределение тем пользователя.

последовательных шагов падения** и практически никогда не сработает.

При α = 0.90 та же Δ даёт 0.03 — порог достижим за 3 шага. Это рабочий диапазон.

Поле теплоты и термодинамические компоненты **измеряют разное на разных масштабах** и
обязаны иметь разные константы.

Три замера, все на 1660 Super, все в один прогон, суммарно ~10 минут.

| офлайн-калибровка 1M токенов, сигнатуры 418 МБ | замороженный подогнанный артефакт = дистилляция |
| низкоранговый зонд `W_gate ≈ UV`, r=16 | сжатый суррогат весов = дистилляция |
| Semantic Controller как обученная микромодель | то же; заменён `cos(h_l, c_i)` |
| норма строки + точный пересчёт для dense | заменены `cos(h_l, c_i)` — полное покрытие, 0.004 % |
| упреждающий прогон черновика для префетча | требует MTP-голов или EAGLE = дистилляция; не нужен (носитель ≠ выбор) |
| `h_diag` как cavity | диагональ даёт `δw_rest ≡ 0` |
| изотропный случайный вход как зонд | восстанавливает только `‖W_gate[c]‖`, читается из весов |
| `bandit.py` (Thompson) для отбора | игнорирует `J_ij`, плохо с бюджетным ограничением |

### Замечание, не оформленное как дефект

`q_ext = 0.5` при выключенном черновике означает, что приток `d_eS` постоянно уполовинен.
Само по себе безвредно, но из этого следует, что **у спекуляции есть термодинамическая роль
помимо скорости**: она единственный непрерывный источник внешней верификации во время
генерации. Держать её включённой стоит даже при низком `r_acc` — не ради ускорения, а ради
того, чтобы `q_ext` не выродился в константу.
