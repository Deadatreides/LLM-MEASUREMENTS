## 0.2 Ворота качества — откалиброваны

gpt-oss-20b MXFP4, `llama-perplexity`. Окна корпуса модели: A — ответы 21–30, B — ответы 31–40;
3 фрагмента по 1024 токена. Раскладка общая (`-fit off -ngl 99 -ncmoe 19`), база с
`MYC_NO_STEER=1`. Перплексия базы: A 3.5042, B 3.3742.

| проверка | KLD (среднее по окнам) | KLD 99.9 % (худшее окно) | совпадение топ-1 | перплексия A / B к базе |
|---|---|---|---|---|
| повтор базы | 0.00000 | 0.0001 | 100.00 % | 1.0000 / 1.0000 |
| руление организма включено | **0.00111** | 0.054 | 98.40 % | 0.9988 / 0.9996 |
| KV `q8_0` | 0.00216 | 0.099 | 97.65 % | 1.0010 / 1.0001 |
| KV `q4_0` | **0.08668** | 2.651 | 86.20 % | **1.1248 / 1.0887** |

* **Прогон детерминирован:** повтор даёт KLD 0 и 100 % совпадения, шум ворот — ниже 0.0002 KLD.
* **«Mean PPL(base)» в режиме KLD врёт на окне B на 0.76 %:** считается по логитам, сохранённым в
  uint16. Отношение перплексий теперь берётся к настоящей базе из отдельного прогона (исправлено в
  сценарии).
* **KV `q4_0` на gpt-oss стоит +10.7 % перплексии, а не +1.5 %.** Прежнее число снято на OLMoE и на
  gpt-oss не переносится.
* **Пороги ворот:**
  - «без потерь» — KLD ≤ 0.003 и топ-1 ≥ 97.5 % (уровень KV `q8_0`);
  - «дёшево» — KLD ≤ 0.01 и топ-1 ≥ 95 %; по линейной оценке между опорами это около 1 % перплексии;
  - порог «дёшево» подтвердить первой проверкой этапа 1 — смещением силы 0.5, чья цена на корпусе
    известна (~1 %).

## 0.4 Руление организма — решение: выключить по умолчанию

С рулением KLD 0.0011, перплексия на A −0.12 %, на B −0.04 % — в пределах погрешности (±0.15).
Пользы для качества не видно. Цена в скорости по парному замеру 16 сентября (ниже, R1) — 1.3 %
ответа (8.51 против 8.62 т/с), а не ~10 %, как было записано 13 сентября по непарной точке.
Решение то же: `myc_steer_enabled()` включается только при `MYC_STEER=1`, правка входит в сборку А.
Выигрыш от неё мал — это уборка, а не рычаг.

## 0.3 Офлайн-расчёты по трассам роутера

gpt-oss-20b (`gx-prb.bin`, 4096 токенов): набор учится на первой половине, замер — на второй.

**Смещение к набору на карте (Б2)** — самый сильный кандидат этапа 1:

| бюджет | сила | выборов на карте | умножений на CPU на токен | изменено решений | потеря массы |
|---|---|---|---|---|---|
| 25 % (как на 16 тыс.) | 0 | 58.9 % | 37.8 | — | — |
| | 0.25 | 69.9 % | 27.7 (−27 %) | 38.8 % | 1.08 % |
| | 0.5 | 77.7 % | 20.6 (−46 %) | 58.9 % | 3.03 % |
| 12.5 % (как на 65 тыс.) | 0 | 40.1 % | 55.1 | — | — |
| | 0.25 | 50.9 % | 45.2 (−18 %) | 37.8 % | 1.15 % |
| | 0.5 | 59.3 % | 37.5 (−32 %) | 59.0 % | 3.51 % |

По модели времени ответа (38.4 мс + 1.05 мс на умножение) это ~1.66× к `--fit` на 16 тыс. при силе
0.25 против 1.43× у одного Б2. Замеренный Б2 давал меньше расчёта (1.24×), так что ждать нужно
пропорционально меньшего. На granite то же в смягчённом виде: −15 % умножений при потере 0.66 %.

**Урезание экспертов (SER, бюджет по слоям)** — у gpt-oss дорого. Веса четырёх выбранных почти
ровные: k 4 → 3.5 отбрасывает 7–8 % веса, k → 3 — 17 %. Кандидат опускается ниже; проверить только
воротами на одной-двух точках.

**Смещение на заполнении ниже обрыва** — слабый рычаг. Убатч в 1024 токена задевает 92.6 % экспертов
слоя. При кэше в половину экспертов дочитывается 43 % на убатч; сила 1.0 снижает это до 30.5 % ценой
8.25 % массы. Заполнение ниже обрыва лечится крупным убатчем и стримингом (этапы 1.5 и 2), а не
смещением.
