## A.2 Кластеры вместо полос — главная метрика части A

Смежные каналы не связаны, поэтому агрегация их усредняет. Члены соактивационного кластера
срабатывают вместе, поэтому агрегация разрежённость сохраняет. Это проверяемое различие.

**Построение кластеров** (без трассы активаций, аналитически из весов):

```
1. Σ_x на слой: префилл ~5000 токенов корпуса, накопление h·hᵀ, ранг 256
2. Σ_x ≈ U Λ Uᵀ
3. Z_l = W_gate_l · U_l · Λ_l^{1/2}          ∈ R^{d_ffn × 256}   эмбеддинг канала
4. k-means на Z (после PCA 256→64) в n_clusters = d_ffn / k
```

Дополнительно проверить разделение доминирующих направлений, оно может оказаться
существенным:

```
Z_glob = W · U_{1:5}      · Λ^{1/2}      домен-общая часть
Z_cond = W · U_{6:256}    · Λ^{1/2}      условная часть
кластеризовать на Z_cond / ‖Z_cond‖, а не на полном Z
```

Причина: `Λ^{1/2}` усиливает направления, общие для всех каналов; кластеры тогда получаются
по отклику на то, что одинаково у всех.

**Метрика структурности:**

```
для k ∈ {4, 8, 16, 32, 48, 64}:
    a_contig(k)  доля активных единиц при нарезке подряд
    a_clust(k)   то же при нарезке по кластерам
    p            доля активных каналов (k = 1)

    S(k) = (a_contig(k) − a_clust(k)) / (a_contig(k) − p)      ∈ [0, 1]
```

| `S` | Читается как |
|---|---|
| → 1 | кластеризация полностью сохраняет разрежённость, **структура сильная** |
| ≈ 0.5 | структура есть, но частичная |
| → 0 | кластеры не лучше смежных полос, **структуры нет** |

**Это единственное число отвечает на вопрос «есть ли соактивационная структура в весах»
напрямую, минуя симулятор кэша.** Вынести в первую строку отчёта части A.

Контроль: кластеризовать также **случайное разбиение** того же размера. `a_random(k)`
должно совпасть с `a_contig(k)` — если нет, ошибка в реализации.

# ЧАСТЬ C. Дробление контекста против потери внимания в середине

**Это новый замер и по важности он выше частей A и B.** Первое задание проверяло память;
это проверяет качество, ради которого термодинамика и вводилась.

## C.1 Утверждение

Модели плохо извлекают информацию из середины длинного контекста — U-образная кривая
точности по позиции (эффект «lost in the middle»). Утверждение:

> Если контекст раздробить на блоки, построить семантический граф, посчитать `H(π)` через
> PPR и отбирать блоки по негэнтропии, то **позиция как таковая уничтожается**: блок «из
> середины» перестаёт быть в середине чего-либо. U-кривая должна выпрямиться.

## C.2 Схема

Задача «иголка в стоге сена» с известной истиной.

```
стог:     ~6000 токенов отвлекающего текста
иголка:   факт, который спрашивают ("код доступа к серверу N — XYZ")
позиции:  {5, 20, 35, 50, 65, 80, 95} % длины стога
иголок:   50 различных
итого:    350 испытаний на условие
```

**Три условия. Третье обязательно.**

| | Условие | Что проверяет |
|---|---|---|
| A | полный линейный контекст | базовая U-кривая |
| B | дробление + отбор по негэнтропии, бюджет 2000 токенов | заявленный эффект |
| **C** | **дробление + СЛУЧАЙНЫЙ отбор, тот же бюджет 2000** | **контроль** |

Без C положительный результат ничего не доказывает: простое сжатие контекста само по себе
двигает U-кривую. Только разрыв **B − C** относится к негэнтропийному отбору.

Опционально D: дробление + отбор по косинусной близости к вопросу (обычный RAG-ретривер).
Отделяет «негэнтропия» от «любой разумный отбор».

## C.3 Механика условия B

Переиспользовать `ptg_core.py` из проекта `PTG+MCP1.3` — там уже есть `BlockGraph`, PPR и
`shannon_entropy`, интерфейс `run_ppr(P, v, alpha=0.85)`.

```
1. раздробить стог на блоки по абзацам, минимум 10 символов (MIN_BLOCK_CHARS)
2. на каждый блок: G_B = BlockGraph().build(text, task_type)
3. P = g.transition_matrix()
   v = g.personalization_vector(вопрос, task_type)     ← вопрос как персонализация
4. π = run_ppr(P, v, alpha=0.85);  H = shannon_entropy(π)
5. негэнтропия блока: J = 1 − H/ln(n)
6. отбирать блоки по убыванию J, пока не выбран бюджет 2000 токенов
7. собрать выбранные блоки в порядке ИСХОДНОГО текста и подать как контекст
```

Важно на шаге 3: `v` строится **от вопроса**, а не равномерно. Именно вектор
персонализации делает `π` неравномерным — при равномерном `v` и регулярном `P`
распределение `π` тоже равномерно, `H = ln n`, `J = 0`, и весь механизм молчит. Это
центральная деталь, проверить её явно на одном примере до полного прогона.

## C.4 Метрики

```
accuracy(позиция)              по каждому условию — семь точек
глубина U:  min(acc) / max(acc)  по позициям
разрыв B − C                    ← ГЛАВНОЕ ЧИСЛО
разрыв B − A на средних позициях (35, 50, 65 %)
токенов контекста фактически    A ≈ 6000, B = C = 2000
```

| Результат | Вывод |
|---|---|
| B − C ≥ 10 п.п. на средних позициях | негэнтропийный отбор работает, механизм подтверждён |
| B ≈ C, оба выше A | помогает дробление и сжатие, негэнтропия ни при чём |
| B ≈ C ≈ A | дробление не помогает вовсе |
| B < C | отбор по негэнтропии активно вредит |

# ЧАСТЬ D. Если C дала положительный результат

Только при `B − C ≥ 10 п.п.`. Иначе не начинать.

Проверить, добавляет ли **термодинамика поверх негэнтропии** — то, что отличает Mycelium
от обычного отбора по энтропии:

```
Φ = |d_eS| − d_iS,    d_eS = −ρ·ΔH·q_env,   d_iS = L_r·(π_r − π̄)²
блок допускается в контекст только при Φ > 0
```

`L_r` = число рёбер `G_B` блока, `q_env` = 0.5 (внешней проверки нет), `ρ` — вес блока.

Условие E: то же, что B, плюс фильтр `Φ > 0`. Сравнить E против B.

Здесь проверяется не «полезен ли блок», а «производит ли он порядок ровно» — временнáя
дисперсия скорости производства негэнтропии. Гипотеза: этот фильтр отсекает блоки,
выглядящие релевантными, но дающими скачкообразный вклад.
