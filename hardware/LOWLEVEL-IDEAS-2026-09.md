# Низкоуровневые идеи вне llama.cpp: веса, пути активации, смена формата — сентябрь 2026

Отдельный файл, журнал не трогается. Снято 15 сентября 2026. Первая пачка —
`GITHUB-FEATURES-2026-09.md`. Скрипт замера MXFP4 — `trace-probe/revision-2026-09/mxfp4_entropy.py`,
выгрузка обсуждений colibri — `reports/colibri_issues.json`.

**Мерка пользы** та же, что у первой пачки:
* **Цель** — gpt-oss-120b MXFP4 ниже обрыва памяти (6 ГиБ видеопамяти, 24 ГиБ ОЗУ, SATA SSD).
  Её бутылочное горло — чтение экспертов.
* **Универсальный случай** — 20b, упёртая в счёт: экспертный счёт — 67 % времени ответа.
* **Правило пользователя:** квантование модели дано. Структурные изменения допустимы, но только с
  измеренной ценой в качестве.

## Сначала — пропуск первой пачки

**JustVugg/colibri** — чистый C, 33.2 тыс.★, 3.5 тыс. форков, создан 1 июля 2026. Стримит экспертов
с диска на моделях от GLM-5.2 до Kimi K3. Мой поиск по ключевым словам его не нашёл: в описании нет
слов «inference» и «LLM».

**Приёмы и замеры:**
* объединение экспертов слоя читается один раз;
* O_DIRECT: +34 % ответа на части железа;
* кэш, который учится на истории маршрутизации между сеансами;
* два SSD с зеркальным чтением: +33 % ответа;
* MTP-черновик работает только в int8 — в int4 приём падает до 0–4 %.

**Отрицательные результаты из его issues совпадают с нашими:**
* подкачка по предсказанию роутера на слой вперёд (PILOT, полнота 71.6–73.6 %) — в форке iliria
  откатили (−6.96 %), в треде MLX −2.9 %;
* раскладка файла помогает только на мелких экспертах (#119);
* резидентный кэш, отнимающий память у страничного кэша, даёт обрыв (#119, M5 Max);
* сжатие без потерь не окупается на CPU+SSD (#594).

## Прямо полезное

### 1. Маршрутизация, условная на кэш — выжившее из ревизии, подтверждено извне

* **Метод** (Skliar et al., arXiv 2412.00099): без обучения, роутер смещается к экспертам, уже
  лежащим в памяти; нерезидентные выбираются, если их вес достаточно высок.
* **Их замер:** промахов меньше более чем вдвое, до 2× сквозной скорости, перплексия +0.1…3 %.
* **Наше:** офлайн 1.53× против 1.34× у горячего набора (ревизия §3.4); цена смещения на корпусе
  модели ~1 %.
* **У нас:** только вариант с горячим набором по частоте. Нужна цель «содержимое кэша» (пакет А).
* **Польза для 120b** — главная из этой пачки: бьёт прямо в чтение и не требует обучения. Отдельно
  проверить на заполнении ниже обрыва: смещение сокращает перечитывание на убатч.

### 2. Разреженность активаций внутри эксперта, без обучения

* **Метод** (arXiv 2605.08575, май 2026): 8 готовых MoE, включая GPT-OSS-20B и OLMoE. Нейрон
  неактивен, если модуль активации после gate ниже порога. Gate считается целиком, up и down
  пропускаются, поэтому потолок — 3× на экспертах.
* **Их замер:** при сохранении 95 % точности у крупных моделей разреженность 87–91 %, у Granite-1B —
  26.5 %. GPT-OSS-20B «менее устойчива», числа только на графике. В vLLM — до 2.5× на слое MoE и
  1.2× сквозной.
* **Расхождение с нашим:** §4.52 на OLMoE мерил долю массы активаций (25 % каналов → 63–69 %), а не
  точность задач. Их критерий «−5 % точности» мягкий. Вердикт ревизии «единица мельче эксперта
  закрыта» верен для точного вывода, но не для этого приближения.
* **На нашем CPU с MXFP4:**
  - строки up пропускаются выборкой строк — это просто;
  - down адресуется столбцами внутри квантованных строк — нужен разреженный vec_dot, выигрыш мал;
  - реальная экономия ≈ s/3 экспертного счёта (при s = 70 % это ~23 %, ~15 % ответа 20b);
  - для 120b — столько же меньше байтов, если читать строки up явно.
* **Цена в качестве** — мерить на корпусе модели двумя окнами.

### 3. Динамический бюджет экспертов по слоям — Alloc-MoE (ACL 2026) и SER

* Без обучения: профиль чувствительности слоёв плюс динамическое программирование распределяют
  активации экспертов по слоям, затем по токенам по весам роутера.
* DeepSeek-V2-Lite при половине бюджета: заполнение 1.15×, ответ 1.34×, качество сохранено.
* Это рюкзак из прошлого разговора, но по бюджету экспертов.
* **Польза для 20b:** каждый активный эксперт стоит ~20 мс на токен на 16 тыс. У gpt-oss top-4 малый,
  цена в качестве неизвестна.

## Полезно условно — крупный выигрыш по памяти, но риск качества или нужен отдельный замер

### 4. Прореживание экспертов — REAP (Cerebras, ICLR 2026), SHAPE, MESA

* **REAP:** срезание 25–50 % экспертов разом; на Qwen3-Coder-480B при 50 % сохраняется 97.6 %
  кодовых задач.
* **SHAPE:** на GPT-OSS-20B конкурентная точность при 20–40 %.
* **Предупреждение — arXiv 2609.04453** (сентябрь 2026) на gpt-oss-20b/120b: маршрутизация
  «сверхрассеянная», перплексия и точность расходятся. Лучшая по перплексии конфигурация хуже всех
  в математике. Выбор по активациям против выбора по частоте — разрыв 18 пунктов на GPQA.
  Нужен предметно-взвешенный выбор (MESA).
* **Для 120b:** −25 % экспертов → ~47 ГБ, в ОЗУ ~40 % экспертов вместо ~30 % — ближе к обрыву.
* **Цена:** калибровочный проход по 120b и проверка на задачах пользователя, не на перплексии.

### 5. Самоспекуляция без отдельной модели — DFlash (ICML 2026), KnapSpec, CLaSp

* **DFlash:** блочный диффузионный черновик, >6× без потерь на GPU, есть и для gpt-oss-120b.
  В ik_llama.cpp — PR 1970.
* **KnapSpec:** выбор слоёв черновика как рюкзак; внимание и MLP разделены. До 1.47×, приём 84–97 %.
* **На нашей машине решает цена проверки:**
  - в режиме, упёртом в счёт, пакет из 8 токенов стоит ~6.5 одиночных (батчинг ×1.23) — выигрыша нет;
  - в режиме, упёртом в диск, один проход стоит примерно одного чтения при любом числе токенов
    (замер MTP) — выигрыш возможен при высоком приёме.
* **Проверять только на 120b.** Черновику нужна видеопамять, которой нет.

### 6. Низкобитная подмена на промахах — HOBBIT, SliceMoE

* **HOBBIT:** промах обслуживается копией эксперта INT4/INT2 — до 9.93× ответа на Jetson, <1 % точности.
* **SliceMoE:** срезы бит, совместимые по усечению — 1.64–1.81× задержки.
* **Для MXFP4** нужна отдельная низкобитная копия или усечение бита мантиссы. Это отступление от
  данного квантования, но только на промахах; качество на gpt-oss неизвестно.

## Не для нас — с причиной

| идея | где | почему нет |
|---|---|---|
| сжатие экспертов без потерь (rANS, Huffman) | colibri #594: int4 GLM-5.2 r = 0.738; Unweight, ZipServ — BF16 | **наш замер на gpt-oss-20b: r = 0.919, снимается только 8.1 %.** Коды e2m1 — 3.85–3.87 бита из 4, масштабы E8M0 — 1.0–2.3 из 8, но это 1/17 байтов. MXFP4, обученный в формате, почти несжимаем; к тому же CPU-декодер ~1 ГБ/с не окупается даже против NVMe (#594) |
| раскладка файла по совместной активации (mbolt, BOLT/PGO для весов) | colibri #119 | 2.23× холодного чтения на экспертах в 400 КБ, но закон размера среза: при 12–19 МиБ смежность не даёт почти ничего. Совпадает с ревизией |
| предсказание экспертов на слой вперёд (PILOT, Pre-gated) | colibri, статьи | полнота 72–77 %, но сквозные A/B отрицательные: −6.96 %, −2.9 %; у нас упреждение вредило |
| E8-решётка int3 или вращение перед int2/int3 | colibri #452, #81 | −25 % байтов при лучшем качестве, чем у их int4 (симуляция); gpt-oss обучен в MXFP4, повторное квантование ниже 4 бит добавит ошибку и нарушает правило |
| общие базисы и дельты экспертов (MoBE, D²-MoE, Sub-MoE) | ICLR 2026 и др. | −24…30 % параметров при −1…2 %, но нужны исходные BF16-веса и новые ядра; у gpt-oss опубликован только MXFP4 |
| перевод внимания в MLA (TransMLA, MHA2MLA) | NeurIPS 2025, Ling-2.5-1T | KV −93 %, но ~6 млрд токенов дообучения; у нас нет железа, у gpt-oss половина слоёв и так со скользящим окном |
| линеаризация внимания (LoLCATs, RADLADS, Mamba-in-Llama) | — | 40–700 млн токенов обучения, готовых версий gpt-oss нет |
| срезание слоёв и ранний выход (ShortGPT, SkipGPT) | — | потеря в рассуждениях; калибровка ненадёжна на сверхрассеянной модели |
| DirectStorage SSD→GPU | kibbyd/llm_upper (Windows 11, NVMe) | ускоряет только загрузку; скорость ответа gpt-oss-20b та же; у нас Windows 10 и SATA |
| таблицы поиска вместо умножения (T-MAC) | microsoft/T-MAC | выигрыш на ≤2 битах и тернарных, не на MXFP4 |
| сверхвеса, массивные активации, транскодеры | Apple 2024, Anthropic 2025 | важны для качества квантования и интерпретации, не для скорости и памяти |
| атлас экспертов, поиск путей (colibri #175, MoE Pathfinder) | — | инструмент анализа для прореживания и закрепления по темам; у нас набор не переносится между текстами |

## Порядок

1. **Маршрутизация, условная на кэш**, в том числе на заполнении ниже обрыва (пакет А).
2. **Разреженность внутри эксперта** на строках up: сначала цена в качестве на корпусе, потом ядро.
3. **Динамический бюджет экспертов по слоям** (Alloc-MoE) как обобщение SER — по цене в качестве.
4. **На 120b:** прореживание экспертов с предметной проверкой, самоспекуляция в режиме, упёртом в
   диск, низкобитная подмена на промахах.
