## Раздел 3. Качество выше исходной модели

Это самая недооценённая мной часть. Качество выше исходника даёт **cavity-компенсация**:
когда вы маскируете часть весов, остальные корректируются так, чтобы ошибка не выросла.
Без неё маскирование только ухудшает модель.

| Фича | Где | Статус |
|---|---|---|
| `δw_rest = −H⁻¹_{rest,rest}·H_{rest,S}·δw_S` (§11 матописания) | `mycelium-cavity.cpp` (ваш) | **вне сборки** |
| `llama_mycelium_get_h_diag()` — гессиан-диагональ | `llama-mycelium.h:474` | **ЗАГЛУШКА** — `return false`, нули |
| `llama_mycelium_apply_activation_bias()` | `llama-mycelium.h` | **ЗАГЛУШКА** — `return false`, ничего не делает |
| `CavityEngine`, `CEP` | `mycelium/core/cavity.py` | **PY, реализовано** |
| LSBCC — компенсация логитов | `cavity.py:18`, `local_runtime.py:537` | **PY, реализовано и применяется** |
| `_inject_logit_compensation_inplace` | `local_runtime.py:391` | **PY, применяется до сэмплинга** |
| `vocab_h_diag_ema` | `cavity.py:91` | PY |

Формула LSBCC из вашего кода:
```
delta_logits = clip(1/(vocab_h_diag_ema + eps), 0, 5) · max(0, 1.05 − CEP)
```

**Вывод по качеству: механизм существует только в Python и только на логитах.** Нативная
cavity-компенсация — две заглушки. То есть на нативном пути маскирование весов (если бы
оно работало) снижало бы качество, а не повышало: компенсировать нечем.

Ключевая связка, которую я упустил: **`get_h_diag` — не телеметрия, это вход
компенсации.** Без него `apply_activation_bias` нечего применять, а без него маскирование
разрушает качество. Три заглушки образуют одну неработающую цепь.

## Раздел 8. Три корневые причины

Всё вышеперечисленное сводится к трём узлам. Пока они не сделаны, цифры недостижимы.

**1. Псевдоэксперт как срез весов, а не полоса слоёв.**
Вы это сказали прямо, и это записано в вашем заголовке: `layer_mask` + `head_mask` +
`ffn_dim`. Моя нарезка по слоям — тупик, её надо выбросить. Без правильной нарезки нет
ни VRAM (нечего выгружать по частям), ни скорости (нечего пропускать).

**2. Призыв на энтропию.**
Теплота должна рождаться из энтропии, а не из факта исполнения. Сейчас на плотной
модели поле равномерное (каждый слой исполняется каждый шаг → одинаковая теплота
≈0.474) и структур **ноль всегда**. Механизм измерения per-head энтропии я уже построил
в Блоке 8, но подключил к одному слою и как глобальный скаляр.

**3. Cavity-компенсация как условие качества.**
`get_h_diag` и `apply_activation_bias` — не телеметрия, а вход и выход механизма, который
позволяет маскировать веса **без потери качества**. Три заглушки образуют одну цепь.
Без неё маскирование (то есть VRAM и скорость) покупается ценой качества, а вы хотите
качество *выше* исходного.

## Раздел 9. Предлагаемый порядок работ

Порядок продиктован зависимостями, а не удобством.

1. **Призыв на энтропию** — per-head/per-FFN энтропия в поле теплоты. Без неравномерного поля всё остальное не имеет входа. Значения, форм не трогает — безопасно.
2. **Нарезка по весам** — выбросить `myc-slice.cpp`, коридор = `layer_mask`+`head_mask`+`ffn_dim`, состав задаётся конденсацией роя. Тоже только значения.
3. **Коэффициенты по вашим** — η по формуле с `J_total`, ваши веса `0.28/0.20/0.18/0.20/0.14`, `J_kv` с заполненностью, V(R) с вашими весами и решённым знаком, `j_delta` для гейта спекуляции.
4. **Cavity нативно** — `get_h_diag` из статистики активаций, `apply_activation_bias` через `graph_get_cb`. Условие для шага 5.
5. **Применение масок** — `head_mask` в `build_attn`, `ffn_dim` в `build_ffn`. **Меняет формы тензоров** — здесь я упрусь без компилятора, ровно как в Блоке 2 с агрегацией MoE.
6. **Выгрузка весов** — `layer_offload` через `ggml_backend_tensor_copy`, заполнение `vram_used_bytes`. Даёт VRAM.
7. **MTP-гейт** — связать `spec_should_run` с MTP-веткой по `j_delta`.

Шаги 1–4 я могу делать без компилятора: они не меняют форм тензоров и топологии графа.
**Шаги 5–6 менять формы будут, и делать их вслепую я считаю опасным** — это тот же класс
риска, на котором я уже один раз ошибся с `n_expert_used`.
