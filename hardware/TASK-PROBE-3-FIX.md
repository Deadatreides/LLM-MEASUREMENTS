# ЭТАП 0-BIS. Переделанный фильтр. CPU, минуты

Тот же корпус иголок можно переиспользовать, но **требование непересечения ключевых слов
снимается**. Иголки должны иметь такое же лексическое отношение к вопросу, какое имеют
реальные запросы к реальным документам.

Опасение, ради которого требование вводилось, снимается иначе: не отрезанием канала, а
честной базой сравнения — условием D.

## 0-BIS.1 Четыре критерия, все на одном и том же наборе

Считать ранг блока с иголкой по каждому:

| # | Критерий | Формула | Что это |
|---|---|---|---|
| **J-low** | `1 − H(π)/ln n` | как было | релевантность через концентрацию π |
| **H-high** | `H(π)` | **правило Mycelium** | неразрешённость / новизна |
| **PPR-mass** | `Σ_{i∈seed} π_i` | масса π на узлах, засеянных вопросом | прямая релевантность |
| **BM25** | стандартный | база сравнения | «просто ретривер» |

`PPR-mass` — то, чего в задании не было вовсе, и, по-моему, именно он является настоящим
ретривером на этом графе: он спрашивает «сколько стационарной массы осело на том, что
связано с вопросом», а не «насколько распределение вообще ровное».

## 0-BIS.2 Персонализация: два варианта `v`

**Вариант 1, лексический** — как есть, с непустым пересечением.

**Вариант 2, эмбеддинговый** — тот, который в `block_graph.py` объявлен и не реализован
(`task_emb = None  # нет task embedding — пропускаем`):

```
emb(узел), emb(вопрос)  — усреднённые скрытые состояния Qwen3-1.7B, слой ~2/3 глубины
v_i ∝ exp( cos(emb(узел_i), emb(вопрос)) / τ_v ),   τ_v = 0.1
```

Модель уже загружена, отдельный эмбеддер не нужен (`sentence-transformers` в окружении и
не стоял). Это даёт канал запроса **без требования лексического совпадения** — то есть
решает исходное опасение правильным способом.

Считать оба варианта. Разница `v_эмбеддинг − v_лексика` показывает, что даёт граф сверх
совпадения слов.

## 0-BIS.3 Размер блока — развёртка, а не константа

Ошибка 3 лечится только замером:

```
блок ∈ {3, 6, 12, 24, 48} предложений
для каждого: n узлов графа, разброс J, разброс H, ранг блока с иголкой
```

Ожидание: при малых блоках динамического диапазона нет; при слишком крупных иголка тонет
среди прочего. Оптимум где-то посередине и его надо увидеть, а не назначить.

## 0-BIS.4 Что записывать

```
для каждого (иголка × позиция × критерий × вариант v × размер блока):
    ранг блока с иголкой,  доля ранга,  попадание в верхнюю треть
сводно:
    R по каждому критерию
    corr(критерий, содержит иголку)
    разброс критерия по блокам
```

## 0-BIS.5 Критерий продолжения

```
max по всем четырём критериям R ≥ 0.60   →  ЭТАП 2 запускать, с ЛУЧШИМ критерием как B
                             0.40–0.60   →  запускать сокращённо (A/B/C/D, один бюджет)
                             ≤ 0.40      →  остановиться и сообщить
```

Важно: если побеждает **BM25**, это тоже результат и его надо назвать прямо — значит
графовая часть не добавляет ничего, и весь контурный слой сводится к обычному ретриверу.

# ЭТАП 2-BIS. Если фильтр пройден

Механика из задания 3 сохраняется целиком (пять позиций, развёртка по бюджету, двойные
иголки, инкрементальная запись, возобновляемость). Меняется только состав условий:

| | Условие |
|---|---|
| A | полный линейный контекст |
| B | дробление + **лучший критерий из 0-BIS** |
| C | дробление + случайный отбор, тот же бюджет |
| **D** | дробление + **BM25**, тот же бюджет |

И два разрыва читаются раздельно:

```
B − C   помогает ли отбор вообще
B − D   даёт ли графовый/энтропийный критерий что-то сверх обычного ретривера   ← ГЛАВНОЕ
A − D   выпрямляет ли дробление U-кривую (утверждение U, независимо от термодинамики)
```

**`A − D` стоит померить в любом случае**, даже если `B − D ≈ 0`: это отдельное
утверждение про потерю внимания, и оно не зависит от того, чем именно отбирать.

Этап 1 (калибровка размера стога) выполняется перед этим, как и было.

# Побочно: `H` как детектор новизны — это `Φ_in`

Данные отчёта 3 показали, что подъём `H` при вставке чужеродного факта происходит в **100 %
случаев**, и блок с иголкой попадает в верхнюю треть по `H` в 72 % случаев **без всякой
информации о запросе**.

Это не ретривер. Это детектор новизны — и в архитектуре у него уже есть место:

```
ν = leak = внешний приток = Φ_in          баланс Пригожина
      ↕
подъём H при появлении чужеродного        то же измерение
```

Оговорка обязательна: стог синтетический и однороден (12 тем, 6 шаблонов), поэтому иголка —
единственная аномалия. На реальном тексте `H` гуляет по многим причинам. Проверить дёшево:
прогнать 0-BIS на **естественном** тексте (любые 50 страниц прозы или документации) и
посмотреть, сохраняется ли `R(H-high) ≈ 0.72` или падает к 0.33.

Это отдельный маленький замер, минуты CPU, и он решает, годится ли `H` как источник `ν`.
